Decision Trees & Random Forests

A single tree grown all the way down can memorize its training data almost perfectly — which is the problem, not the achievement. Random forests fix this by averaging many decorrelated trees instead of trusting one.

CONCEPT — explained here, not built or tested anywhere in this repo ~16 min read Prereqs: Model Selection: AIC & BIC (bias-variance framing)
Prefer pictures to prose? Try the Visual Guide — the same ground covered here, broken into short interactive slides.
TL;DR
  • A decision tree is built by recursive binary splitting: at every node, try every feature and every candidate threshold, pick the split that most reduces impurity (for regression, variance/MSE), and repeat on each child until a stopping rule is hit — the CART algorithm (Breiman, Friedman, Olshen & Stone, 1984).
  • Grown all the way down, a tree can carve out a leaf for every single training point — training error near zero, but it has memorized noise along with signal, and it generalizes badly.
  • A random forest (Breiman, 2001) averages many trees, each trained on an independent bootstrap resample of the data (bagging) and restricted to a random subset of candidate features at each split — the second ingredient decorrelates the trees so their individual errors don't all point the same direction.
  • Averaging \(B\) correlated estimators does not drive variance to zero as \(B\to\infty\); it converges to \(\rho\sigma^2\), where \(\rho\) is the average pairwise correlation between trees. Feature subsampling lowers \(\rho\) directly — this, not just "more trees," is the actual lever.
  • Forests naturally produce a genuinely useful practical output: feature importance (mean decrease in impurity, or the more reliable permutation importance) — and an internal, free validation estimate from the roughly one-third of rows left out of each bootstrap sample (out-of-bag error).
  • None of this says a specific feature set fed into a forest produces real trading edge — a strong general-purpose method and a validated signal are two different claims, kept separate throughout this lesson.
Section 01

Why this matters

Every regression tool covered elsewhere in this curriculum — OLS, ARIMA, a GARCH variance equation — commits to a single functional form chosen in advance: a straight line, a linear recursion, a specific parametric variance equation. A decision tree commits to nothing in advance beyond "split on whichever feature helps most, wherever it helps." That flexibility is exactly what makes trees powerful for irregular, non-linear relationships with interactions between features — and exactly what makes an unconstrained tree dangerous: nothing stops it from treating every last quirk in the training data as a pattern worth splitting on.

Model Selection: AIC & BIC covers the same underlying tension — complexity that always improves in-sample fit but eventually hurts out-of-sample performance — from a completely different angle: an explicit penalty added to a selection criterion, \(k\) or \(k\ln(n)\) charged per parameter. Random forests solve the identical bias-variance problem with a different mechanism entirely — not a penalty term added after the fact, but averaging many high-variance trees so their errors cancel. Two lessons, one problem, two unrelated fixes; worth having both mental tools.

💡
Plain-English intuition

Twenty questions, played by an algorithm that never stops asking

A decision tree is the "twenty questions" game formalized: ask a yes/no question that splits the remaining possibilities as usefully as possible ("is \(x_1\) above 5?"), then ask another question on each of the two resulting groups, and keep going. A shallow tree stops after a few useful, general questions — "is the RSI above 70? is the day a Friday?" — and each leaf still contains a healthy handful of training examples that broadly agree. An unconstrained tree keeps asking questions until every single training example sits alone in its own leaf. At that point the tree hasn't learned a general rule about the data; it has built an elaborate, question-by-question lookup table that reproduces the training set exactly and says nothing reliable about anything it hasn't already seen.

A random forest's fix sounds almost too simple to work: instead of trusting one tree's elaborate story, grow hundreds of different trees — each one shown a slightly different, randomly resampled version of the training data, and each one only allowed to consider a random subset of the available questions at each step — and average their answers. Any one tree's overfit quirks are essentially random noise particular to the data and features it happened to see; averaging over many differently-noisy trees cancels most of that noise out, while the genuine signal — the pattern that shows up no matter which resample or feature subset a tree was given — survives the averaging and comes through in the vote.

Section 02

The math, step by step

Recursive binary splitting. A regression tree is built top-down, greedily, one split at a time. Every node starts holding some subset of the \(N\) training examples \((x_i, y_i)\). For regression, the impurity of a node holding a set of points \(S\) is its variance around its own mean prediction:

\[ I(S) = \frac{1}{|S|}\sum_{i \in S} \big(y_i - \bar{y}_S\big)^2, \qquad \bar{y}_S = \frac{1}{|S|}\sum_{i\in S} y_i \]
I(S)the node's impurity — how spread out the targets in this node still are
ȳ_Sthe node's own prediction if it were left as a leaf right now — the mean of its targets
|S|how many training points currently sit in this node

A candidate split is a pair (feature \(j\), threshold \(s\)): it sends every point with \(x_{ij} \le s\) to a left child \(S_L\) and every point with \(x_{ij} > s\) to a right child \(S_R\). Among every feature and every realized threshold (in practice, the midpoints between consecutive sorted values of that feature), the algorithm picks the one that maximizes the drop in weighted impurity:

\[ \Delta I(j, s) = I(S) - \left[ \frac{|S_L|}{|S|} I(S_L) + \frac{|S_R|}{|S|} I(S_R) \right] \]
ΔI(j, s)the impurity reduction this specific split would buy — the quantity being maximized
I(S_L), I(S_R)the impurity of the two child nodes this split would create
|S_L|/|S|, |S_R|/|S|weights — a child holding more points counts for more
1

Start at the root

Every training example sits in one node — the whole dataset.

2

Search every candidate split

For every feature and every realized threshold, compute \(\Delta I(j,s)\).

3

Take the single best split

Pick the \((j^*, s^*)\) that maximizes \(\Delta I\); this is a purely greedy, locally-optimal choice — the algorithm never looks ahead to whether a worse split now would enable a better one two levels down.

4

Recurse on each child

Repeat steps 2–3 independently on \(S_L\) and \(S_R\), and their children, and so on.

5

Stop, and predict at each leaf

Recursion stops at a node once a stopping rule triggers — a maximum depth, a minimum number of points per leaf, or no split left that reduces impurity by more than a set minimum. Each leaf's prediction is simply \(\bar{y}_S\), the mean of the training points that landed there.

The central motivating problem, stated plainly. If the stopping rule in step 5 never fires — no minimum leaf size, no maximum depth, split until impurity is exactly zero everywhere — the tree keeps splitting until every leaf holds one single training point (or several points sharing an identical target), and training error goes to zero. A tree that deep has not found the underlying relationship between features and target; it has built a lookup table that reproduces the training set exactly, including every bit of measurement noise and every coincidental pattern that will never recur. This is overfitting in its most literal form, and it is the single central problem this entire lesson exists to fix.

🧒 Explain like I'm 5

Imagine "studying" for a test by memorizing the exact answer key for last year's exam, word for word, instead of actually learning the subject. You'd get a perfect score on last year's exam — and probably do terribly on this year's, because you never learned the underlying material, just one specific answer sheet. A tree that's allowed to keep splitting forever does the same thing: it stops learning the general pattern and starts memorizing the exact training examples, noise included.

Section 03

Random forests: bagging plus random feature subsets

A random forest (Breiman, 2001) grows \(B\) trees and combines two separate sources of randomness, each doing a distinct job:

1. Bagging — bootstrap aggregation

Each of the \(B\) trees is trained on its own bootstrap resample: \(N\) rows drawn with replacement from the original \(N\)-row training set. Some rows appear multiple times in a given resample; others don't appear at all. This alone gives every tree a slightly different training set, so their overfit quirks — driven by which specific noisy points they happened to see — differ from tree to tree.

2. Random feature subsets at each split

At every single split (not just once per tree), only a random subset of \(m\) features out of the full \(p\) is considered as a candidate — commonly \(m \approx \sqrt{p}\) for classification or \(m \approx p/3\) for regression, Breiman's original defaults. This stops a single dominant feature from being chosen at the top of every tree, which is what would make the trees look alike (and their errors move together) even after bootstrapping.

🧒 Explain like I'm 5

A random forest is like asking a hundred different doctors for a diagnosis instead of just one. First, each doctor only reviews a randomly reshuffled subset of a patient's test results (bagging) — so no two doctors saw the exact same evidence. Second, at each step of their reasoning, each doctor is only allowed to consider a random handful of possible symptoms, not the entire list (random feature subsets) — so they don't all latch onto the one obvious symptom and reason identically. Then you take a vote across all hundred doctors. Any one doctor's weird individual mistake gets drowned out, while the pattern most of them independently notice survives.

The forest's prediction is the plain average of all \(B\) trees' leaf predictions (majority vote, for classification):

\[ \hat{f}_{\text{forest}}(x) = \frac{1}{B}\sum_{b=1}^{B} T_b(x) \]

Why averaging reduces variance without adding much bias. A single unconstrained tree has low bias (it can fit almost any shape) and high variance (regrow it on a slightly different sample of the same data and you can get a noticeably different tree). Averaging \(B\) independent, identically-distributed estimators, each with variance \(\sigma^2\), gives an average with variance \(\sigma^2/B\) — variance falls straight toward zero as \(B\) grows, while the average's bias is unchanged from a single tree's bias, since averaging unbiased (or equally-biased) predictors doesn't shift the expectation. That is the entire bias-variance case for bagging in one sentence: many high-variance, low-bias estimators, averaged, keep the low bias and lose most of the variance.

Bootstrap-trained trees are not actually independent — they share the same underlying dataset. The honest formula for the variance of an average of \(B\) estimators, each with variance \(\sigma^2\) and average pairwise correlation \(\rho\), is \(\rho\sigma^2 + \frac{1-\rho}{B}\sigma^2\). As \(B\to\infty\) the second term vanishes, but the first term does not — the variance of the averaged forest converges to \(\rho\sigma^2\), a floor set entirely by how correlated the trees are with each other. This is exactly why the random feature subset at each split matters as much as bagging itself: it is the mechanism that lowers \(\rho\), which lowers the floor that adding more trees alone can never get below.
🧒 Explain like I'm 5

If you ask ten people who all read the exact same newspaper for their opinion, averaging their answers doesn't actually give you ten independent opinions — they're all repeating what the same source told them, so the "average" is barely more reliable than asking just one of them. But if you ask ten people who each got their information from a different, independent source, their combined average genuinely gets more trustworthy the more people you ask. Trees trained on similar data using similar rules are like the newspaper-readers — that's why simply growing more of them stops helping past a certain point unless you also make them see genuinely different things.

This is a genuinely different mechanism from the AIC/BIC penalty covered in Model Selection: AIC & BIC — that lesson penalizes complexity directly inside a selection score computed once, on one fitted model; a random forest never penalizes complexity at all, and each individual tree is still allowed to overfit its own bootstrap sample as much as it wants. The variance reduction comes entirely from combining many such trees, not from restraining any single one of them.

Section 04

Feature importance — a genuinely useful byproduct

Because a forest already tracks every split made by every tree, it produces feature importances essentially for free, in two standard flavors:

📊

Mean decrease in impurity (MDI)

Sum \(\Delta I(j,s)\) over every split that used feature \(j\), across every tree in the forest, weighted by how many training points passed through that split; average over the \(B\) trees. Cheap — it falls out of training with no extra computation — but biased toward continuous features and high-cardinality categoricals, which simply have more candidate thresholds to be picked at, inflating their apparent importance.

🔀

Permutation importance

For each feature \(j\), randomly shuffle that feature's column in a held-out (or out-of-bag) set, re-score the forest, and measure how much prediction error increases. A feature the model genuinely relies on causes a large error increase when scrambled; a feature it ignores causes almost none. More expensive to compute, but not biased toward high-cardinality features the way MDI is — generally the more trustworthy of the two.

🧒 Explain like I'm 5

Mean decrease in impurity is like counting how many times a word shows up in a book to guess how important it is — quick to check, but a word like "the" shows up constantly without actually meaning much. Permutation importance is more like removing a word from every page and seeing how much the story stops making sense — slower to check, but a far more honest test of whether that word actually mattered.

A useful side effect of bagging: since each tree only ever sees roughly 63% of the rows in its bootstrap sample (as \(N\to\infty\), the chance any given row is excluded from one bootstrap draw converges to \((1-1/N)^N \to e^{-1} \approx 0.368\)), the remaining ~37% — the out-of-bag (OOB) rows for that tree — were never used to train it. Averaging each row's prediction only over the trees that didn't see it during training gives an internal, honest validation estimate without needing to hold out a separate test set at all — the basis for permutation importance above, and a genuinely useful practical convenience of the bagging design.

\(\Delta I(j,s)\)Impurity reduction a candidate split (feature \(j\), threshold \(s\)) would produce.

\(m\)Number of features randomly considered as split candidates at each node (\(m < p\)).
\(p\)Total number of available features.

Worked example

A single deep tree memorizes; a small forest generalizes better

Eight training points, one feature \(x=1,\dots,8\), with a true underlying step relationship (0 below the boundary, 1 above it) plus two mislabeled points from noise, at \(x=4\) (noise flips it to 1) and \(x=5\) (noise flips it to 0):

x1   2   3   4   5   6   7   8
y (observed)0   0   0   1   0   1   1   1
1

An unconstrained single tree

Grown with no depth limit, the tree keeps splitting until every point is isolated — it can place a split between \(x=3\) and \(x=4\), then another between \(x=4\) and \(x=5\), then another between \(x=5\) and \(x=6\), reproducing all eight labels exactly, including both noise flips. Training error is exactly zero. Asked to predict a brand-new point at \(x=4.5\), this tree — having carved out a dedicated one-point region around the noisy \(x=5\) observation — has no principled reason to answer 0 or 1; it has fit the noise as confidently as the signal.

2

A forest of 3 shallow (depth-1) trees on bootstrap resamples

Each tree is restricted to a single split and trained on its own 8-point bootstrap resample (drawn with replacement, so each resample over- or under-represents different points, including possibly the two noisy ones). A depth-1 tree can only place one threshold, so it is forced to find the split that best separates the majority of its resampled points — the two isolated noise flips at \(x=4\) and \(x=5\) pull individual splits around slightly, but rarely dominate all three resamples at once.

3

Average the three trees' votes

Suppose the three depth-1 trees end up splitting at \(x\le3.5\), \(x\le4.5\), and \(x\le5.5\) respectively (plausible outcomes given which points each resample happened to emphasize). Their majority vote at \(x=4.5\) is 1 with probability \(2/3\) — noisy, but pulling toward the correct side of the true boundary more often than the single overfit tree's answer, which was fit to the specific noise realization at \(x=5\) rather than to where the underlying step actually sits.

This is illustrative of the mechanism, not a live model run on real data — the point is structural: the single deep tree's zero training error is a red flag, not an achievement, while the shallow forest's imperfect-but-more-robust vote is what the bias-variance tradeoff predicts an averaged, decorrelated ensemble should do.

Real-world trading scenario

A forest fed daily macro/technical features to predict next-day direction

Imagine building a feature table — yesterday's realized volatility, a handful of moving-average distances, a rate-differential level, a day-of-week dummy — and training a random forest to predict next-day FX direction. The forest will happily report feature importances: maybe the volatility feature and one moving-average distance rank highest. That output is real and reproducible in the sense that it faithfully describes which features the trained trees relied on most to reduce training-set impurity (or which features hurt OOB error most when shuffled). It says nothing yet about whether that importance reflects a genuine, persistent relationship or a relationship the forest found and exploited only within this particular historical sample — that question is a completely separate one, answered only by genuine out-of-sample testing with costs, exactly as the honest-teammate framing below insists.

A validated general-purpose method is not the same claim as "this feature set has edge." Random forests are real, effective, well-evidenced machinery for reducing a high-variance model's variance through averaging — that is a statement about the method. Whether any specific set of FX or macro features fed into that method contains a real, tradable, out-of-sample-surviving relationship is an entirely separate, unanswered question that this lesson does not touch. Nothing here should be read as evidence that a specific forest-based signal has, or will have, real edge — see The Research Pipeline for the actual discipline that question requires.
Section 05

How practitioners actually use this

In practice, forests are rarely tuned by exhaustively searching every hyperparameter; the handful that matter most are the number of trees \(B\) (more is essentially always at least as good, with diminishing returns and rising compute cost — there is no overfitting-from-more-trees effect the way there is with a single tree's depth), the feature-subset size \(m\) (the main lever on \(\rho\), the correlation floor above), and each tree's own depth or minimum leaf size (a secondary lever, since bagging already tolerates individually overfit trees far better than a single tree would). OOB error is commonly used in place of a separate validation split to tune these, since it comes essentially free from the training procedure itself. Forests are also a common first "sanity check" model before reaching for gradient boosting — covered next — precisely because they have so few hyperparameters that meaningfully change the result, making them harder to accidentally overfit through tuning alone.

⚠️
Common pitfalls

Where trees and forests quietly go wrong

Reading MDI feature importance as causal or as unconditionally reliable. A feature that's highly correlated with another, more genuinely informative feature can still rank as "important" by MDI simply because it was available as a proxy at some splits — MDI also mechanically favors continuous/high-cardinality features over binary ones, independent of true relevance. Prefer permutation importance, and treat both as "what the model leaned on," not "what causes the outcome."

Time-series data breaks the bootstrap's core assumption. Bootstrap resampling assumes rows are exchangeable — shuffling them and redrawing with replacement doesn't change what the data represents. Financial time series have autocorrelation and regime structure that a plain row-wise bootstrap ignores entirely, and a forest trained this way can leak information from adjacent time-adjacent rows across the train/OOB boundary. A specialized time-series-aware validation split remains necessary; OOB error is not a substitute for it here.

"More trees always helps" is true for variance, not for the correlation floor. Growing \(B\) from 100 to 10,000 keeps shrinking the \(\frac{1-\rho}{B}\sigma^2\) term, but the forest's variance never drops below \(\rho\sigma^2\) — if the trees are highly correlated (too large a feature subset \(m\), or too little diversity in the underlying features), no amount of extra trees fixes that.

Section 06

Key Takeaways

✓A tree is built by greedy recursive binary splitting, picking at each node the (feature, threshold) that most reduces impurity, and recursing on the children — the CART algorithm.
✗An unconstrained deep tree can drive training error to zero by memorizing the data — that is overfitting, not success, and it generalizes badly.
✓Random forests average many trees, each on a bootstrap resample (bagging) and restricted to a random feature subset per split. The feature subset decorrelates the trees — that's what the averaging actually needs to work.
⚠Averaging \(B\) correlated trees converges to a variance floor of \(\rho\sigma^2\), not zero. Lowering the trees' pairwise correlation matters as much as growing more of them.
✓Feature importance (MDI or permutation) and OOB error are genuinely useful, low-cost byproducts of the bagging design — not something bolted on afterward.
✗A trained forest's feature importances say nothing on their own about real trading edge. That question needs a genuine out-of-sample test with costs, kept entirely separate from "the method works well in general."
Section 07

Self-test

Q1. What quantity does a regression tree's greedy split search actually maximize at each node?
The impurity reduction \(\Delta I(j,s) = I(S) - \big[\frac{|S_L|}{|S|}I(S_L) + \frac{|S_R|}{|S|}I(S_R)\big]\) — the drop from the parent node's variance to the size-weighted average variance of the two children a candidate split (feature \(j\), threshold \(s\)) would produce. The search is over every feature and every realized threshold, and it is purely greedy: the single best split is taken immediately, with no lookahead to whether a locally worse split might enable a better tree overall.
Q2. Why does an unconstrained single decision tree tend to overfit so badly?
With no stopping rule (no max depth, no minimum leaf size), recursive splitting continues until every leaf holds a single training point (or a group of points sharing an identical target), driving training error toward zero. At that point the tree has stopped describing a general relationship between features and target and has instead built a lookup table that reproduces the training set exactly — including whatever noise happened to be in it — which has no reason to generalize to new data.
Q3. Random forests use two distinct sources of randomness. Name both, and state what each one is for.
(1) Bagging: each tree trains on its own bootstrap resample (drawn with replacement) of the training rows, giving each tree a different training set and therefore different overfit quirks. (2) A random subset of \(m\) of the \(p\) features is considered at each split (not just once per tree), which stops one dominant feature from producing similar splits — and therefore correlated trees — across the whole forest. Bagging alone gives variety; the random feature subset is what keeps that variety from collapsing back into correlated trees.
Q4. Why doesn't simply growing more trees (larger \(B\)) drive a random forest's variance all the way to zero?
The variance of the averaged forest is \(\rho\sigma^2 + \frac{1-\rho}{B}\sigma^2\), where \(\rho\) is the average pairwise correlation between individual trees' predictions. As \(B\to\infty\) the second term vanishes, but the first term, \(\rho\sigma^2\), does not depend on \(B\) at all — it is a floor set purely by how correlated the trees are with each other. More trees only ever removes the part of the variance the trees don't already share.
Q5. What is out-of-bag (OOB) error, and why does it come essentially free with a bagged forest?
Each bootstrap resample, drawn with replacement from \(N\) rows, excludes roughly \(e^{-1}\approx 36.8\%\) of the original rows on average — those excluded rows are that tree's out-of-bag set. Averaging each row's prediction only across the subset of trees that never saw it during training gives an honest validation-style error estimate without setting aside a separate held-out split, since the "held-out" rows are already a natural byproduct of the resampling every tree does anyway.
Q6. A random forest's permutation importance ranks a volatility feature as the single most important input for predicting next-day FX direction. Is that, by itself, evidence of real trading edge?
No. It is evidence that, within this trained model on this historical sample, scrambling that feature hurt the forest's own predictions the most — a statement about what the model leaned on, not a statement about whether that reliance reflects a genuine, persistent, out-of-sample relationship. A strong general-purpose method producing a confident-looking importance ranking is not the same claim as "this specific feature set has validated edge" — that requires a genuine out-of-sample test with realistic costs, entirely separate from the importance ranking itself.
