The Shortest Explanation Wins — Measured in Bits

This closes out the Information Theory category. Lesson 1 measured how much two variables tell each other, in bits — Lesson 2 asked whether one variable's past predicts another's future. This lesson turns the same bit-counting machinery on a different question: how do you formally judge whether a model is too simple, too complex, or exactly right? The Minimum Description Length (MDL) principle answers by literally treating "model + data" as a message and counting its bits — and lands, via a completely unrelated route through coding theory, on exactly the same penalty term worked out from Bayesian statistics in the earlier Model Selection: AIC & BIC lesson.

Section 1

Occam's razor, made countable

Imagine paying by the bit to send someone your model, and the data it describes, over a slow wire.

📡

Send the raw data

No model needed at all — but every idiosyncrasy of this one sample has to be spelled out in full. Expensive, and it teaches the receiver nothing reusable.

✂️

Send a model, then the leftovers

First a compact description of the pattern you found, then only what that pattern didn't already explain. If the pattern is real, this beats sending raw data outright.

🪶

Underfit — cheap model, costly leftovers

A model too simple to say much needs almost no bits to state, but leaves a mountain of unexplained residual to describe instead.

🧩

Overfit — costly model, suspiciously cheap leftovers

A model with a parameter for every quirk memorizes the sample. The residual nearly vanishes — but the model description itself becomes expensive to write down.

A model that "fits perfectly" by memorizing every data point is not a triumph under this accounting — it's often the most expensive message you could send, because you had to describe every last idiosyncrasy of this one sample instead of the underlying pattern.
Why "shortest," not just "simplest"

"Simplicity" is a vague, informal word — everyone agrees Occam's razor is a good idea and disagrees about what it means in any specific case. MDL replaces the word with a number: total bits to describe model plus data, lower always better. That's the entire move this lesson builds out.

Section 2

The two-part code, formalized

Total description length splits cleanly into two pieces. Lower is always better.

The formula
DL(M)
=
L(M)
+
L(D|M)
L(M) is the bits needed to state the model's form and its parameters. L(D|M) is the bits needed to state the data's residual "surprise," once the model is known — everything the model didn't already explain.

L(D|M) has a direct answer from Shannon's source coding theorem, introduced in Lesson 1 of this category: the shortest achievable average code for an outcome under a known probability distribution is −log₂ of that outcome's probability. Treat a fitted model's likelihood L̂(M) as "the probability of this data under this model," and the shortest code for the data given the model costs exactly −log₂ L̂(M) bits.

A quantity you've already met

−log₂ L̂(M) is precisely the "deviance," −2 ln L̂, from the Model Selection: AIC & BIC lesson — just expressed in bits (log₂) instead of nats (ln), and without that lesson's factor of 2. A model that fits well needs very few residual bits; a model that fits poorly needs many.

Section 3

Costing L(M): Rissanen's precision argument

A real-valued parameter has infinitely many decimals — but your data can't support infinite precision.

The formula
L(M)
≈
k/2
×
log₂(n)
k free parameters, each costing about half a log₂(n) bits — enough precision for the data to actually support the stated value, no more.
∞

Exact precision is impossible

Writing "3.14159265…" out in full never actually finishes — real numbers have infinite decimal expansions.

📏

But only finite precision is useful

A parameter estimated from n observations carries a standard error shrinking roughly as 1/√n — stating it more finely than that just describes noise.

➕

More data buys more digits

A bigger sample resolves each parameter more finely, so it costs a little more (growing as log₂n, slowly) to state it precisely.

×k

k parameters, k times the cost

Each free parameter pays its own share independently — the total scales linearly in k, the model's actual complexity count.

You don't need every decimal of a fitted parameter — only as many trustworthy digits as your sample size can actually back up. Rissanen's rule prices out exactly how many digits that buys you, per parameter.

Section 5

Two costs pulling in opposite directions

A schematic, not numeric, illustration of the trade-off — the exact computed version follows on the next two slides.

A simple model is cheap to state but may leave more residual surprise. A complex model costs more to state but can leave less residual. MDL adds both costs and picks whichever total is shorter — neither extreme wins automatically, and the only way to know which side of the trade-off you're on is to actually add the two numbers up.

Section 7

The bridge to BIC — the same rule, two directions

Two completely different starting points. Watch them land on the same number.

Two-part code (bits)

DL(M) = (k/2)·log₂(n) − log₂ L̂(M) — built from Shannon's source coding theorem, asking "what's the shortest message that describes this model and this data?"

BIC (nats)

BIC = k·ln(n) − 2 ln L̂(M) — built from Schwarz's Laplace approximation to a Bayesian marginal likelihood, asking "which model has the highest posterior probability?"

Multiply DL(M) by 2ln(2) ≈ 1.386 — a fixed positive constant, the bits-to-nats conversion doubled to match convention — and use ln(x) = ln(2)·log₂(x): the k/2·log₂(n) term becomes exactly k·ln(n), and −log₂L̂(M) becomes exactly −2 ln L̂(M). The result: BIC(M) = 2ln(2) · DL(M), exactly, for every candidate model. Since that scale factor never depends on which model M is, minimizing BIC and minimizing the two-part code are the identical optimization problem.

Not a coincidence

Schwarz derived BIC from Bayesian asymptotics in 1978. Rissanen derived (essentially) the same penalty from pure coding theory the same year, entirely independently — no shared assumptions, no shared toolkit. Two unrelated derivations landing on the same practical rule is strong evidence the rule is capturing something real: both are independently answering "how much does added complexity really buy you," and the coding-theory route gives BIC's abstract penalty a concrete, physical meaning — the literal cost, in bits, of writing the model down.

Section 9

How practitioners actually use this

📏

A sanity check on new penalties

"Does this correspond to a sensible code length" is a standard test any proposed complexity penalty is held to in the model-selection literature.

🧮

Normalized Maximum Likelihood (NML)

A more rigorous, encoding-independent refinement of the simple two-part code — harder to compute, used when the arbitrariness of a naive code matters.

🗜️

Lossless compression as model selection

Universal compressors are, at their core, implicitly solving an MDL-style model-selection problem over candidate coding schemes.

🔁

"Just compute BIC" is usually enough

Because of the exact bridge on the previous slide, computing BIC already gets you the MDL answer for the common two-part-code case — a second formula is rarely needed.

Recall the AIC & BIC lesson's own lag-selection scenario: a 5-lag spread model's four extra coefficients would cost about 4×½log₂(100) ≈ 13.3 extra bits just to state, and only bought back about 6/ln2 ≈ 8.66 fewer bits of residual. Describing those four extra lags costs more, in bits, than the story they tell about the spread is worth — the same BIC verdict, in a physical, checkable currency.

The one nuance carried over from the AIC & BIC lesson's own check still holds: forge/residual.py's Augmented Dickey-Fuller stationarity test calls statsmodels with autolag="AIC", so plain AIC does quiet work choosing a lag count inside that one diagnostic. That is AIC, not MDL, and it is not an explicit, reported model-comparison step — nothing in this repo computes a two-part MDL code length, BIC, or NML anywhere. The full lesson's "concept only" framing is, on inspection, still accurate for MDL specifically; nothing new to correct here.

Where this needs qualifying

The classical two-part code's L(M) term depends somewhat on the encoding scheme chosen — NML exists specifically to remove that arbitrariness, so treat the simple two-part number as a useful approximation, not a unique canonical constant. The (k/2)log₂(n)-per-parameter formula is also asymptotic, valid under the same large-n regime BIC's own derivation assumes. And the exact bridge proved above is specific to BIC — it does not extend to AIC, which targets a different quantity (expected out-of-sample KL divergence) entirely.

Section 11

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

What does the Minimum Description Length principle say the "best" model is?

DL(M) = L(M) + L(D|M), lower always better. Fewest parameters can lose (underfitting leaves a huge residual); highest likelihood can lose too (an overfit model's L(M) can outweigh its tiny residual).
Question 2

Why is L(D|M) = −log₂ L̂(M)?

Straight from Lesson 1's entropy result, applied to a model's own predicted probability of the observed data. It's also exactly the "deviance," −2lnL̂, from the AIC & BIC lesson — just expressed in bits.
Question 3

Per Rissanen, roughly how many bits does stating one real-valued parameter cost?

A parameter's standard error shrinks roughly as 1/√n, so stating it finer than that is wasted precision. The resolvable digits work out to about ½log₂(n) bits — growing slowly as more data resolves the parameter more finely.
Question 4

n=100, Model A (k=2) gives DL≈78.78 bits, Model B (k=5) gives DL≈84.42 bits. Which model does BIC prefer, from the AIC & BIC lesson?

1.386 × 78.78 ≈ 109.21 and 1.386 × 84.42 ≈ 117.03 — exactly the BIC values from the AIC & BIC lesson. The shorter code always picks the same winner as the lower BIC score.
Question 5

Schwarz (1978, Bayesian) and Rissanen (1978, coding theory) derived essentially the same penalty independently. Why does that matter?

That's the "aha" this lesson is built around — but it's specific to BIC and the classical two-part code. AIC targets a different quantity (out-of-sample KL divergence), so the equivalence doesn't extend to it.
Section 12

What to carry forward

01

MDL formalizes Occam's razor as literally the shortest total message: DL(M) = L(M) + L(D|M), lower always better.

02

L(D|M) = −log₂L̂(M) comes straight from Shannon's source coding theorem (Lesson 1's entropy result), applied to the model's own predicted distribution.

03

L(M) ≈ (k/2)log₂(n), per Rissanen — each parameter costs bits proportional to the precision the data can actually support.

04

BIC = 2ln(2)·DL(M), exactly, not approximately — verified on the AIC & BIC lesson's own Model A/B numbers: 78.78 and 84.42 bits scale to 109.21 and 117.03 nats precisely.

05

Two unrelated derivations — Schwarz's 1978 Bayesian asymptotics, Rissanen's 1978 coding theory, the same year — landed on the same practical penalty. Reassuring convergence, not coincidence.

06

The bridge is specific to BIC, not AIC — AIC targets a different (out-of-sample, KL-divergence) quantity, so don't over-extend the equivalence.

What this now lets you do

Explain, in plain "compression" terms, exactly what BIC's abstract penalty is charging for — the literal cost, in bits, of writing a model down. Compute a two-part code length and confirm it always picks the same model BIC does. Recognize an overfit model as a demonstrably inefficient message, not just a vaguely "risky" one — and know that, like BIC itself, a shorter code is a relative verdict among the candidates compared, never proof any of them is true.
