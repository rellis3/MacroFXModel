Lesson 01 · Foundation Mathematics

Algebra & Functions, Underneath the Formulas

Every later lesson in this curriculum hands you a formula and expects two things without saying so: that you can rearrange it to solve for whichever piece you actually need, and that you can read it as a function — an input-to-output rule — rather than a single fixed number waiting to be found. Both habits get built here, from nothing, before they show up later wearing a Greek letter.

The whole idea
🎧 Listen · the four-minute version

A trader and a quant talk the lesson through. No symbols, just the idea and one worked number, so it works on a walk or a commute.

I'll be honest. My school maths is rusty. When a lesson says "solve for x", I tense up.

Then let's make it small. Picture a balance scale, perfectly level. On one side, two bags of the same unknown weight plus three kilos. On the other side, eleven kilos.

And I want to know what one bag weighs.

Right. The only rule is this: whatever you do to one side, do to the other, and the scale stays level. So take three kilos off both sides. Now two bags balance eight kilos.

So one bag is four.

That's it. You halved both sides. That is all "solving for x" ever means: keep the scale level while you peel away everything that isn't the unknown.

Why did we take the three off first, and not halve first?

Because you undo things in reverse order. To build that side, someone doubled the bag and then added three. So you take away the three first, then halve. Like taking off your shoes before your socks.

OK. And what's a function? People say it like it's different.

It is different. A function is a machine. You put a number in, it does the same thing every time, and one number comes out. The "double it and add three" machine turns four into eleven. It isn't asking you to solve anything. It is just waiting for an input.

And running the machine backwards?

That is the inverse. Take away three, then halve, and eleven comes back to four. Running a machine backwards and solving an equation are the same move.

Where does a trader actually need that?

All the time. Markets quote prices, but traders compare yields and volatilities, and those are hidden inside the price. In nineteen seventy-six two researchers, Latané and Rendleman, took the new option pricing formula and ran it backwards, to get the volatility out of the price. Today options are quoted that way.

And this is old?

Very old. The name algebra comes from a handbook written in Baghdad around eight twenty by al-Khwarizmi, partly for trade. Its title talks about restoring and balancing, which is exactly the scale we just used.

So what do I take away?

Keep the scale level, undo the last step first, and remember that a formula is a machine you can also run backwards.

Section 1 · How it reached trading

Every yield is a formula run backwards

How it reached trading

Bond yield tables · implied volatility, Latané & Rendleman · 1976

A bond trades at a price and an option at a premium, but traders compare yields and volatilities. To get them you solve the pricing formula for the input that reproduces the quoted price.

Dealers once used printed yield tables for this. After Black–Scholes (1973), Latané and Rendleman (1976) solved it for volatility; interbank FX options are now quoted in implied vol, not premium.

Section 3

A function is a machine, not an answer

→

One input, one output

A function must return exactly one output for every input it accepts. f(x) = x² always gives back a single number, never two.

▢

The input is a placeholder

The x inside f(x) isn't a number waiting to be solved for — it's a stand-in for whatever gets fed in next.

≠

The name isn't the output

f is the machine itself; f(x) is one specific result of running it. Writing "f = x²" instead of "f(x) = x²" blurs a distinction that matters later.

⊘

Not everything qualifies

y² = x fails the test: x = 4 has two valid y-values, +2 and −2. y = √x fixes it by keeping only one.

Confusing a function with an equation is one of the most common early stumbling blocks, and it resurfaces constantly later in this curriculum. A pricing model, a volatility formula, an option's Greek — all of them are functions, not fixed numbers, and every one of them can be run forwards (given inputs, get a price) or asked to run backwards (given a price, recover an input).
Why you were taught it this way

Most courses introduce equations first and functions second, so the two ideas blur together early — it's simpler to teach "solve for x" before "this is a rule, not a question needing an answer." The blur is cheap, right up until the first time a formula needs to be run in reverse.

Section 4

What it can eat, what it can spit out

Domain is every input a function accepts without breaking. Range is every output it can actually produce. Pick a function.

Try it
Domain: every real number except 0 (dividing by zero is undefined). Range: every real number except 0 — the machine can never output exactly zero.
Domain: x ≥ 0 only — no real square root of a negative number. Range: f(x) ≥ 0 — the output is never negative.
Domain: every real number — squaring never breaks. Range: f(x) ≥ 0 only — a square is never negative.

Domain and range aren't pedantic technicalities — they're the boundary of what a formula is allowed to promise. A volatility model whose range excludes negative numbers is telling you something real about the world: volatility, by construction, can't be negative. When a formula's output starts landing outside its stated range, that is usually the first sign something upstream broke, not a special case worth explaining away.

Where this needs qualifying

In real market data, domain violations happen constantly — a negative price during a halt, a divide-by-zero from a stale feed, a zero-volume bar breaking a ratio. The math says these inputs are impossible; a data pipeline still has to catch them before a formula ever sees them.

Slope — direction and steepness

Positive rises left-to-right, negative falls, zero is flat. A slope further from zero is a steeper line.

⏚

Intercept — where it starts

On y = mx + c, that's exactly c — the value of y when x = 0, read straight off the formula, no computation required.

◡

Concavity — bowl or dome

Bending upward (its own slope keeps increasing) is convex; bending downward (its slope keeps decreasing) is concave. The sign of a in y = ax² decides which.

This is worth sitting with, because "convexity" comes back later in this curriculum wearing far more expensive clothing — an option's payoff diagram, a portfolio's risk profile, a bond's price-yield curve. All of it reduces to the exact question asked here: is the slope of this thing increasing or decreasing as the input moves?
Section 6

Chaining machines, and undoing them

Composition feeds one function's output into another. An inverse runs a function backwards.

Composition — f(g(x))

Feed x into g first, then feed g's result into f. With f(x)=x² and g(x)=x+1: (f∘g)(x) = f(g(x)) = (x+1)². Order matters — (g∘f)(x) = x²+1 is a different expression entirely.

Inverse — f⁻¹(x)

The machine that exactly undoes f, so f⁻¹(f(x)) = x. For f(x) = 2x+3: swap x and y, then resolve for y — f⁻¹(x) = (x−3)/2. Not every function has one; f(x)=x² doesn't, unless the domain is restricted to x ≥ 0.

Composition is what happens whenever one model's output feeds straight into another — a volatility figure into a pricing formula into a P&L calculation. Reading which function is innermost, applied first, versus outermost, applied last, is exactly the skill needed to correctly read a nested formula several layers deep. An inverse runs a formula backwards — "implied volatility" is, quite literally, an inverse function: recovering the input that would have produced an observed market price.

Rearranging isn't a detour from the "real" formula — it's the same formula, read backwards, which is most of what actually using a formula on a desk means.

The formula everyone starts from computes position size from equity: position size = equity × leverage ÷ price. But the question on the desk runs the other way — how much equity does a specific position actually require? Rearrange for equity by multiplying both sides by price, then dividing by leverage: equity = (position size × price) ÷ leverage = (10,000 × 1.20) ÷ 20 = $600.

Section 8

Nobody "does algebra" — but everyone runs formulas backwards

🎯

Interviews test this directly

"Given this formula, solve for this other variable" is common desk-interview shorthand for basic algebraic fluency, because it's the daily mechanical work underneath fancier-sounding tasks.

🔁

Calibration is inverse-solving at scale

Fitting a model to observed prices means finding the inputs that would have produced them — the same move as the leverage example, run thousands of times over.

📈

Reading a chart is reading slope and concavity

A steepening yield curve or an accelerating drawdown is, underneath the finance vocabulary, just "is the slope increasing or decreasing, and in which direction."

🏷

The vocabulary changes, the algebra doesn't

Convexity, duration, gamma: different names, applied to different formulas, for the exact bowl-vs-dome idea from Section 5.

Quant and desk-analyst interviews frequently test precisely this skill directly, because it's the daily mechanical work underneath far fancier-sounding tasks like calibration or implied-volatility surface construction. None of it is new math — it's this page, applied to longer formulas.
Section 9

Guessing vs. the rule

The same rearranging problem, approached two ways.

Rearranging by feel
  • Trial and error — plug in numbers until the equation looks right
  • Breaks down fast once roots or exponents appear
  • No way to know you've made an error until you check by substitution
  • Doesn't generalize to a formula you haven't seen before
Rearranging by rule
  • Same operation, both sides, every time
  • Undo operations in the exact reverse order they were applied
  • Works identically whether the unknown is x, a rate, or a required position size
  • The compound-interest case just needs one more layer — a fractional-power root
The difference isn't sophistication — it's whether the method still works once the formula gets longer than the one you memorized it on. A rule that only works on equations you've already seen isn't a rule; it's a memory.
Where this needs qualifying

Rearranging gets genuinely harder once roots, exponents, and logarithms are involved — solving the compound-interest formula FV = P(1+r)ⁿ for the rate r needs a fractional-power root, not just addition and subtraction. That's a habit worth building deliberately, before the formulas get longer.

Check yourself

Question 1

Rearrange y = 3x − 7 for x.

Add 7 to both sides, then divide both sides by 3 — the same "undo in reverse order" rule from Section 2.
Question 2

Can f(x) = x² ever output a negative number?

Range: f(x) ≥ 0. Negative outputs simply aren't in this machine's range, whatever the sign of the input.
Question 3

For f(x)=x² and g(x)=x−2, is (f∘g)(5) equal to (g∘f)(5)?

(f∘g)(5) = f(3) = 9. (g∘f)(5) = g(25) = 23. Composition generally isn't commutative — order matters.

Your call
Scenario drill · an illustrative account check

How much of your own money does the position need?

You want a position of 10,000 units of an instrument priced at \$1.20. Your broker allows 20:1 leverage, so each \$1 of your own money controls \$20 of position. How much equity do you need in the account?

  1. \$600.
    The position is worth 10,000 × \$1.20 = \$12,000. Leverage lets each \$1 control \$20, so divide: \$12,000 ÷ 20 = \$600. Check by running it forwards: \$600 × 20 ÷ \$1.20 = 10,000 units.
  2. \$12,000, to be safe.
    That is the full value of the position, with no leverage at all. It is a careful choice, but it answers a different question from the one asked.
  3. \$240,000.
    This multiplies by the leverage instead of dividing. Leverage means you need less of your own money, not more. Undo "times 20" with "divide by 20".
  4. \$500.
    This is 10,000 ÷ 20. It forgets the price, so it treats each unit as costing \$1 instead of \$1.20.

How it works out. This is an illustrative example using the numbers from this lesson's trading scenario, not a real account. The answer is \$600. The safe habit is the one from the whole lesson: after solving, put your answer back into the original formula and check it gives the number you started with.

Section 11

What to carry forward

01

Whatever you do to one side of an equation, do to the other — solving for a variable is repeatedly undoing operations, in reverse order, on both sides at once.

02

A function is a machine, not a solved value — f(x) means "apply the rule f to input x," and x is a placeholder, not an unknown waiting to be found.

03

Domain and range bound what's possible — domain is what a function can accept, range is what it can produce, and both matter before trusting a formula's output.

04

Slope is constant on a line, changing on a curve — a changing slope is exactly what "curving" (convex/concave) means, the idea convexity later builds on directly.

05

Composition chains functions, inverses undo them — order matters for composition, and not every function has a clean inverse.

06

Every yield or implied volatility on a screen is a pricing formula solved for one input: the same rearranging, run backwards from the market's price.

What this now lets you do

Rearrange any formula in this curriculum to solve for whichever variable you actually need, not just the one it was written to output. Read f(x) correctly on sight, without mentally translating it into "an equation to solve." Recognise convexity, composition, and inverses the moment they reappear later — under different names, in longer formulas.
