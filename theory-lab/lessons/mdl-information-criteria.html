Minimum Description Length & Information Criteria

Occam's razor, made countable: the best model is the one that lets you write down the shortest total message — model plus data — in bits. This lesson builds that idea from Shannon's coding theory, then shows it lands on exactly the same number as BIC, derived from a completely different, Bayesian starting point.

TL;DR
  • The Minimum Description Length (MDL) principle: the best model is the one giving the shortest total description of model + data given model, measured in bits — a coding-theory formalization of Occam's razor, with "shortest" doing the work "simplest" does informally.
  • The two-part code makes this concrete: \(DL(M) = L(M) + L(D\mid M)\) — bits to state the model, plus bits to state the data's residual "surprise" once the model is known. A more complex model costs more in the first term but less in the second; MDL picks the genuine trade-off, not either extreme.
  • Rissanen's classical result: encoding each of \(k\) real-valued parameters to the precision the data can support costs about \(\tfrac12\log_2(n)\) bits — which, after matching units, is exactly BIC's \(k\ln(n)\) penalty (from the AIC & BIC lesson) up to a constant scale factor.
  • The worked example reuses that lesson's exact numbers (\(n=100\), Model A: \(k=2\), Model B: \(k=5\)) and shows the two-part code length for each model is literally proportional to its BIC value — \(BIC = 2\ln(2)\cdot DL\) — so minimizing one always picks the same model as minimizing the other.
  • Schwarz derived BIC from Bayesian asymptotics in 1978; Rissanen derived (essentially) the same penalty from pure coding theory the same year, independently. Two different starting points, the same practical rule — the "aha" this lesson is built around.
  • How it reached trading: Rissanen's 1978 MDL criterion matches BIC, and mainly reached markets through BIC-style lag, factor and regime choices — plus the habit of asking whether a backtest compresses the data or memorises it.
🎧 Listen · the four-minute version

A trader and a quant talk the lesson through. No symbols, just the idea and one worked number, so it works on a walk or a commute.

Every time I add a rule to a strategy, the backtest gets better. When should I stop?

Here's one way to think about it. Imagine you have to send your model and your data to someone over a slow line, and you pay for every bit.

Why would that help?

Because you send two things. First the model itself, every rule and parameter. Then whatever the model fails to explain, the leftovers. A good model is cheap to state and leaves small leftovers. The best model is the one with the shortest total message.

And a model with a parameter for every quirk?

Its leftovers are tiny, but the model itself is expensive to write down. Memorising the data is often the longest message of all.

How much does one parameter cost?

Jorma Rissanen, a compression engineer at IBM, worked that out in 1978. You only need to state a parameter as precisely as your data can pin it down. That comes to about half the base-two log of the sample size, in bits. With a hundred observations, about three and a third bits per parameter.

Give me the comparison.

A hundred observations. Model A has two parameters. It costs about six and a half bits to state and leaves seventy-two bits of leftovers. About seventy-nine in total. Model B has five parameters and fits better. Its leftovers drop to about sixty-eight bits, but stating it costs over sixteen. About eighty-four in total.

So the three extra parameters lose.

They cost about ten bits to write down and save fewer than nine. A losing trade, in bits.

This sounds a lot like BIC.

It is BIC. Multiply the message length by a fixed constant, about one point four, and you get BIC exactly: one hundred and nine for Model A, one hundred and seventeen for Model B. Gideon Schwarz got BIC from Bayesian probability in 1978. Rissanen got the same penalty from compression, the same year, independently.

Two roads, one answer.

Which is good evidence the penalty measures something real. Two cautions, though. The shortest message is only the best of the models you tried, not the true model. And this exact match is with BIC, not AIC.

So what do I ask of my next backtest?

The one-line version: does this model compress the data, or does it just memorise it? Every parameter has to pay for itself in bits.

Section 01

Why this matters

The Model Selection: AIC & BIC lesson established that raw in-sample fit always favors the most complex candidate model, and built two ways to penalize complexity honestly: AIC's flat \(2\) bits — well, points — per parameter, and BIC's \(\ln(n)\)-per-parameter penalty derived from a Bayesian marginal-likelihood argument. Both are presented there as formulas to compute and compare. This lesson asks a different question about BIC specifically: where else does that exact penalty come from, and does starting from a completely unrelated field — coding theory, not Bayesian statistics — land on the same answer?

The reason this is worth building out, rather than treating as a curiosity, is that MDL gives "penalize complexity" a physical, literal meaning that "Bayesian marginal likelihood" doesn't immediately convey: a complex model that doesn't actually describe the data any better than a simple one is, quite concretely, a longer message — you'd need more bits to write it down and transmit it to someone else, model and all. That framing is Occam's razor with a ruler attached to it, and it's exactly the core overfitting argument this repo's own concerns are built around: a model with parameters that don't earn their keep isn't just "risky" in some vague sense, it is demonstrably a less efficient description of the same data.

💡
Plain-English intuition

Sending someone your model over a slow wire

Imagine you have to transmit both your model and the data it describes to someone over a slow connection, and you're paying by the bit. You could send the raw data as-is — expensive, but requires no model at all. Or you could first send a compact description of a pattern you found in the data (the model), and then only send the leftover part the pattern doesn't explain (the residual). If the pattern is real, this is a great trade: a short model description plus a small residual beats sending the raw data outright. But if you get greedy and build an overly elaborate model — one with a parameter carved out for every quirk in this particular batch of data — the model description itself gets expensive to send, even though the residual it leaves behind shrinks to almost nothing. MDL says: add up both costs, model and residual, and pick whichever description is shortest overall. A model that "fits perfectly" by memorizing every data point is not a triumph under this accounting — it's often the most expensive message you could possibly send, because you had to describe every last idiosyncrasy of this one sample instead of the underlying pattern.

How it reached trading

A backtest that memorised history

Minimum description length · Rissanen, 1978 · in markets mostly via its BIC-equivalent penalty — a research tool rather than a market standard

A strategy with enough rules and parameters can fit any history. Traders have long had the instinct that such a strategy has memorised the past rather than learned from it, but needed a way to charge a model for its own complexity on the same scale as its fit.

Jorma Rissanen, a compression engineer at IBM, gave that charge a precise form in 1978: the best model minimises the bits needed to describe the model plus the data encoded with it. His penalty matches Schwarz's BIC, and that is mainly how it reached finance — through BIC-style choices of lag length, factor count and number of regimes. MDL itself has stayed a research-desk tool rather than a market standard, used in places such as segmenting a series into regimes or change points.

On a desk today, its lasting use is as a question to ask of any backtest: does this model compress the data — capture real structure in fewer bits — or does it only reproduce the history it was fitted to?

🧒 Explain like I'm 5

MDL says the best explanation is the shortest one that still lets someone rebuild the full picture — the model plus whatever's left over that the model didn't cover. A model so simple it misses everything leaves a huge "leftover" pile to describe. A model so complicated it memorizes every last data point is expensive to write down in the first place. The winner is whichever total message — model plus leftovers — is shortest.

Section 02

The math, step by step

Watch the formula build
From "shortest message" to BIC, one term at a time
\[ DL(M) = \color{#fbbf24}{L(M)} \]

First you pay to state the model: its form and its fitted parameters.

\[ DL(M) = L(M) + \color{#fbbf24}{L(D \mid M)} \]

Then you pay to state what the model leaves unexplained. A better fit means fewer bits here.

\[ DL(M) = L(M) + \color{#fbbf24}{\bigl(-\log_2 \hat L(M)\bigr)} \]

Shannon's coding theorem prices the leftovers: the shortest code for the data is minus the log of its likelihood under the model. For Model A that is \(50/\ln 2 \approx 72.135\) bits.

\[ DL(M) = \color{#fbbf24}{\frac{k}{2}\log_2(n)} + \bigl(-\log_2 \hat L(M)\bigr) \]

Rissanen prices the model: each of \(k\) parameters, stated only as precisely as \(n\) observations allow, costs about \(\tfrac12\log_2 n\) bits. With \(n = 100\) and \(k = 2\), that is 6.644 bits, so \(DL(M_A) \approx 78.779\).

\[ \color{#10b981}{2\ln(2)\cdot DL(M) = k\ln(n) - 2\ln\hat L(M) = \text{BIC}(M)} \]

Rescale bits to the BIC convention with the fixed constant \(2\ln 2 \approx 1.386\), and the message length is BIC exactly: \(1.386 \times 78.779 \approx 109.21\). Same argmin, so the same model wins.

The two-part code

Formalize "send the model, then send what's left over" as a literal two-part code length. For a candidate model \(M\) and observed data \(D\), define the total description length as:

\[ DL(M) = L(M) + L(D \mid M) \]
L(M)
Bits to describe the model
Its form, and its parameters, to whatever precision the data can support
L(D|M)
Bits to describe the data, given the model
The residual "surprise" — everything the model didn't already explain
DL(M)
Total message length
Lower is better — the model that compresses the data most efficiently overall

\(L(D\mid M)\) has a direct answer from Shannon's source coding theorem — introduced in the first lesson of this category: the optimal (shortest achievable, on average) code length for describing an outcome under a known probability distribution is \(-\log_2\) of that outcome's probability. If \(M\)'s fitted parameters assign the observed data a likelihood \(\hat L(M)\), the shortest achievable code for the data given that model is:

\[ L(D\mid M) = -\log_2 \hat L(M) \]

This is precisely the "deviance" quantity from the AIC & BIC lesson, \(-2\ln\hat L(M)\), just expressed in bits (\(\log_2\)) instead of nats (\(\ln\)) and without the AIC/BIC convention's factor of 2. A model that fits the data well (high likelihood) needs very few bits to describe the residual surprise; a model that fits poorly needs many.

🧒 Explain like I'm 5

This half of the message is "the part your model still can't explain." If your model of the data is a good one, there's very little left to say — a short leftover message. If it's a bad model, everything the data actually did still needs to be spelled out in full, and that costs a lot of bits.

Costing L(M): Rissanen's parameter-precision argument

\(L(M)\) is subtler: describing a model with continuous, real-valued parameters exactly would take infinitely many bits (real numbers have infinite decimal expansions). But you don't need infinite precision — you only need enough precision that the parameter's value is distinguishable from "noise" given how much data you actually have. Rissanen's classical argument (1978, refined in later work) shows that specifying a single real-valued parameter to the precision a sample of size \(n\) can actually support costs approximately:

\[ \tfrac{1}{2}\log_2(n) \text{ bits per parameter} \]

The intuition: a parameter estimated from \(n\) observations carries a standard error that shrinks roughly as \(1/\sqrt{n}\) — so specifying the parameter to a finer precision than its own standard error is wasted, meaningless precision, describing noise rather than signal. The number of bits needed to distinguish among the "genuinely resolvable" values within that precision works out to about \(\tfrac12\log_2(n)\), growing (slowly) with the sample size because more data resolves the parameter more finely and so costs slightly more to state precisely. For a model with \(k\) free parameters:

\[ L(M) \approx \frac{k}{2}\log_2(n) \]
(k/2)log₂(n)bits to state k parameters, each to data-supported precision
nsample size — more data resolves each parameter more finely, costing slightly more to state
🧒 Explain like I'm 5

Writing down a parameter like "3.14159265..." exactly would take forever, since real numbers never actually end. But you don't need every decimal — only as many digits as your data can actually back up. A small sample only justifies a rough value; a huge sample justifies a much more precise one. Rissanen's rule prices out how many "trustworthy digits" a given sample size buys you, per parameter.

The bridge to BIC — the same rule, two directions

Put the two pieces together into the full two-part code length, in bits:

\[ DL(M) = \frac{k}{2}\log_2(n) \;+\; \big(-\log_2\hat L(M)\big) \]

Now recall BIC from the AIC & BIC lesson, defined there in nats: \(\text{BIC} = k\ln(n) - 2\ln\hat L\). Multiply the two-part code length above by \(2\ln 2\) (a fixed positive constant — the conversion factor between bits and nats, doubled to match the AIC/BIC convention) and use \(\ln(x) = \ln(2)\cdot\log_2(x)\):

\[ 2\ln(2)\cdot DL(M) = 2\ln(2)\cdot\frac{k}{2}\log_2(n) + 2\ln(2)\cdot\big(-\log_2\hat L(M)\big) = k\ln(n) - 2\ln\hat L(M) = \text{BIC}(M) \]
2ln(2)·DL(M)the two-part code length, rescaled from bits to the AIC/BIC nats convention
= BIC(M)exactly — the same quantity, not merely similar

This is the whole bridge, stated precisely: \(\text{BIC}(M) = 2\ln(2)\cdot DL(M)\). Since \(2\ln(2)\approx 1.386\) is a fixed positive constant that doesn't depend on which model \(M\) you're evaluating, multiplying every candidate's \(DL(M)\) by it can never change which model has the smallest value. Minimizing BIC and minimizing the two-part MDL code length are the same optimization problem — not "similar in spirit," but the identical argmin, arrived at from two unrelated starting points: Schwarz (1978) derived BIC from a Laplace approximation to a Bayesian marginal likelihood; Rissanen (1978), the same year, entirely independently, derived (essentially) the same per-parameter penalty from asking "what is the shortest code that describes this model and this data." A Bayesian asymptotic argument and a coding-theory argument, arriving at the same practical rule — that convergence is exactly the "aha" this lesson exists to make explicit, not a coincidence to wave past.

🧒 Explain like I'm 5

Two people, working entirely separately with entirely different toolkits — one thinking about probability and belief, the other thinking about compressing messages — landed on the same formula for "how much a model should be punished for having extra knobs." When two unrelated ways of solving a problem agree on the same answer, that's strong evidence the answer is capturing something real, not an accident of either person's particular approach.

What this does and doesn't say about AIC: the exact bridge proved above is specifically between BIC and the classical two-part MDL code. AIC does not have the same clean, exact coding-theory derivation — its justification (from the AIC & BIC lesson) is an out-of-sample, Kullback-Leibler-divergence argument, a different target from "shortest code for this specific sample." More refined MDL formulations exist (normalized maximum likelihood, NML) that relate more closely to AIC-style penalties in some settings, but that connection is looser and outside the scope of this lesson — don't over-extend the exact BIC bridge above into an equally exact AIC one.

Worked example

Reusing the AIC/BIC lesson's exact numbers

The AIC & BIC lesson's worked example used \(n=100\) observations, Model A (\(k=2\), \(-2\ln\hat L_A=100\)) and Model B (\(k=5\), \(-2\ln\hat L_B=94\)), and found BIC\(_A=109.21\), BIC\(_B=117.03\) — BIC preferring the simpler Model A by about 7.8 points. Compute the two-part MDL code length for the same two models and check the bridge above holds exactly.

Model A (\(k=2\), \(-2\ln\hat L_A=100 \Rightarrow \ln\hat L_A=-50\)):

\[ L(M)_A = \tfrac{2}{2}\log_2(100) \approx 6.644 \text{ bits} \qquad L(D\mid M)_A = \frac{50}{\ln 2} \approx 72.135 \text{ bits} \]
\[ DL(M_A) = 6.644 + 72.135 \approx 78.779 \text{ bits} \]

Model B (\(k=5\), \(-2\ln\hat L_B=94 \Rightarrow \ln\hat L_B=-47\)):

\[ L(M)_B = \tfrac{5}{2}\log_2(100) \approx 16.610 \text{ bits} \qquad L(D\mid M)_B = \frac{47}{\ln 2} \approx 67.807 \text{ bits} \]
\[ DL(M_B) = 16.610 + 67.807 \approx 84.416 \text{ bits} \]

Check the bridge: \(2\ln(2)\times 78.779 \approx 109.21\) — matching BIC\(_A\) exactly. \(2\ln(2)\times 84.416 \approx 117.03\) — matching BIC\(_B\) exactly. Model A's shorter two-part code (78.78 bits vs. 84.42 bits, a gap of 5.64 bits) picks out precisely the same winner BIC did, because it is, up to that fixed \(2\ln(2)\) rescaling, the exact same number. Model B's three extra parameters cost \(3\times\tfrac12\log_2(100)\approx 9.97\) extra bits to state, and only saved \(\tfrac{6}{\ln 2}\approx 8.66\) bits of residual — a losing trade in coding-length terms, told in the same currency (bits) that made the original in-sample-fit-always-improves problem from the AIC & BIC lesson concrete in the first place.

Section 03

How practitioners actually use this

MDL is used two ways in practice. First, as a philosophical anchor: when a new information criterion or regularization penalty is proposed, "does it correspond to a sensible code length" is a standard sanity check applied by the model-selection literature, and the BIC-MDL equivalence above is the textbook example of that check succeeding. Second, and more directly, MDL is used as a literal model-selection procedure in its own right — most rigorously via normalized maximum likelihood (NML), a refinement of the simple two-part code that removes the arbitrariness of exactly how you encode the model (the classical two-part code's \(L(M)\) term depends somewhat on the encoding scheme chosen; NML is designed to be encoding-independent). NML is more principled but computationally harder, which is exactly why the simpler two-part code — and its convenient exact equivalence to BIC — remains the practically dominant way practitioners actually use "MDL thinking" day to day: compute BIC, and know that you are, in effect, already choosing the shortest two-part description.

Normalized Maximum Likelihood (NML)

The more rigorous, encoding-independent refinement of the simple two-part code — harder to compute, used when the arbitrariness of a naive code matters.

🗜️

Lossless compression as model selection

Universal compressors (used e.g. in data-compression benchmarks) are, at their core, implicitly solving an MDL-style model-selection problem over candidate coding schemes.

🔁

"Just compute BIC" is usually enough

Because of the exact bridge proved above, computing BIC already gets you the MDL answer for the common two-part-code case — a second formula is rarely needed in practice.

🎯
Real-world trading scenario

Explaining a lag-selection decision in coding-theory language

Recall the AIC & BIC lesson's own trading scenario: choosing between a 1-lag and a 5-lag autoregressive model of a mean-reversion spread, where BIC preferred the simpler 1-lag model by about 7.8 points. Reframe that exact decision through the two-part code lens built here: the 5-lag model's four extra coefficients would need roughly \(4\times\tfrac12\log_2(100)\approx 13.3\) extra bits just to state — to write down their fitted values to the precision 100 days of data can actually support — and those four extra lags bought back only about \(\tfrac{6}{\ln 2}\approx 8.66\) fewer bits of residual "surprise" in the data. In plain terms: describing those four extra lag coefficients costs more, in bits, than the story they tell about the spread's actual behavior is worth. That is a genuinely different way of stating the same verdict BIC already gave — not a new number, but a physical, checkable interpretation of what the BIC penalty is actually charging for: the literal cost of writing the model down.

⚠️
Common pitfalls

Where this goes wrong in practice

Treating the two-part code's \(L(M)\) as encoding-scheme-free. The classical two-part code's model-description cost depends, in principle, on exactly how you choose to encode parameters — a different (equally valid) encoding scheme can shift \(L(M)\) somewhat. Rissanen's later NML refinement exists specifically to remove this arbitrariness; treating the simple two-part number as if it were the unique, canonical "true" code length overstates its precision.

Confusing "shortest description" with "true model." Like BIC (per the AIC & BIC lesson's own caveats), a winning MDL code length is a relative statement among the candidates you actually compared — it does not certify that the winning model is correct in any absolute sense, only that it compressed this particular dataset most efficiently among the options tried.

The \(\tfrac12\log_2(n)\)-per-parameter formula is asymptotic. It's derived under large-\(n\) approximations, the same regime BIC's own Bayesian derivation assumes. For small samples relative to \(k\), both the code-length approximation and BIC itself become less reliable — the same small-sample caveat (and the AICc correction) already flagged in the AIC & BIC lesson applies here too.

Reading the BIC-MDL bridge as also covering AIC. The exact equivalence proved in this lesson is specifically between BIC and the classical two-part code — it is not a general "all information criteria are secretly MDL" claim. AIC's justification targets a different quantity (expected out-of-sample KL divergence), and conflating the two derivations is a common, avoidable overreach.

Scenario drill · an illustrative model review

One lag or five for a mean-reversion spread?

You have 100 days of a mean-reversion spread and two autoregressive models. The 5-lag model fits better in sample. Its four extra coefficients would cost about 13.3 bits to state at the precision 100 days support, and they cut the bits needed for the leftovers by about 8.66. BIC prefers the 1-lag model by about 7.8 points. Which model do you take forward, and what do you say about it?

  1. The 5-lag model. It fits the data better, and fit is what matters.
    In-sample fit always improves when you add parameters. The extra lags cost more bits to write down than they save, which is the signature of describing this sample's quirks rather than the spread's behaviour.
  2. The 1-lag model, as the shortest total description among the two you compared, then check it out of sample.
    This is what both MDL and BIC say, and it states the claim at its true size: the best compression of this data among the candidates tried. The out-of-sample check is the next test, not something the code length already proves.
  3. The 1-lag model, described in the write-up as the true model of the spread.
    Right model, wrong claim. A shorter code is a relative verdict among the models you compared. It does not certify that the winner is correct, or that it carries a trading edge.
  4. Switch to AIC, which penalises parameters less, and keep the 5-lag model if AIC prefers it.
    Choosing the criterion after seeing which answer you like is a hidden form of overfitting. AIC also targets a different question, expected out-of-sample KL divergence, so the exact coding argument here does not carry over to it.

What the lesson says. This is an illustrative case built on the lesson's own lag-selection scenario, not a dated episode. Describing the four extra lag coefficients costs more bits than the story they tell about the spread is worth, so the 1-lag model is the shorter message, the same verdict BIC gives. It wins among the candidates compared; whether it holds up is a question for out-of-sample data.

Key Takeaways

✓MDL formalizes Occam's razor as "shortest total message." \(DL(M) = L(M) + L(D\mid M)\) — bits to state the model, plus bits to state what's left over — with lower always better.
✓\(L(D\mid M) = -\log_2\hat L(M)\), directly from Shannon's source coding theorem. The same "deviance" quantity from the AIC & BIC lesson, just expressed in bits.
✓\(L(M)\approx\tfrac{k}{2}\log_2(n)\), per Rissanen — each parameter costs bits proportional to the precision the data can support.
✓BIC equals \(2\ln(2)\) times the two-part MDL code length — exactly, not approximately. Verified numerically on the AIC/BIC lesson's own Model A/B example: 78.78 and 84.42 bits scale to 109.21 and 117.03 nats precisely.
✓Two unrelated derivations, one answer. Schwarz's 1978 Bayesian asymptotic argument and Rissanen's 1978 coding-theory argument — independently, the same year — land on the same practical penalty.
⚠The bridge is specific to BIC, not AIC. AIC targets a different (out-of-sample, KL-divergence) quantity — don't extend the exact BIC-MDL equivalence into a claim about AIC too.
⚠A shorter code is a relative, not absolute, verdict. Same caveat as BIC itself: the winning model compressed this dataset best among the candidates tried — that's not the same claim as "this model is true," or that it produces trading edge.
ℹHow it reached trading: does the strategy compress, or memorise? MDL reached markets mostly through its BIC-equivalent penalty for lags, factors and regimes; its lasting use is as an overfitting test for parameter-heavy backtests.
Section 05

Self-test

Q1. In your own words, what does the Minimum Description Length principle say the "best" model is?
The model that minimizes the total number of bits needed to describe both the model itself and the data given that model — \(DL(M) = L(M) + L(D\mid M)\). It's a coding-theory version of Occam's razor: not "simplest" in some vague, informal sense, but literally "shortest total message," where a more complex model has to justify its extra cost of description by leaving a correspondingly smaller residual to describe.
Q2. Why is \(L(D\mid M) = -\log_2\hat L(M)\), and what earlier result in this category does that formula come from?
It comes directly from Shannon's source coding theorem, introduced in the first lesson of this category: the shortest achievable average code length for describing an outcome under a known probability distribution is \(-\log_2\) of that outcome's probability. Once a model's parameters are fixed, it assigns the observed data a likelihood \(\hat L(M)\) — treating that as the "probability of this data under this model," the optimal code for describing the data given the model costs \(-\log_2\hat L(M)\) bits, exactly the entropy-coding bound from Lesson 1 applied to the model's own predicted distribution.
Q3. Derive the exact relationship between BIC and the two-part MDL code length \(DL(M)\), starting from \(DL(M) = \tfrac{k}{2}\log_2(n) - \log_2\hat L(M)\).
Multiply both sides by \(2\ln(2)\): \(2\ln(2)\cdot DL(M) = 2\ln(2)\cdot\tfrac{k}{2}\log_2(n) - 2\ln(2)\cdot\log_2\hat L(M)\). Using the change-of-base identity \(\ln(x) = \ln(2)\cdot\log_2(x)\), the first term becomes \(k\ln(n)\) and the second becomes \(-2\ln\hat L(M)\). So \(2\ln(2)\cdot DL(M) = k\ln(n) - 2\ln\hat L(M)\), which is exactly the definition of BIC from the AIC & BIC lesson. Since \(2\ln(2)\) is a fixed positive constant independent of which model is being scored, \(\text{BIC}(M) = 2\ln(2)\cdot DL(M)\) for every candidate model, so minimizing one always selects the same model as minimizing the other.
Q4. Using the worked example's numbers (Model A: \(DL=78.78\) bits; Model B: \(DL=84.42\) bits), verify the bridge numerically and state which model the two-part code prefers.
\(2\ln(2)\approx1.386\). \(1.386\times78.78\approx109.21\), matching BIC\(_A=109.21\) from the AIC & BIC lesson exactly. \(1.386\times84.42\approx117.03\), matching BIC\(_B=117.03\) exactly. Since \(78.78 < 84.42\), Model A has the shorter two-part code — the same model BIC preferred, for the identical reason (up to the fixed rescaling): fewer total bits to describe model plus data.
Q5. Why does it matter, historically and conceptually, that Schwarz (1978) and Rissanen (1978) arrived at essentially the same per-parameter penalty from completely different starting points?
Schwarz's derivation is Bayesian: approximate a marginal likelihood (an integral over a prior on the model's parameters) using a Laplace approximation, valid asymptotically as \(n\to\infty\). Rissanen's derivation is coding-theoretic and has nothing to do with priors or Bayesian updating at all: it asks purely "what is the shortest code that describes this model and this data." That two derivations built from entirely unrelated mathematical frameworks converge on the same practical penalty is strong independent corroboration that the penalty is capturing something real and not an artifact of either framework's specific assumptions — the kind of cross-validation-by-independent-derivation that gives a result more weight than either derivation alone would.
Q6. A colleague argues "MDL and AIC must also be secretly the same thing, since MDL and BIC are." What's the error in that reasoning?
The exact equivalence proved in this lesson (\(\text{BIC}=2\ln(2)\cdot DL\)) is specific to BIC and the classical two-part code — it does not extend to AIC. AIC is derived from a different target altogether: an estimate of expected out-of-sample Kullback-Leibler divergence between the fitted model and the true data-generating process (from the AIC & BIC lesson), not "the shortest code for this specific sample." The two-part MDL code and BIC happen to optimize the same underlying description-length quantity; AIC optimizes a genuinely different one. Their formulas resembling each other's general shape (a fit term plus a complexity penalty) does not imply all three collapse into one identity — only the BIC/MDL pair has the exact bridge shown here.
