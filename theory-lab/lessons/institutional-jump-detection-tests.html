Lee-Mykland & Boudt-Croux-Laurent: Testing for Jumps

Bipower variation, the previous lesson's tool, tells you how much of a day's total variance came from jumps in aggregate. It cannot tell you which specific return was the jump. This lesson builds the test that can — and the correction that keeps that test honest across a trading day whose ordinary volatility is anything but flat.

CONCEPT — with a rare exception: this repo's own jump_detect_lm.py implements BOTH Lee-Mykland AND a Boudt-Croux-Laurent-style periodicity correction, live and consumed by two downstream modules — details in the repo callout below ~19 min read Prereqs: Bipower Variation: Decomposing Continuous vs. Jump Variation
Prefer pictures to prose? Try the Visual Guide — the same ground covered here, broken into short interactive slides.
TL;DR
  • Bipower variation answers "how much of today's variance was jumpy" with a single daily ratio. It has no per-return resolution — it structurally cannot say which return was the jump, how many there were, or when. Lee-Mykland (2008) is the test built to answer exactly that.
  • Lee-Mykland scales each return by a local volatility estimate built from bipower variation over nearby returns, excluding the return being tested — so a genuine jump can't contaminate the very yardstick used to judge it. The ratio is \(L_i = r_i/\hat\sigma_i\).
  • The day's maximum \(|L_i|\), under the null of no jumps, converges to a Gumbel (extreme-value) distribution as the number of tested returns grows — not a normal distribution — because it is the maximum of many approximately-Gaussian ratios, and maxima of Gaussians have their own, slower-growing limiting law. The critical threshold has to come from that theory, with sample-size-dependent normalizing constants, not from a flat "4-sigma" rule of thumb.
  • Intraday volatility has a well-documented U-shape — busy at the open and close, quiet mid-session. A plain Lee-Mykland test, applied without adjustment, systematically over-flags ordinary open/close moves as jumps and under-flags genuine mid-session jumps, because its local-vol yardstick blends the whole day together.
  • Boudt-Croux-Laurent (2011) fixes this by estimating a per-time-of-day volatility factor and dividing every return by its own time-of-day's typical size before applying the Lee-Mykland statistic — de-seasonalizing volatility before testing for jumps.
  • This repo's own detector implements both pieces, is consumed by two downstream modules, and its own unit test shows the periodicity correction collapsing a diurnal false-positive count from 1,020 to 3 on synthetic pure-diffusion data. The findings it produces are about volatility regime, not direction — see the repo callout for the honest specifics.
Section 01

Why this matters — the question bipower variation can't answer

Bipower Variation decomposed a day's total realized variance into a continuous part and a jump part — one number per day, telling you what share of the day's variance came from discontinuous moves. That is genuinely useful, and it is also, by construction, the end of what a single daily ratio can say. It cannot tell you whether the day held one enormous jump or four modest ones. It cannot tell you whether the jump happened at the London open, around a scheduled data release, or in a quiet overnight session. It has no per-return resolution at all — a ratio computed over an entire day's worth of returns has already thrown that information away by the time you read it.

This lesson answers the sharper question: given a sequence of high-frequency returns, which specific one is statistically very unlikely to have come from ordinary continuous diffusion? That is a per-return hypothesis test, run independently at every point in the day, and it needs its own machinery — built by Suzanne Lee and Per Mykland in 2008, with an important correction added by Kris Boudt, Christophe Croux, and Sébastien Laurent in 2011 once the test was run on real, intraday-seasonal data and produced systematically wrong answers at certain times of day.

💡
Plain-English intuition

Judging "unusually late" against how late someone usually runs

Deciding whether a single return is a jump is like deciding whether a friend showing up 20 minutes late is alarming. The answer depends entirely on the yardstick: 20 minutes late is nothing for a friend who routinely runs 30 minutes behind, and a real red flag for a friend who has never once been more than 2 minutes late. Lee-Mykland's core idea is exactly this comparison, made rigorous: build a local estimate of how big returns usually are right around this point in time, from the nearby returns — but pointedly excluding the return currently being judged, so a genuine jump can't inflate the very yardstick used to catch it — and then ask whether today's specific return is implausibly large against that local yardstick.

The complication Boudt-Croux-Laurent exists to fix is equally intuitive: what if "how late this friend usually runs" itself depends systematically on the time of day — chronically 25 minutes late to breakfast, always on time for dinner? Averaging across the whole day to build one yardstick would call the friend "suspiciously punctual" at breakfast and "suspiciously late" at dinner, when neither is actually unusual once you condition on the time. Intraday volatility does exactly this — high near the open and close, quiet mid-session — and a yardstick that ignores it makes precisely that mistake, for precisely that reason.

Section 02

The math, step by step — Lee-Mykland (2008)

Let \(r_i\) denote the (possibly already-deseasonalized — Section 04 covers that) log-return over a short high-frequency interval, indexed \(i=1,\dots,n\) across a trading day. The local volatility estimate at point \(i\) is built from bipower variation over the \(K\) returns immediately preceding it, deliberately excluding \(r_i\) itself:

\[ \hat\sigma_i^2 = \frac{1}{K-2}\sum_{j=i-K+2}^{i-1} |r_j|\,|r_{j-1}| \]
σ̂ᵢthe local volatility estimate used to judge return i — built entirely from OTHER returns
Kthe window size — how many nearby returns feed the local estimate
|r_j||r_{j-1}|consecutive absolute-return products — the same bipower building block from the previous lesson

Excluding \(r_i\) from its own yardstick is the whole point: if a real jump happened at \(i\) and its size leaked into \(\hat\sigma_i\), the estimate would inflate itself around the jump and the test would blind itself to the very thing it exists to catch. The test statistic is then simply the standardized return:

\[ L_i = \frac{r_i}{\hat\sigma_i} \]

A large \(|L_i|\) says "this return is big relative to what's been typical right around it." The subtlety — and the reason this test needed an entire paper rather than a single formula — is what "big" should mean when you are computing \(L_i\) at every point in the day and asking whether any of them stands out.

⚠️
Why the maximum of many z-scores is not itself a z-score

Extreme value theory, not a flat "4-sigma" rule

Under the null hypothesis of pure continuous diffusion (no jumps anywhere), each \(L_i\) is, approximately and individually, a standard-normal-like ratio. But a day's test doesn't ask about one \(L_i\) — it asks whether the maximum of \(|L_i|\) over all \(n\) returns in the day exceeds some threshold. That is a completely different statistical object. The maximum of \(n\) independent (or weakly dependent) draws from a distribution in the normal's domain of attraction does not converge to another normal distribution as \(n\) grows — it converges to a Gumbel distribution, one of the three classical extreme-value laws (the Fisher–Tippett–Gnedenko theorem). Normal tails decay so fast that the maximum over many draws grows only slowly, on the order of \(\sqrt{\ln n}\) — a specific, well-characterized shape, but not a bell curve, and not something a flat "flag anything past 4 standard deviations" rule respects.

Practically, this means the critical value a day's maximum \(|L_i|\) needs to clear depends on \(n\) — how many returns were tested that day — through two normalizing constants derived from the Gumbel limit law:

\[ \text{flag return } i \text{ if } |L_i| > C_n + S_n\big(-\ln(-\ln(1-\alpha))\big) \]
\[ C_n = \frac{\sqrt{2\ln n}}{c} - \frac{\ln\pi + \ln\ln n}{2c\sqrt{2\ln n}}, \qquad S_n = \frac{1}{c\sqrt{2\ln n}}, \qquad c = \sqrt{\tfrac{2}{\pi}} \]
α
Per-day false-positive rate
Under pure diffusion with no jumps at all, a fraction α of days would still show at least one "jump" purely by chance. This repo's detector uses α=1%.
C_n, S_n
Gumbel location & scale
Reparameterized for this test, both functions of n alone — more returns tested per day pushes the critical value up, since there are more chances for an ordinary large return somewhere.
c = √(2/π)
A normalizing constant
The raw bipower average is a slightly biased variance estimator (E|Z|=√(2/π) for standard normal Z). Rather than rescale σ̂ᵢ itself, this constant is folded straight into Cₙ and Sₙ — exactly how this repo's own code does it too.
The "~4-sigma" heuristic is a simplification, not the actual rule. A commonly cited rough guide in practice is to treat \(|L_i|\) past roughly 4 to 5 as "probably a jump" for a typical intraday sample size. That number isn't arbitrary — it's roughly where \(C_n + S_n(-\ln(-\ln(1-\alpha)))\) happens to land for common \((n,\alpha)\) combinations — but it is a simplification riding on that coincidence, not the actual rule. The real critical value is sample-size-dependent, computed exactly as above. For \(\alpha=1\%\), it moves with \(n\):
\(n=10\)critical value ≈ 4.80 (this lesson's toy 10-bar example, Section 05)
\(n=78\)critical value ≈ 5.10
\(n=96\)critical value ≈ 5.14
\(n=288\)critical value ≈ 5.40 (a full session of continuous 5-minute bars — this repo's own default, and the value used by the calculator in Section 06)
🧒 Explain like I'm 5

If you flip one coin, getting heads isn't surprising. If you ask a thousand people to each flip a coin, someone getting ten heads in a row isn't surprising either — with a thousand tries, a run that rare is bound to show up in at least one of them. The more chances you give something unlikely to happen, the more likely it is that somewhere in all those chances it actually does — and the "how surprised should I be" threshold has to rise with the number of chances, not stay fixed. Testing every single return in a day for "is this one a jump" is exactly this situation: more returns tested means a bigger single move is needed before it's genuinely surprising, and the Gumbel-based threshold is what correctly raises the bar as the number of tries grows.

\(K\)The local window size. This repo uses \(K=270\) for 5-minute returns — Lee-Mykland's own recommendation at that sampling frequency.
\(L_i\)The test statistic — return \(i\) standardized by its own local volatility.
\(n\)Number of returns tested (per day, or per continuous grid) — the critical value is a function of this.

Section 03

The problem a plain test walks straight into: the intraday U-shape

Intraday volatility in FX and equities is not flat across the trading session — it follows a well-documented, structural U-shape: busiest right at the open and again into the close, quietest in the middle of the session. This is not specific to any one market or era; it shows up wherever intraday microstructure has been studied, and it is exactly the shape a plain Lee-Mykland local-vol window, if wide enough to span much of the day, will blend together rather than track.

The consequence runs in both directions at once. Near the open and close, a blended local-vol estimate is too low relative to what's actually typical there — so an entirely ordinary large open-bar move looks abnormally large against that too-low yardstick, and gets flagged as a false-positive jump. Mid-session, the same blended estimate is too high relative to what's actually typical there — so a genuine jump, which only needs to be large relative to the quiet midday baseline, can hide beneath an inflated yardstick and produce a false negative, missed entirely.

Notice what that readout is really showing: the standardized critical value (5.40, from Section 02) never changes — but the raw return size needed to clear it swings by roughly 4.5× across the session, purely because the local baseline it's being compared against swings by that much. A test that doesn't track this swing is, in effect, applying a wildly different practical bar for "jump" depending on the clock — without ever meaning to.

Section 04

The fix: Boudt-Croux-Laurent (2011) — deseasonalize first, then test

BCL's fix is conceptually simple, even though estimating it robustly takes some care: estimate how much bigger or smaller returns typically run at each time of day, relative to the session average, and divide every return by its own time-of-day's factor before handing it to the Lee-Mykland machinery above.

\[ \tilde r_i = \frac{r_i}{f_{\text{tod}(i)}} \]
f_tod(i)the periodicity factor for return i's time-of-day bucket — its typical size relative to the session average
r̃ᵢthe deseasonalized return — what feeds Section 02's L_i and σ̂ᵢ machinery instead of the raw return

The factor itself needs to be estimated robustly — a naive standard deviation per time bucket would itself be inflated by any jumps that happen to fall in that bucket, which is precisely the contamination problem Section 02 solved for the local-vol window, reappearing one level up. The BCL paper's own solution is a weighted standard deviation (WSD): a robust, outlier-downweighted dispersion estimate computed separately within each time-of-day bucket, across many historical days, then normalized so the factors average to 1 across the session (a factor of 1.8 means "1.8× the session-average typical size," a factor of 0.5 means half).

🗂️
Verified against this repo's actual code

jump_detect_lm.py implements both pieces — and got there by fixing two real bugs

volatilityExhaustion/jump_detect_lm.py is a working Lee-Mykland detector, and it is not plain Lee-Mykland only — it includes a Boudt-Croux-Laurent-style periodicity correction, applied by construction before the jump test runs. The specifics, read directly from the file:

  • local_sigma(r, k=K) implements Section 02's \(\hat\sigma_i\) exactly — bipower over the \(K\) returns strictly before \(i\), excluding \(r_i\).
  • lm_threshold(n, alpha) implements Section 02's \(C_n, S_n\) Gumbel critical value exactly, including the \(c=\sqrt{2/\pi}\) constant folded into the threshold rather than into \(\hat\sigma_i\) — matching the paper's own convention.
  • periodicity(r, tod, n_is) is the BCL piece: a per-30-minute-bucket factor (BUCKET=30, so 48 buckets/day), using a robust median absolute return per bucket (a simpler, same-spirit stand-in for the paper's WSD) — fitted only on the leading 60% of each instrument's history (IS_FRAC=0.60) and applied unchanged out-of-sample, so the correction itself never peeks at the data it's later used to judge.
  • Parameters actually used: STEP=5 minutes, K=270 (Lee-Mykland's own recommendation at 5-minute sampling), ALPHA=0.01 (a stated 1%-per-day false-positive rate).

Two bugs in the first draft were caught only by plotting the time-of-day profile of the detections, and both are worth knowing about because neither was visible in the aggregate numbers: (1) the local-vol window was originally rebuilt per day, which meant \(K=270\) couldn't fill until roughly 11 hours into a session and the detector was structurally blind to a London-open jump — fixed by running the window continuously across the whole instrument's history and mapping detections back to days afterward; (2) the periodicity correction was simply missing at first, and the file's own self-test quantifies the damage precisely: on synthetic pure-diffusion data with an injected 3× busy window, the raw detector flagged 1,020 false jumps; deseasonalized, 3.

It is genuinely used downstream, not a standalone script: per this project's own brick registry (LEGO_MODULES.md), jump_detect_lm.py is registered as a Tier-1 pure brick exposing lm_threshold, local_sigma, periodicity, and instrument_grid, consumed by jump_regime_book.py and jump_exhaustion.py. Those two modules run the descriptive questions the daily bipower ratio structurally couldn't answer — and the honest headline finding from that work is that jumps here describe volatility regime, not direction: detected jumps are close to day-to-day independent (unlike volatility itself, which clusters hard), carry no persistent directional skew, don't shift next-day continuation odds, and don't change how a fresh price extreme's exhaustion odds behave at a matched distance from the open. What jumps do carry is a genuine, replicated signal about how fast volatility decays afterward — the one channel the previous lesson's bipower work was also pointing toward. This is measurement, not a trading signal: no cost model, no backtest, no claim of edge anywhere in that work.

🧒 Explain like I'm 5

Imagine grading how loud a classroom is, but recess and nap time are both part of the same school day. If you compute one "typical loudness" number for the whole day, recess will never look loud (it's compared against a number padded by recess itself) and nap time will look suspiciously noisy if even one kid whispers (it's compared against that same padded number, which is way too high for nap time specifically). The fix is to grade each period against its OWN typical loudness — recess against typical recess noise, nap time against typical nap-time quiet — before asking "was this moment unusually loud." That's exactly what dividing each return by its own time-of-day's typical size does before the jump test ever runs.

Worked example

A toy 10-bar session: one false positive, one false negative, both fixed by BCL

Ten consecutive intraday bars, U-shaped baseline size (bp = basis points = 0.01%): typical moves of 18, 14, 9, 6, 4, 4, 6, 9, 14, 18 bp through the session (open → midday → close). Every bar's actual return equals its own baseline exactly (alternating sign), except two: bar 1 (the open) actually moves +55bp — a big open-bar move, but nowhere near unprecedented for an open — and bar 6 (deep in the quiet midday stretch) actually moves +25bp — the session's one genuine jump, planted exactly where ordinary moves are smallest.

baseline (bp)18149644691418
actual r (bp)+55−14+9−6+4+25−6+9−14+18

Session average baseline is 10.2bp, so bar 1's periodicity factor is \(18/10.2=1.7647\) and bar 6's is \(4/10.2=0.3922\). Applying Section 02's bipower \(\hat\sigma_i\) formula (window = the other 9 bars) to the raw returns gives the plain Lee-Mykland read; applying it to the returns after dividing each by its own periodicity factor gives the BCL-corrected read. For this 10-bar toy day (\(n=10\)), Section 02's Gumbel formula puts the critical value at 4.80 (\(\alpha=1\%\)):

plain: \(\hat\sigma_i\)plain: \(L_i\)BCL: \(\hat\sigma_i\)BCL: \(L_i\)verdict (threshold 4.80)
Bar 1 — open, +55bp10.52bp5.2315.51bp2.01plain falsely flags it · BCL correctly clears it
Bar 6 — midday, +25bp14.17bp1.7611.60bp5.50plain misses it entirely · BCL correctly flags it

Both statistics recompute directly from the definitions above with nothing hidden: plain \(\hat\sigma_1\) is the root-mean bipower product over the other 9 bars' raw returns (\(\sqrt{886/8}=10.52\)bp), so \(L_1=55/10.52=5.23\) — above the 4.80 threshold, a false positive, purely because the whole-day yardstick doesn't know the open is supposed to run hot. Once every return is divided by its own factor, the ordinary bars (2–5, 7–10) all normalize to exactly \(\pm10.2\)bp — the session average — because each one's actual return already equalled its own baseline. Only the two unusual bars stand out after normalizing: bar 1 becomes \(55/1.7647=31.17\)bp (still large, but no longer enormous once judged against a 10.2bp-normalized yardstick of \(\hat\sigma_1=15.51\)bp — \(L_1=31.17/15.51=2.01\), clearing the bar cleanly) and bar 6 becomes \(25/0.3922=63.75\)bp — genuinely enormous even after normalizing — against \(\hat\sigma_6=11.60\)bp, giving \(L_6=63.75/11.60=5.50\), correctly above threshold. The plain test got both bars backwards; the corrected test gets both right.

Section 07

Common pitfalls

⚠️
Where this test quietly goes wrong

Two limits worth keeping in view every time this test is used

The critical value doesn't transfer across sampling frequencies without recalibration. \(K\), \(n\), and the resulting critical value are all tied to a specific bar size. This repo's \(K=270\) is Lee-Mykland's own recommendation at 5-minute sampling, chosen partly because 1-minute FX returns carry enough microstructure noise (measured elsewhere in this repo at roughly 1.05× to 1.19× the 5-minute realized variance) that an L-statistic built on 1-minute bars mistakes noise for jumps. Swapping to 1-minute or 15-minute bars without recomputing \(K\), \(n\), and the Gumbel threshold for that new frequency will over- or under-flag jumps in a way that has nothing to do with whether the market actually jumped.

A statistically significant \(L_i\) says nothing about why. The test flags that a return was implausibly large relative to its local, deseasonalized baseline — full stop. It cannot distinguish a scheduled data release everyone was watching from a thin-liquidity flash move nobody was positioned for. This repo's own validation work (Section 04's callout) ties detected jumps to known calendar events only statistically — jump days run 1.15× to 1.31× more likely on Major-event days, and roughly a quarter to a third of a day's first detected jump lands within ±5 minutes of a release — which still leaves a large share of detected jumps with no calendar-event explanation at all. Attributing a specific flagged return to a specific cause requires external context the statistic itself does not, and cannot, provide.

This is the fourth and final lesson in Volatility Estimation & Jump Detection, and the four lessons build one continuous toolkit rather than four unrelated topics:

🎲

1. Model the possibility of jumps

Merton jump-diffusion (an earlier lesson, outside this category) bolts a Poisson-driven jump process onto ordinary geometric Brownian motion — the theoretical acknowledgment that price paths can genuinely tear, not just wiggle.

📏

2–3. Measure the aggregate contribution

Garman-Klass/Yang-Zhang and HAR-RV (Lessons 1–2) build better realized-volatility estimators from OHLC and intraday data; bipower variation (Lesson 3) then splits a day's realized variance into a continuous part and a jump part — how much of the total was jumpy, in aggregate.

🎯

4. Pin down individual events

This lesson: Lee-Mykland plus the Boudt-Croux-Laurent correction takes that aggregate share and localizes it — which specific return, at which specific moment, is the jump. Model the possibility, measure the total, then find the exact event: the whole arc in one line.

Key Takeaways

✓Lee-Mykland tests one return at a time, standardizing it by a local bipower volatility estimate that strictly excludes the return being tested — so a genuine jump can't inflate its own yardstick.
⚠The day's maximum \(|L_i|\) is Gumbel-distributed under the null, not normal — a flat "4-sigma" rule is a rough simplification of a real, sample-size-dependent critical value built from extreme-value theory.
✗A plain test, run against the intraday U-shape without adjustment, gets it wrong in both directions — false positives at the open/close, false negatives mid-session — because its local-vol window blends the whole day together.
✓Boudt-Croux-Laurent fixes this by deseasonalizing first: divide each return by its own time-of-day's typical size, then apply Lee-Mykland's machinery to the deseasonalized series.
✓This repo's own detector implements both pieces, honestly — a Tier-1 brick consumed by two downstream modules, with a self-test that shows the correction collapsing 1,020 diurnal false positives to 3.
✗Neither test explains WHY a flagged return jumped, and neither transfers across sampling frequencies without recalibrating K, n, and the critical value from scratch.
Section 10

Self-test

Q1. Bipower variation (previous lesson) and Lee-Mykland (this lesson) both concern jumps. What is the actual difference in what each one tells you?
Bipower variation produces a single number per day: what share of that day's total realized variance came from jumps in aggregate. It has no per-return resolution. Lee-Mykland is a per-return hypothesis test — it flags which specific return(s), at which specific time, are statistically implausible under continuous diffusion. One measures the total; the other localizes it.
Q2. Why does Lee-Mykland's local volatility estimate \(\hat\sigma_i\) deliberately exclude the return \(r_i\) being tested?
If a genuine jump occurred at \(i\) and its size were included in \(\hat\sigma_i\), the local volatility estimate would inflate itself right around the jump, making the very return that should stand out look "normal" relative to an artificially widened yardstick. Excluding \(r_i\) keeps the test statistic's denominator uncontaminated by the thing the numerator is being tested for.
Q3. Why does the day's maximum |L_i| follow a Gumbel distribution rather than a normal distribution, even though each individual L_i is approximately normal under the null?
The maximum of many independent (or weakly dependent) draws from a normal-like distribution does not converge to another normal distribution as the number of draws grows — by the Fisher–Tippett–Gnedenko extreme-value theorem, it converges to a Gumbel distribution, because normal tails decay fast enough that the maximum only grows slowly, on the order of \(\sqrt{\ln n}\). Testing a whole day's worth of returns for a jump means testing a maximum, not a single draw, so the correct reference distribution for the critical value is Gumbel, not normal.
Q4. What specific problem does the intraday U-shape create for a plain Lee-Mykland test, and in which direction does each type of error run?
A plain local-vol window that spans much of the day blends the U-shape away, producing one blended yardstick used everywhere. Near the open and close, actual local volatility is higher than that blended yardstick, so ordinary large moves there look abnormally large and get falsely flagged as jumps. Mid-session, actual local volatility is lower than the blended yardstick, so a genuine jump can be smaller than the (too-high) yardstick suggests is needed, and gets missed — a false negative.
Q5. In one sentence, what does the Boudt-Croux-Laurent correction actually do to the returns before Lee-Mykland's test runs?
It divides each return by a robustly-estimated, per-time-of-day periodicity factor (that time bucket's typical size relative to the session average) — deseasonalizing volatility first, so the Lee-Mykland machinery is then applied to returns that no longer carry the intraday U-shape's systematic swing.
Q6. This repo's jump_detect_lm.py flags a return as a jump with statistical confidence, on a day that also happens to carry a scheduled Major economic release. Does the statistic itself prove the release caused the jump?
No. The Lee-Mykland/BCL statistic only establishes that the return was implausibly large relative to its deseasonalized local baseline — it has no mechanism to attribute a cause. This repo's own validation shows only a statistical tendency (jump days run 1.15×–1.31× more likely on Major-event days, and roughly a quarter to a third of first jumps land within ±5 minutes of a release) — real, but far from universal, and confirming any single flagged return's actual cause requires external context the test itself cannot supply.
