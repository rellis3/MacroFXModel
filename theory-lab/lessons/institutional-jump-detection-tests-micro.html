Lee-Mykland & Boudt-Croux-Laurent, Finding the Exact Jump

Bipower variation, the previous lesson, told you what SHARE of a day's variance came from jumps — one number, no per-return resolution. This lesson builds the test that flags the exact return, and the correction that keeps it from being fooled by the ordinary rhythm of a trading day.

The whole idea
🎧 Listen · the four-minute version

A trader and a quant talk the lesson through. No symbols, just the idea and one worked number, so it works on a walk or a commute.

Bipower variation told me how much of today was jumps. Now I want to know which minute.

That's a different test. Suzanne Lee and Per Mykland built it in 2008. You take each return and divide it by how big returns have typically been just before it.

Including the return itself?

No, and that's the key. If a jump got into its own yardstick, it would make itself look normal. So the yardstick is built only from its neighbours, using the same paired-returns trick as bipower variation.

Then I flag anything past four standard deviations?

Not quite. You're testing every return in the day and asking whether the biggest one stands out. The biggest of many ordinary moves is naturally large. Its behaviour follows extreme-value theory, a Gumbel distribution, not the bell curve. So the bar rises with the number of returns you test.

How high?

At a one percent false-alarm rate, about four point eight for ten returns, and about five point four for a full day of five-minute bars.

Fine. What goes wrong in practice?

The clock. Volatility is U-shaped through the day: busy at the open and the close, quiet at midday. A yardstick that averages the whole day is too small at the open and too big at midday.

So the open gets flagged and midday gets missed.

Exactly. The lesson's toy session shows both. A fifty-five basis point open scores five point two three against the flat yardstick, a false alarm. A real twenty-five point jump at midday scores only one point seven six, missed.

And the fix?

Boudt, Croux and Laurent, 2011. First divide every return by its own time of day's typical size. Then run the same test. Now the open scores about two, cleared, and the midday jump scores five and a half, caught.

So a flag tells me it was news?

It tells you the move was implausibly big for that moment. It can't tell you why. And if you change bar size, you have to recalibrate the window and the threshold.

One line?

Judge each return against its own neighbourhood and its own time of day, with a bar that rises with how many returns you test.

Section 1 · How it reached trading

Timestamping the jump, not just the day

How it reached trading

Barndorff-Nielsen & Shephard's day-level test (2006) said a session had a jump, not when. Lee & Mykland (2008) tested each intraday return against local, jump-robust vol.

Lee (2012) used such tests to tie jumps to macro announcements; Boudt, Croux & Laurent (2011) fixed the intraday U-shape. Desks use them to tag events, clean vol inputs and calibrate jump models.

Section 2

A daily ratio can't say WHICH return jumped

📊

What bipower variation gives you

One number per day: what share of that day's total realized variance came from jumps in aggregate.

❓

What it structurally can't answer

How many jumps? How big was each one? In which direction? Did they cluster? A single daily ratio has already thrown that resolution away.

🎯

What this lesson adds

A per-return test: given a sequence of high-frequency returns, which SPECIFIC one is statistically implausible under ordinary continuous diffusion?

Lee & Mykland (2008) built the test. Boudt, Croux & Laurent (2011) fixed the one thing that made it unreliable on real, intraday-seasonal data. Both pieces matter — this deck covers both.
Section 3

Judge each return against its OWN neighborhood

Build a local volatility estimate from nearby returns — but never from the return being judged.

The local yardstick — σ̂ᵢ

Bipower variation over the K returns immediately before return i — deliberately EXCLUDING rᵢ itself. If a real jump's size leaked into its own yardstick, the yardstick would inflate around the jump and blind the test to the very thing it exists to catch.

The test statistic — Lᵢ = rᵢ / σ̂ᵢ

How big return i is, relative to what's been typical right around it. A large |Lᵢ| says "this return doesn't look like it came from the same process as its neighbors."

This is exactly how you'd judge a friend showing up 20 minutes late: alarming for someone who's never more than 2 minutes late, nothing for someone who routinely runs 30 minutes behind. The yardstick has to be LOCAL to mean anything.
Section 4

Why "past 4 sigma" isn't the real rule

The maximum of many is not one more normal draw

A day's test doesn't ask about one Lᵢ — it asks whether the MAXIMUM |Lᵢ| over every return tested that day clears a bar. The maximum of many approximately-normal ratios does NOT converge to another normal distribution as the count grows: it converges to a Gumbel (extreme-value) distribution, because normal tails decay so fast that the maximum only grows slowly, like √(ln n). The correct critical value has to come from that theory — sample-size-dependent constants Cₙ and Sₙ — not from a flat "4 sigma."

One coin flip landing heads isn't surprising. A thousand people each flipping a coin, and SOMEONE getting ten heads in a row — also not surprising, with a thousand tries. More chances raises the bar for what counts as "surprising." Testing every return in a day for a jump is exactly this: the bar has to rise with the number of returns tested, and Cₙ/Sₙ are precisely that rising bar.
Roughly, for α = 1%

n=10 → critical value ≈ 4.80 · n=78 → ≈ 5.10 · n=96 → ≈ 5.14 · n=288 (a full 5-min session) → ≈ 5.40. The "~4-sigma" heuristic is a coincidence of common sample sizes, not the actual rule.

Section 7

BCL's fix: deseasonalize, then test

📐

Estimate a periodicity factor

Per time-of-day bucket, a robust dispersion estimate (the paper uses a weighted standard deviation, WSD) — normalized so factors average to 1 across the session. 1.8 means "1.8× the session-average typical size."

➗

Divide every return by its own bucket's factor

r̃ᵢ = rᵢ / f₍tod(i)₎ — the deseasonalized return. Ordinary time-of-day swings are divided out BEFORE the jump test ever runs.

🔁

Run Lee-Mykland on r̃, not r

Same σ̂ᵢ formula, same Gumbel threshold — just applied to a series that no longer carries the intraday U-shape's systematic swing.

Grading classroom noise across recess AND nap time with one "typical loudness" number makes recess never look loud and nap time look suspiciously noisy at a single whisper. Grade each period against its OWN typical loudness first — exactly what dividing by a time-of-day factor does here.
Section 8

Section 9

Verified against this repo's actual code

jump_detect_lm.py implements BOTH pieces — a rare exception in this curriculum

volatilityExhaustion/jump_detect_lm.py is not plain Lee-Mykland only. local_sigma(r, K) matches Section 3's σ̂ᵢ exactly (K=270 for 5-min bars); lm_threshold(n, alpha) matches Section 4's Gumbel critical value exactly (α=1%); periodicity(r, tod, n_is) is the BCL piece — a robust per-30-minute-bucket factor, fitted on the leading 60% of history only and applied unchanged out-of-sample. Its own self-test: on synthetic pure diffusion with an injected 3× busy window, the RAW detector flags 1,020 false jumps; deseasonalized, 3.

It's registered as a Tier-1 brick, consumed by two downstream modules (jump_regime_book.py, jump_exhaustion.py). The honest finding from that work: detected jumps describe volatility REGIME, not direction — near-independent day to day (unlike volatility, which clusters hard), no persistent directional skew, no shift in next-day continuation odds. What they DO carry: a genuine signal that jump-driven volatility decays faster afterward. Measurement only — no trade, no cost, no signal claimed anywhere in that work.

Section 10

Two limits worth keeping in view

Frequency mismatch
  • K, n, and the critical value are all tied to a specific bar size
  • This repo's K=270 is calibrated for 5-min bars specifically
  • Swap to 1-min or 15-min bars without recalibrating and the test over- or under-flags for reasons that have nothing to do with real jumps
A flagged return proves nothing about WHY
  • The statistic says "implausibly large relative to its local baseline" — full stop
  • It can't distinguish a scheduled release from a thin-liquidity flash move
  • This repo's own calendar check: only 1.15–1.31× more likely on Major-event days, ~24–34% of first jumps near a release — real, but leaves most flags unexplained by that check alone

Section 12

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

Why does Lee-Mykland's local volatility estimate σ̂ᵢ exclude the return rᵢ being tested?

If a jump's size leaked into its own local-vol estimate, the yardstick would widen right around the jump, making the jump look "normal" relative to an artificially inflated denominator.
Question 2

Why is the day's maximum |Lᵢ| Gumbel-distributed under the null, not normal?

By the Fisher–Tippett–Gnedenko theorem, the maximum of many normal-like draws grows only slowly (~√(ln n)) and converges to a Gumbel distribution — the correct reference for a "test the max over the whole day" statistic.
Question 3

A plain (non-deseasonalized) Lee-Mykland test tends to do what, specifically, at the market open?

A blended, whole-session local-vol yardstick under-estimates the true (higher) local vol at the open, so an ordinary open-bar move looks abnormally large against that too-low yardstick.
Question 4

What does the Boudt-Croux-Laurent correction actually do to a return before the jump test runs?

Each return is divided by its own time bucket's typical size relative to the session average — deseasonalizing volatility before the Lee-Mykland statistic is ever computed.
Question 5

This repo's detector flags a return as a jump on a day that also carries a scheduled Major release. Does the statistic itself prove the release caused it?

The repo's own check shows only a statistical tendency (1.15–1.31× more likely on event days, ~24–34% of first jumps near a release) — real, but leaving most flags without a calendar-event explanation. Attribution needs external context the statistic can't supply.
Your call
Scenario drill · an illustrative busy open

Your jump detector fires at the open, again

You clean jumps out of your realized-volatility input before forecasting. Your detector runs plain Lee-Mykland on 5-minute bars with a full-session critical value of 5.40 and a yardstick that averages the whole session at about 10.2 bp. This morning it flagged a 60 bp move in the opening bar (L = 5.88), as it does most mornings. The open's typical move is 18 bp. What do you do?

  1. Trust the flag: strip the bar from the volatility input as a jump.
    The flag comes from the clock, not from a jump. Against the open's own typical 18 bp the move is about 3.3, nowhere near 5.40. Stripping ordinary open bars every morning removes real volatility and biases your forecast low.
  2. Add the time-of-day correction: divide each return by its bucket's typical size before testing, then re-run.
    This is the Boudt-Croux-Laurent fix. The open bar scores 60 ÷ 18 ≈ 3.33 and is cleared, while quiet-period moves get judged against their own small baseline. It fixes the false alarms at the open and the misses at midday at the same time.
  3. Raise the critical value to 6 for the whole day.
    It stops this one false alarm, but it makes the midday problem worse: a real midday jump already needs about 55 bp to clear the plain test, and now it needs more. You have traded false positives for more false negatives instead of fixing the yardstick.
  4. Switch to 1-minute bars for finer resolution and keep the same settings.
    The window, the number of tests and the critical value all belong to one bar size. On 1-minute bars microstructure noise adds false jumps, and the old threshold no longer has the false-alarm rate you chose.

What the method says. This morning is illustrative, using the numbers from the lesson's own calculator (60 bp at the open, plain L 5.88 against 5.40, corrected L 3.33). The lesson's point is that a plain test run against the intraday U-shape errs both ways, and the cure is to deseasonalise before testing, not to move the threshold.

Section 13

What to carry forward

01

Lee-Mykland tests one return at a time: Lᵢ = rᵢ/σ̂ᵢ, where σ̂ᵢ is a local bipower volatility estimate that strictly excludes rᵢ itself.

02

The day's maximum |Lᵢ| is Gumbel-distributed under the null, not normal — the critical value is sample-size-dependent, not a flat "4 sigma."

03

A plain test, run against the intraday U-shape unadjusted, over-flags the open/close and under-flags midday — in both directions, from one blended yardstick.

04

Boudt-Croux-Laurent fixes this by dividing each return by its own time-of-day's typical size BEFORE the jump test runs.

05

This repo's own detector implements both pieces honestly, and is consumed by two downstream measurement modules — a rare exception to "concept only" in this curriculum.

06

Neither test explains WHY a flagged return jumped, and neither transfers across sampling frequencies without recalibrating from scratch.

07

On a desk: Lee & Mykland (2008) timestamp jumps, so they can be tied to announcements, cleaned out of vol inputs and counted for jump models.

What this now lets you do
