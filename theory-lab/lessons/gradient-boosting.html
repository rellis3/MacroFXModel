Gradient Boosting

Instead of averaging many independent trees, build them one at a time, each one trained specifically to correct what the ensemble so far still gets wrong — the dominant technique on structured, tabular data, and a method whose strength is not, by itself, evidence about any specific FX or macro feature set.

CONCEPT — explained here, not built or tested anywhere in this repo ~17 min read Prereqs: Decision Trees & Random Forests
TL;DR
  • Random forests average many independent trees trained in parallel (bagging). Gradient boosting instead builds trees sequentially: each new tree is fit specifically to correct the current ensemble's errors.
  • The general update is \(F_m(x) = F_{m-1}(x) + \nu\cdot h_m(x)\), where \(h_m\) is a new tree fit to approximate the negative gradient of the loss with respect to the ensemble's current predictions, and \(\nu\) (shrinkage) controls how much each new tree is allowed to contribute (Friedman, 2001).
  • For squared-error loss, the negative gradient is literally the residual, \(y_i - F_{m-1}(x_i)\) — stated explicitly, this is the intuitive special case: each new tree is quite literally fit to what's still left over.
  • Production implementations — XGBoost (Chen & Guestrin, 2016), LightGBM, CatBoost — add regularization terms that penalize tree complexity directly in the objective, efficient handling of missing values, and histogram-based split-finding for speed, without changing the core sequential-correction idea.
  • Mandatory honest framing: gradient-boosted trees are genuinely, consistently the strongest general-purpose method on structured/tabular prediction problems — that is a statement about the method. It says nothing about whether any specific set of FX or macro features handed to it contains real, out-of-sample-validated trading edge, and a model this flexible makes leakage-free, honest out-of-sample testing more important, not less, because it can fit noise very convincingly.
Section 01

Why this matters

Decision Trees & Random Forests closed on a specific limitation: averaging \(B\) trees' predictions converges to a variance floor of \(\rho\sigma^2\), set by how correlated the trees are — a purely parallel, "grow many independent guesses and vote" strategy. Gradient boosting takes the opposite structural approach. Rather than making each tree as independent from the others as possible, it makes each tree deliberately dependent on all the ones before it: tree 2 is built to fix what tree 1 got wrong, tree 3 fixes what trees 1 and 2 together still get wrong, and so on. Where a forest reduces variance by averaging away independent noise, boosting reduces both bias and variance by directly, iteratively chasing down the ensemble's remaining error — a different mechanism aimed at the same underlying goal of a model that predicts well on data it hasn't seen.

This sequential-correction idea is also why gradient boosting is the dominant technique on structured/tabular data across real-world machine learning competitions and production systems — a genuinely well-evidenced claim about the method, developed at length in the mandatory honest framing box below, and one this lesson is careful never to let bleed into a claim about any particular trading application of it.

💡
Plain-English intuition

A committee of specialists, each hired to fix the last one's mistakes

Picture estimating a house's price. The first, crude estimator just guesses the average price of every house in the dataset — wrong for almost every individual house, but a reasonable starting point. The second estimator doesn't try to predict the price from scratch; it only looks at how wrong the first guess was for each house — too low here, too high there — and tries to predict that error. Add the second estimator's correction to the first guess and the combined estimate is better. The third estimator repeats the trick: it looks only at whatever error is still left after the first two, and tries to predict that. Keep hiring new specialists, each one focused purely on the leftover mistake of everyone hired before them, and the combined committee's estimate keeps improving — not because any single specialist is a great forecaster on their own, but because each one is solving a narrower, easier problem: "what did everyone before me still get wrong?"

That is gradient boosting exactly: each new tree isn't trained on the original target \(y\) at all — it's trained on the current ensemble's leftover error, and its correction is added to the running total, a little at a time, controlled by a shrinkage rate so no single new tree is allowed to overcorrect and swing the whole committee's estimate too far in one step.

Section 02

The math, step by step

The general algorithm (Friedman, 2001). Gradient boosting builds an additive model \(F_M(x) = \sum_{m=0}^{M} \nu\, h_m(x)\) (with \(h_0\) initialized to a constant) by fitting each new piece \(h_m\) sequentially, in the direction that most reduces a chosen loss function \(L(y, F(x))\):

1

Initialize with a constant

\[ F_0(x) = \arg\min_{\gamma} \sum_{i=1}^{N} L(y_i, \gamma) \]

For squared-error loss this is simply the training mean, \(\bar{y}\) — the same crude "average guess" starting point from the intuition box.

2

Compute the pseudo-residuals

\[ r_{im} = -\left[\frac{\partial L(y_i, F(x_i))}{\partial F(x_i)}\right]_{F=F_{m-1}} \]

For every training point, this is the negative gradient of the loss with respect to the ensemble's current prediction — the direction, per point, that would most reduce that point's loss if the prediction nudged that way.

3

Fit a new tree to those pseudo-residuals

Train a fresh regression tree \(h_m(x)\) — using exactly the recursive binary splitting from the previous lesson — with the pseudo-residuals \(r_{im}\) as its regression target, not the original \(y_i\).

4

Add the new tree's correction, shrunk by ν

\[ F_m(x) = F_{m-1}(x) + \nu \cdot h_m(x) \]

Repeat steps 2–4 for \(m=1,\dots,M\) rounds. The final model is \(F_M(x)\).

🧒 Explain like I'm 5

Gradient boosting is like a team of tutors working on the same struggling student, one after another. The first tutor takes a rough first pass. The second tutor doesn't start over — they only look at whatever the first tutor's student is still getting wrong, and focus entirely on fixing that. The third tutor only looks at whatever's still wrong after tutors one and two. Each tutor's job gets narrower and more specific, but the student keeps improving with every tutor added, because nobody is wasting effort re-teaching what's already been fixed.

The squared-error special case, made explicit. Take \(L(y,F) = \frac{1}{2}(y-F)^2\). Its derivative with respect to \(F\) is \(\partial L/\partial F = -(y-F) = F - y\), so the negative gradient is:

\[ r_{im} = -\Big[F_{m-1}(x_i) - y_i\Big] = y_i - F_{m-1}(x_i) \]
r_imthe pseudo-residual this round — for squared-error loss, literally the ordinary residual
y_ithe true target for training point i
F_{m-1}(x_i)the ensemble's current prediction for point i, before this round's tree

In other words: for the most common loss function, "fit a tree to the negative gradient" reduces exactly to "fit a tree to the ordinary residual" — the intuitive committee-of-specialists story from above, made precise. The general gradient formulation exists because the same machinery extends cleanly to other losses (log-loss for classification, Huber loss for robustness to outliers, quantile loss for predicting a specific percentile) — each just swaps in a different derivative for step 2, with steps 1, 3, and 4 completely unchanged.

🧒 Explain like I'm 5

A "residual" is just what's left over — the part of the answer still wrong after your best guess so far. If you guess a house is worth $300,000 and it's really worth $340,000, your residual is $40,000: the exact gap the next tutor should focus on closing. Fitting a tree to the residual literally means training it to predict that gap, not the original house price all over again.

Why the shrinkage rate \(\nu\) matters. Setting \(\nu=1\) would let each new tree fully correct the current residual in one step — fast, but prone to fitting each round's tree too eagerly to that round's specific noise. A small \(\nu\) (commonly 0.01–0.3) forces many more rounds \(M\) to reach the same overall fit, but each individual step is more conservative, which empirically produces better-generalizing models — the direct boosting analogue of the previous lesson's "many trees, none of them trusted too much on their own" theme, achieved here through small sequential steps rather than through averaging.

🧒 Explain like I'm 5

Shrinkage is like taking small, careful corrective steps instead of one huge overcorrection. If a recipe tastes slightly bland, you add a pinch of salt, taste again, then decide on the next pinch — rather than dumping in a whole spoonful based on one taste test. Each small correction is safer because it doesn't overreact to that one moment's specific impression; many small pinches, tasted and adjusted along the way, get you to a better final dish than one big confident guess.

\(F_m(x)\)The ensemble's prediction after \(m\) boosting rounds.
\(h_m(x)\)The new tree fit during round \(m\), trained on the current pseudo-residuals.
\(r_{im}\)The pseudo-residual for point \(i\) at round \(m\) — the negative gradient of the loss.
\(\nu\)(nu) The shrinkage / learning rate — how much of each round's correction is actually applied.
\(L(y,F)\)The loss function being minimized — squared error, log-loss, etc.
\(M\)Total number of boosting rounds (trees) in the final ensemble.
Bagging (parallel, independent) versus boosting (sequential, corrective)
Bagging's three trees never see each other's output — they're trained in parallel on independent resamples and combined only at the end. Boosting's trees form a strict chain: tree 2 cannot be trained until tree 1's residual exists, because tree 2's entire training target is that residual.

Worked example

One full boosting round, by hand, on 5 points

Five training points with targets \(y = [3, 5, 6, 9, 12]\) at \(x=1,2,3,4,5\), squared-error loss, shrinkage \(\nu = 0.5\).

1

Initialize F₀ as the mean

\[ F_0 = \bar{y} = \frac{3+5+6+9+12}{5} = 7 \]
2

Compute round-1 pseudo-residuals (= y − F₀, for squared error)

x1    2    3    4    5
y3    5    6    9    12
r₀ = y − F₀−4   −2   −1   +2   +5
3

Fit a depth-1 tree h₁ to the pseudo-residuals

The best single split for these residuals is \(x \le 3\) versus \(x>3\): left leaf mean \(=\frac{-4-2-1}{3}=-2.333\), right leaf mean \(=\frac{2+5}{2}=3.5\).

\[ h_1(x) = \begin{cases} -2.333 & x\le 3 \\ 3.5 & x>3 \end{cases} \]
4

Update: F₁(x) = F₀ + ν·h₁(x), with ν = 0.5

\[ F_1(x\le3) = 7 + 0.5(-2.333) = 5.833, \qquad F_1(x>3) = 7 + 0.5(3.5) = 8.75 \]

New residuals after this one round, \(r_1 = y - F_1\):

x1     2     3     4     5
F₁5.833  5.833  5.833  8.75  8.75
r₁ = y − F₁−2.833  −0.833  +0.167  +0.25  +3.25

Sum of absolute residuals went from \(|{-4}|+|{-2}|+|{-1}|+|2|+|5| = 14\) before this round to \(2.833+0.833+0.167+0.25+3.25 = 7.333\) after just one round — roughly halved. A second round would fit a new tree \(h_2\) to these residuals \(r_1\) and shrink the leftover error further, exactly the same four steps repeated, continuing to chip away at whatever's still unexplained.

Gradient-boosted trees are the dominant, most consistently-winning technique on structured/tabular data across real-world machine learning competitions and production systems — that is genuinely well-evidenced as a statement about the method. It says nothing, on its own, about whether any specific set of features fed into it in an FX or macro context would produce real, out-of-sample-validated trading edge. A method's general strength across thousands of unrelated tabular problems does not transfer as a claim about any one specific feature set's predictive power in one specific market — that is a completely separate question, answered only by honest out-of-sample testing on that exact feature set, with realistic costs. Because gradient boosting is flexible enough to fit noise very convincingly, rigorous, leakage-free out-of-sample validation (see The Research Pipeline: Hypothesis to Honest Backtest) becomes more important with a model this powerful, not less.

Being told "this is the best-selling, most versatile kitchen knife in the world" tells you the knife is genuinely great — but it tells you nothing about whether it's the right tool for the specific recipe you're making tonight. Gradient boosting being the best general-purpose method for tabular data is the "great knife" claim. Section 03

How practitioners actually use this

Almost nobody implements the raw Friedman (2001) algorithm from scratch today; three production libraries dominate real-world use, all built on the same sequential-correction core above, with different practical additions:

🌲

XGBoost

Chen & Guestrin (2016). Adds an explicit regularization term to the objective that penalizes tree complexity directly (number of leaves, leaf weight magnitudes) — a genuine complexity penalty built into training itself, alongside shrinkage. Also popularized efficient handling of missing values (learning a default split direction for them automatically) and approximate, histogram-based split-finding for speed on large datasets.

🍃

LightGBM

Grows trees leaf-wise (expanding whichever leaf reduces loss most) rather than level-wise, and uses histogram-based split-finding aggressively for speed on very large or high-dimensional datasets — often noticeably faster to train than XGBoost with comparable accuracy, at the cost of leaf-wise growth being slightly more prone to overfitting on small datasets without careful depth control.

🐱

CatBoost

Built around native, statistically careful handling of categorical features (avoiding the target leakage that naive target-encoding of categoricals can introduce), and an ordering scheme intended to reduce a specific form of bias from re-using the same data across boosting rounds.

All three sit on top of the identical two ideas from this lesson — a score-function-style corrective step (fit to the loss's negative gradient) and a shrinkage rate — without changing that core mechanism. The practical additions above are about training efficiently and handling messy real-world tabular data well, not about a different underlying algorithm.

⚠️
Common pitfalls

Where gradient boosting quietly goes wrong

Too many rounds with too little shrinkage overfits, just like an unconstrained single tree. Because each round strictly reduces training loss, boosting for enough rounds \(M\) with a large enough \(\nu\) can drive training error toward zero exactly the same way a single unconstrained tree can — early stopping on a genuine validation set (not the training loss curve) is standard practice, not optional.

A powerful method fitting noise looks identical to it fitting signal, from the training curve alone. This is the direct practical consequence of the mandatory honest framing above: a falling training loss, or even a falling loss on a validation split that leaked information from the training period (a look-ahead feature, a target-encoded categorical fit on the full dataset before splitting), will look exactly like real generalization until it's tested on data genuinely held out in time.

Feature importance from a boosted ensemble inherits the same MDI-vs-permutation caveat as forests. A gradient-boosted ensemble's built-in importance scores are computed the same way as a forest's (gain per split, summed across trees) and carry the identical bias toward high-cardinality/continuous features discussed in the previous lesson — the fix (prefer permutation importance, or a proper held-out validation check) is unchanged.

Key Takeaways

✓Boosting builds trees sequentially, each one correcting the ensemble's current error — the structural opposite of a forest's independent, parallel trees.
✓\(F_m(x) = F_{m-1}(x) + \nu\cdot h_m(x)\), where \(h_m\) is fit to the negative gradient of the loss. For squared error, that negative gradient is literally the residual — the intuitive special case.
✓The shrinkage rate \(\nu\) trades more boosting rounds for a more conservative, better-generalizing step each round. \(\nu=1\) lets a single tree overcorrect to that round's specific noise.
•XGBoost, LightGBM, and CatBoost are the real, dominant production implementations — regularization, histogram-based splitting, and careful categorical handling on top of the same sequential-correction core, not a different algorithm.
✗Being the strongest general-purpose method on tabular data is not evidence any specific FX/macro feature set fed into it has real edge. Those are two entirely different claims — state which one is meant, every time this method is proposed for a real strategy.
⚠This exact flexibility is what makes leakage-free, honest out-of-sample validation more important, not less. A model this powerful fits noise very convincingly — a falling training or leaked-validation loss looks identical to real generalization until tested on genuinely held-out data.
Section 05

Self-test

Q1. What is the core structural difference between how a random forest and a gradient-boosted ensemble are trained?
A random forest trains \(B\) trees independently and in parallel, each on its own bootstrap resample, and combines them only at the end by averaging (or majority vote) — no tree depends on any other. Gradient boosting trains trees strictly sequentially: each new tree \(h_m\) is fit to the current ensemble's pseudo-residuals, which only exist once every previous tree has already been trained and added in, so each tree is deliberately dependent on all the ones before it.
Q2. In the update \(F_m(x) = F_{m-1}(x) + \nu \cdot h_m(x)\), what is \(h_m\) actually fit to, in general, and what does it reduce to for squared-error loss?
In general, \(h_m\) is a new regression tree fit to the negative gradient of the loss function with respect to the ensemble's current predictions, \(r_{im} = -[\partial L(y_i,F(x_i))/\partial F(x_i)]_{F=F_{m-1}}\). For squared-error loss, \(L=\frac{1}{2}(y-F)^2\), this negative gradient works out to exactly \(y_i - F_{m-1}(x_i)\) — the ordinary residual — so \(h_m\) is literally fit to what's left over after the ensemble so far.
Q3. What does the shrinkage rate ν control, and what happens if it's set to 1?
\(\nu\) controls how much of each new tree's correction is actually applied to the running ensemble each round — a small \(\nu\) (commonly 0.01–0.3) means many more rounds are needed to reach the same overall fit, but each individual step is more conservative. Setting \(\nu=1\) lets each new tree fully apply its correction in one step, which tends to let that tree overfit to that specific round's residual noise rather than capturing a pattern that generalizes.
Q4. Name one specific practical addition each of XGBoost, LightGBM, and CatBoost bring on top of the core Friedman (2001) algorithm.
XGBoost adds an explicit regularization term penalizing tree complexity directly in the training objective, plus efficient built-in missing-value handling. LightGBM grows trees leaf-wise instead of level-wise and leans heavily on histogram-based split-finding for training speed on large datasets. CatBoost focuses on statistically careful native handling of categorical features, avoiding the target leakage that naive target-encoding can introduce. All three keep the same sequential negative-gradient-fitting core unchanged.
Q5. A gradient-boosted model achieves an excellent, steadily falling loss on a validation split built from FX/macro features. Why is this not, by itself, evidence of real trading edge?
Gradient boosting is powerful and flexible enough to fit noise very convincingly, and a validation split that leaked any information from the training period — a look-ahead feature, target-encoding fit before the split, or any other leakage — will produce a falling validation loss that looks identical to genuine generalization. The method's general strength across tabular problems everywhere is a statement about the method; whether this specific feature set on this specific market has real, persistent predictive power is a separate question, answered only by leakage-free out-of-sample testing with realistic costs on data genuinely held out in time.

Further reading
  • Jerome H. Friedman, "Greedy Function Approximation: A Gradient Boosting Machine", Annals of Statistics, 29(5), 2001 — the foundational gradient boosting paper: the general algorithm, the negative-gradient/pseudo-residual framing, and shrinkage.
  • Tianqi Chen and Carlos Guestrin, "XGBoost: A Scalable Tree Boosting System", Proceedings of the 22nd ACM SIGKDD International Conference on Knowledge Discovery and Data Mining (KDD), 2016 — the XGBoost paper: regularized objective, missing-value handling, and system-level speed optimizations.
  • Guolin Ke, Qi Meng, Thomas Finley, et al., "LightGBM: A Highly Efficient Gradient Boosting Decision Tree", NeurIPS, 2017 — the LightGBM paper: leaf-wise growth and histogram-based split-finding.
  • Liudmila Prokhorenkova, Gleb Gusev, Aleksandr Vorobev, Anna Veronika Dorogush, and Andrey Gulin, "CatBoost: Unbiased Boosting with Categorical Features", NeurIPS, 2018 — the CatBoost paper: ordered boosting and native categorical feature handling.
  • Trevor Hastie, Robert Tibshirani, and Jerome Friedman, The Elements of Statistical Learning (2nd ed.), Springer, 2009 — Chapter 10 covers boosting and gradient boosting machines with the same notation used in this lesson.
