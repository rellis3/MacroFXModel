Decision Trees & Random Forests, One Model's Overfitting, Averaged Away

A single decision tree, grown all the way down, can carve out a private leaf for every training example and reproduce the training set almost perfectly — which is the problem, not the achievement. This is the first lesson in a new category of the curriculum, and it opens on that exact tension: a tree by itself has low bias and dangerously high variance, and the fix isn't a smarter tree — it's growing many different ones and averaging their votes.

Section 1

Twenty questions, asked by an algorithm

A decision tree is built by repeatedly asking the single most useful yes/no question about the data it still has left.

?

One yes/no question per node

At every node, the tree searches every feature and every candidate threshold — "is x₁ above 5?" — and picks whichever split most reduces how mixed the remaining targets still are.

↳

Recurse on each branch

Whatever split wins gets applied, splitting the data into a "yes" group and a "no" group — then the exact same search runs again, independently, inside each of those two groups.

🍃

A leaf is the final answer

Once a stopping rule fires — a maximum depth, a minimum group size, or no split left that helps enough — a node stops splitting and predicts the average target of whichever training points landed there.

⚡

Nothing is decided in advance

Unlike a straight-line regression, a tree commits to no fixed shape ahead of time — it decides which feature matters, and exactly where to draw each line, entirely from the data itself.

If "tree" already sounds familiar from earlier in this curriculum: hierarchical risk parity built a tree too, but bottom-up and for a completely different job — clustering similar assets together by correlation distance into a dendrogram, then using it to allocate portfolio weight. A decision tree grows top-down instead, splitting rows of data by a feature's value to predict a target. Same branching shape, unrelated purpose.

Section 3

A tree with no limits doesn't stop asking

The same splitting rule, run with a stopping point versus run without one.

A shallow, restrained tree
  • Stops after a handful of genuinely general questions
  • Each leaf still holds a healthy group of training examples that broadly agree
  • Regrow it on a slightly different sample of the same data — you get roughly the same tree
  • Low variance, at the cost of some bias
An unconstrained, deep tree
  • Keeps splitting until every leaf holds a single training point
  • Training error goes essentially to zero
  • Regrow it on a slightly different sample — the specific splits can look completely different
  • Very low bias, but very high variance
Zero training error from an unconstrained tree is a red flag, not an achievement. At that point the tree has stopped describing a general relationship between features and target and has instead built an elaborate, question-by-question lookup table that reproduces the training set exactly — noise included — and has no principled reason to answer correctly on anything it hasn't already memorized.
The core tension

Low bias and low variance rarely come free together. An unconstrained tree buys almost-zero bias by paying for enormous variance — the true relationship between features and target hasn't moved at all, but the specific splits a deep tree draws depend heavily on exactly which training points it happened to see, noise included.

Section 5

Fix #1 — bagging: many trees, many resamples

Bootstrap aggregating ("bagging"): train each tree on its own resample of the training rows, drawn with replacement.

Each resample has the same size as the original (8 rows), drawn with replacement — some rows appear two or three times, others not at all. Each tree only ever trains on its own resample, so each one's overfit quirks — driven by which specific noisy points it happened to oversee — differ from tree to tree.
As the number of rows grows large, a given row's chance of being left out of one bootstrap draw converges to (1 − 1/N)ᴺ → e⁻¹ ≈ 36.8%. Those left-out rows are that tree's "out-of-bag" set — never used to train it, and useful later as a free validation check.

Averaging \(B\) independent, equally-good estimators, each with variance σ², produces an average with variance σ²/B — variance falls straight toward zero as B grows, while bias barely moves, since averaging equally-biased predictors doesn't shift the expectation. That's the entire case for bagging in one sentence: many high-variance, low-bias trees, averaged, keep the low bias and lose most of the variance.

Section 6

The catch: bootstrap-trained trees aren't independent

They all still come from the exact same underlying dataset.

The honest formula

The variance of an average of B estimators, each with variance σ² and average pairwise correlation ρ, is ρσ² + (1 − ρ)σ²/B. As B → ∞ the second term vanishes — but the first term does not. The forest's variance converges to ρσ², a floor set entirely by how correlated the trees are with each other, not by how many of them exist.

If ten people all read the exact same newspaper, averaging their opinions doesn't give you ten independent opinions — they're repeating what one source told them, so the "average" is barely more reliable than asking one of them. Ten people who each got their information from a genuinely different source is where averaging actually starts to pay off. Bootstrap resamples of the same dataset are closer to the newspaper-readers than the fully independent sources — which is exactly why bagging alone leaves a variance floor on the table.

This is the setup for the next section: if the floor ρσ² is the real limit, the only way to genuinely improve a forest past what bagging alone offers is to actively push ρ — the correlation between trees — down.

Section 8

Fix #2 — random forest's extra trick

Bagging resamples the rows. A random forest also resamples the features — separately, at every single split.

Bagging alone
  • Every tree searches all p features at every split
  • Whichever feature is strongest tends to get picked near the root of nearly every tree, resample or not
  • Trees end up making very similar early splits — correlated trees, even after bootstrapping the rows
  • The correlation floor ρσ² stays high
Random forest (bagging + feature subsets)
  • At each split, only a random subset of m features (out of p) is even considered
  • The single strongest feature isn't always in the running — different trees get forced down different early paths
  • Trees genuinely decorrelate from each other, not just from resampled rows
  • Lowering ρ lowers the actual floor, not just the part more trees can shrink
Where this needs a number

Breiman's original defaults are m ≈ √p candidate features per split for classification, m ≈ p/3 for regression — a deliberately small fraction of the total, chosen specifically to force the trees apart rather than to search as thoroughly as possible at any one split.

Section 10

What a trained forest hands you for free

📊

Feature importance

Because the forest already tracks every split every tree made, it can report which features it leaned on most — either cheaply (mean decrease in impurity) or more reliably (permutation importance, which shuffles a feature and measures how much error rises).

✅

Out-of-bag error

Each tree already left ~37% of rows unseen. Averaging each row's prediction only over the trees that never trained on it gives an honest validation estimate — with no separate held-out split needed.

🧭

A sane first model

Forests have few hyperparameters that meaningfully change the result — mainly B, the feature-subset size m, and each tree's depth — making them a common first "sanity check" before reaching for gradient boosting, next in this series.

Verified against this repo's actual code

The full lesson this deck condenses labels decision trees and random forests a "concept — explained here, not built or tested anywhere in this repo." A repo-wide search confirms that's still accurate: no RandomForestClassifier/Regressor and no plain DecisionTreeClassifier/Regressor exist anywhere in this codebase. Section 11

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

What does a decision tree's split search try to maximize at each node?

Every feature and every candidate threshold is tried; the split chosen is whichever one most reduces how mixed the remaining targets still are.
Question 2

Why does an unconstrained, fully-grown decision tree tend to overfit badly?

With no stopping rule, recursion continues until training error is essentially zero — very low bias, but very high variance, since the exact splits depend heavily on which specific noisy points the tree happened to see.
Question 3

What does "bagging" actually resample to build each tree?

Each tree trains on its own N-row resample drawn with replacement from the original N rows — some rows repeat, others are left out entirely (that tree's out-of-bag set).
Question 4

What does a random forest add on top of plain bagging?

Restricting each split's search to a random feature subset stops one dominant feature from producing similar splits — and therefore correlated trees — across the whole forest.
Question 5

Does growing the number of trees B toward infinity drive a forest's variance all the way to zero?

Var(ensemble) = ρσ² + (1 − ρ)σ²/B. As B → ∞ the second term vanishes, but ρσ² does not depend on B at all — lowering ρ (via feature subsampling) is what lowers the floor itself.
Section 12

What to carry forward

01

A decision tree recursively splits data on the feature and threshold that most reduces impurity, building yes/no questions down to leaf nodes that predict a mean.

02

Grown without limit, a single tree drives training error toward zero by memorizing individual training points — very low bias, very high variance.

03

Bagging trains many trees on independent bootstrap resamples and averages their predictions, canceling out each tree's own overfit noise.

04

Random forests add one more twist: only a random subset of features is considered at each split, decorrelating the trees further than bagging alone manages.

05

Averaging B correlated trees never reaches zero variance — it converges to a floor of ρσ², set by tree correlation, not by tree count.

06

Feature importance and out-of-bag error come essentially free from the bagging design — but neither one, by itself, is evidence of real trading edge.

What this now lets you do

Recognize when a single model's variance — not its bias — is the actual problem, and reach for averaging many decorrelated models rather than a fancier feature set. Read a forest's feature-importance output for what it honestly is: what the trained model leaned on, not proof of a causal or tradable relationship. Understand exactly why "grow more trees" helps only up to a correlation floor, and what genuinely lowers that floor — which sets up gradient boosting's very different fix for the same underlying tension, next.
