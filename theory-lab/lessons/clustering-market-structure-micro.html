Clustering for Market Structure, Grouping What Nobody Labeled

Every other method in this curriculum has a target to check its answer against — a return to predict, a regime to classify. Clustering has none. It starts from a pile of things — trading days, currency pairs, factor exposures — with no labels attached at all, and asks only which of them behave alike. k-Means answers that by picking a number of groups upfront and iterating toward them; hierarchical clustering answers it by building a full tree of every possible grouping first, and only deciding "how many groups" after the fact. Both are the same tree-building idea this curriculum already used narrowly inside the earlier Hierarchical Risk Parity lesson — generalized here into a stand-alone discovery tool.

Section 1

No labels, no answer key — that's the whole point

Every regression or classifier elsewhere in this curriculum is supervised. Clustering is a different kind of question entirely.

🏷

Supervised methods have a target

A regression, a classifier, a diagnostic test — each has a known "correct" answer for every observation, and can be scored against it directly.

❓

Clustering has no target at all

It starts from a set of things with nothing labeled in advance, and asks only: which of these look alike, and which look different?

🔍

It's built for discovery

Genuinely useful for "are there natural groups here I haven't already hypothesized?" — a question supervised methods can't even ask.

⚠

It is never self-validating

An algorithm will confidently produce groups from almost any input, including pure noise. A clean-looking split proves the algorithm ran — not that the groups mean anything.

Both honest facts belong in the same sentence: clustering is a real, useful way to discover structure, and its output is never proof of anything on its own. Every result needs an independent sanity check against evidence the clustering never saw.
Section 2

The one building block underneath both methods

"How alike are two points?" is answered the same way everywhere below: ordinary Euclidean distance. Edit either point, live.

Try it
↔
Δx = 5, Δy = 5
Δx² + Δy² = 50
distance = √(Δx² + Δy²) = 7.0711
Blank or non-numeric input shows "—" instead of breaking — the same guard every calculator on this page uses.

This one quantity — squared distance, most of the time — is what "closest centroid" means to k-means and what "closest cluster" means to hierarchical clustering's linkage rule. Everything downstream is built on top of it, which is also exactly why unscaled features quietly wreck both methods: a feature with a bigger raw range dominates this calculation regardless of whether it's actually more informative.

Section 3

k-Means: commit to k, then loop

MacQueen (1967) named it; the iterative version almost everyone actually runs is Lloyd's algorithm (1957/1982).

1

Choose k, then initialize

Decide the number of clusters up front — the algorithm has no way to suggest one — and drop k starting centroids into the data.

2

Assign

Every point joins whichever centroid it's currently closest to, by squared distance.

3

Update

Recompute each centroid as the mean position of the points now assigned to it.

4

Repeat

Alternate assign and update until no point switches clusters. That's convergence.

Where this needs qualifying

Each step can only shrink the total squared distance from points to their own centroid, or leave it unchanged — so the loop is guaranteed to settle down. It is not guaranteed to settle on the best possible split: an unlucky starting position can converge to a genuinely worse local optimum and stay there, which is why production k-means always runs several restarts and keeps the lowest-error result.

Section 4

Watch it self-correct from a bad start

Try it
Cluster 1 = {A} only. Cluster 2 = {B,C,D,E,F}. Wrong split — D, E, F are far closer to each other than to B or C, but both starting centroids happened to sit on the same side.
Cluster 1 = {A,B,C}. Cluster 2 = {D,E,F}. μ₂ moved to the mean of {B,C,D,E,F} = (4.4, 5.0) — pulled toward D/E/F — which now puts B and C closer to μ₁ than to μ₂. They switch.
Converged. Reassigning every point against the new centroids changes nothing — the algorithm has found the natural two-cluster split, despite starting from centroids that were both on the wrong side.
This particular bad start still self-corrected in two iterations — that isn't guaranteed. A worse or unluckier start can settle into a genuinely wrong split and stay there.

Section 6

Picking k is a judgment call, not a calculation

Minimizing error alone would always push k toward the largest value available — at k=n, error hits exactly zero. Two heuristics try to find a defensible k instead.

Elbow method

Plot total within-cluster error against k. It always decreases, but often with a visible bend where returns sharply diminish. Pick k at the bend — except real data frequently has no obvious bend, and reasonable people can disagree on where it is.

Silhouette score

For each point, compare its distance to its own cluster against its distance to the nearest other cluster; average for a score from −1 to +1. Pick the k that maximizes it — except it can disagree with the elbow, and can be maximized at a useless k=2.

Neither is a calculator for the correct k

Both are heuristics for narrowing a judgment call, and both can point to different answers on the identical data. The defensible practice: look at both, look at the actual clusters they produce, and weigh whatever domain knowledge exists about how many groups should plausibly be there.

Section 7

Hierarchical clustering: build the whole tree first

No k to guess upfront — every level of grouping gets built at once, from the bottom.

1

Start with n singleton clusters

Every point begins as its own cluster of one.

2

Merge the two closest clusters

"Closest" is set by a linkage rule — single (nearest pair), complete (farthest pair), or average (mean pairwise distance). Record the distance the merge happened at.

3

Repeat until one cluster remains

Every merge is recorded, building a dendrogram — leaves are the original points, internal nodes are merges labeled by distance.

4

Choose k only at the end

Draw a horizontal cut across the finished tree at any height; the branches it crosses are the resulting clusters. Different heights, same tree, computed once.

Nothing here has to be decided before the algorithm runs — that's the entire trade against k-means. The cost is that building the full tree is more expensive, and — same as k-means — the choice of linkage rule changes the answer.

Section 9

The linkage rule changes the tree it builds

⊂

Single linkage

Distance between the single closest pair, one point from each cluster. Even one close pair triggers a merge — can produce long, straggly clusters.

⊃

Complete linkage

Distance between the single farthest pair. Only merges when even the most dissimilar members aren't too far apart — tends toward tighter, more compact clusters.

≈

Average linkage

The mean distance across every cross-cluster pair — a middle ground between the other two.

The same six points can produce a meaningfully different dendrogram depending on which rule is used. "A" dendrogram is not "the" dendrogram — the choice should be stated and justified, not left as an unexamined default.
Section 10

This is the Hierarchical Risk Parity tree, generalized

Explicit connection to an earlier lesson

The Hierarchical Risk Parity lesson in this curriculum already builds exactly this machinery — correlation turned into distance, then agglomerative clustering into a dendrogram — for one narrow purpose: recursively splitting portfolio weight down the branches. Nothing about the clustering step itself has anything to do with portfolios. The identical dendrogram-building procedure applies whenever the question is "which of these things behave alike" — whether the "things" being merged are assets awaiting a weight, trading days awaiting a regime label, or instruments being grouped purely to map market structure with no allocation decision attached at all.

Recognizing "this is the same clustering problem, just pointed at a different set of things" is the actual transferable skill here. The algorithm doesn't know or care whether the points it's merging are assets, days, or signals — it only ever sees numbers and distances between them.

Section 11

Where this actually shows up on a desk

🎯

Regime discovery

Build a daily feature vector — realized vol, trend strength, cross-asset correlation — with no "regime" label attached to any day, and let clustering surface which days behave alike.

💱

Instrument grouping

Cluster a universe of currencies or assets by return-behavior similarity to build a smaller set of representative baskets — without hand-specifying what "similar" should mean.

⚖

Signal deduplication

Identify which candidate signals are effectively near-duplicates of each other before feeding a pile of collinear features into a model.

Factual check against this repo's actual code

The full lesson's status line reads "CONCEPT — not built or tested anywhere in this repo." That's now stale for k-means specifically: js/forecastFeatureScan.js runs a real, deterministic, seeded k-means (_cluster) that groups trading days into recurring "day types" from their realized signature — exactly the regime-discovery scenario above — and it's exercised by js/forecastFeatureScan.test.mjs (asserting every day is clustered exactly once and that the seeded run is reproducible), consumed by js/volForecastResearchEngine.js and js/crossPairResearch.js, and surfaced live in vol-research-book.html and cross-pair-research.html. Hierarchical (dendrogram-based) clustering, by contrast, still has no general-purpose use in this repo outside the narrow Hierarchical Risk Parity allocator — consistent with that lesson's own, more precisely worded claim ("no clustering-based allocator built or tested"). Read literally, both statements can be true at once: k-means clustering exists and is tested; a hierarchical-clustering allocator does not.

A regime map that survives an independent check — does the "stressed" cluster line up with dates already known to be volatile from other evidence? — is a genuine discovery. A regime map only ever checked against the clustering that produced it is not evidence of anything; it's the algorithm confirming its own output.
Section 12

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

What must you commit to before running k-means that hierarchical clustering never requires upfront?

k-means needs k chosen before it starts. Hierarchical clustering builds the entire tree first and only picks a cluster count afterward, by choosing where to cut.
Question 2

In Lloyd's algorithm, what does the "update" step do?

Assign and update alternate: assign every point to its nearest centroid, then recompute each centroid as the mean of its current members.
Question 3

Why is k-means guaranteed to converge, but not guaranteed to find the best possible clustering?

Assigning to the nearest centroid, and setting a centroid to the mean of its points, both provably never increase the total squared distance — but where it lands depends on where it started, which is why production use runs multiple restarts.
Question 4

Cutting a dendrogram at a lower height, versus a higher height, tends to produce:

A lower cut happens before more merges have occurred, so more of the original singleton-to-small clusters are still separate. A higher cut has already absorbed more merges into fewer, bigger groups.
Question 5

Two years of daily feature vectors cluster neatly into 3 groups that look like calm/trending/stressed regimes. What's the appropriate next step?

Clustering has no ground truth to check itself against — it will produce k groups from almost any input. The only real validation is checking against something independent of the clustering process itself.
Section 13

What to carry forward

01

Clustering is unsupervised — there's no labeled target, only the question "which of these look alike?" — and its output is never self-validating.

02

k-Means loops assign-to-nearest-centroid then update-centroid-to-mean until stable. Fast and guaranteed to converge, but only to a local optimum, and only to roughly round, similarly-sized clusters.

03

Hierarchical clustering builds the entire tree bottom-up by repeatedly merging the closest pair, per a chosen linkage rule — no k needed upfront, only where to cut afterward.

04

Both methods measure distance directly, so unscaled features silently distort every decision either one makes — the same standardization discipline other methods in this curriculum require.

05

This generalizes the earlier Hierarchical Risk Parity lesson's own dendrogram machinery — the same tree-building tool, pointed at regimes, instruments, or signals instead of portfolio weight.

06

Every clustering result needs an independent sanity check against real domain knowledge before it's trusted as a finding, not just an algorithm's own internal metric agreeing with itself.

What this now lets you do

Discover regime groupings or instrument groupings directly from data — without having to hand-specify in advance what a "regime" or a "similar instrument" should look like — using either a fast, k-committed method or a slower, tree-building one that defers that choice. And know the mandatory next step either way: check the result against evidence the clustering itself never had access to, before treating it as a finding.
