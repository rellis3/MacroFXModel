Deep Q-Networks, Trading the Table for a Trained Guesser

The Q-learning & temporal-difference lesson learned one number for every state-action pair in a table small enough to fit on a page. The policy gradients & actor-critic lesson sidestepped that table entirely by optimizing a policy directly. This lesson closes the loop: what to do when you want to keep Q-learning's exact update rule, but the table it needs has become impossible to write down — replace it with a neural network, then add the two specific tricks that stop that replacement from destabilizing the very learning process it's supposed to rescue.

The whole idea
🎧 Listen · the four-minute version

A trader and a quant talk the lesson through. No symbols, just the idea and one worked number, so it works on a walk or a commute.

Q-learning kept one number for every situation and action. My real state is thirty features. What happens to the table?

It explodes. Thirty features cut into just ten levels each would need more rows than you could ever visit. So you throw the table away and train a network to guess the value instead.

Same update rule?

Same target: the reward, plus the discounted best guess for the next state. The difference is that you square the gap and take a gradient step on the network's weights, instead of overwriting a cell.

That sounds like it should just work.

Done naively, it's badly unstable. DeepMind's team found two fixes and published them in Nature in 2015, playing Atari games from raw pixels.

Fix one?

Experience replay. Neighboring moments in the market look almost the same, so training on them in order makes the network overfit whatever just happened. Instead you store every transition in a buffer and train on a random draw from it.

And fix two?

The target network. If the same network builds its own target, every step moves the goalposts. So you keep a frozen copy to build the target and only refresh it every so often.

Give me a number.

One transition pays a tenth. The frozen copy rates the next state at two for holding. With a discount of zero point nine, the target is zero point one plus one point eight, so one point nine. The online network currently guesses one point six. The gap is zero point three, and squared that's zero point zero nine. That's the loss you shrink.

Has anyone traded with this?

Researchers have tried it on execution, and in 2020 Zhang, Zohren and Roberts tested it on about fifty futures contracts, with rewards net of costs. In their backtests it beat classic time series momentum.

So should I trust a DQN backtest?

With extra scepticism. It was proven where the score is clean and frequent. A market reward is noisy and shifts with the regime. And a network is far harder to inspect than a table, so a high score in a simulator mostly proves it optimized that simulator.

So the one-line version?

Same target as Q-learning, a network instead of a table, shuffled replay and a frozen target to keep it stable, and more doubt, not less, about what it learned.

Section 1 · How it reached trading

Too many market states for a table

Deep Q-learning · into trading and execution research from the late 2010s

How it reached trading

Tabular Q-learning needs the market chopped into a few buckets; a real state (order-book levels, returns, volatility, inventory) has far too many combinations. DQN, built at DeepMind for video games, swaps the table for a network, with replay and a target network to keep it stable.

From the late 2010s researchers applied it to execution and trading. Zhang, Zohren & Roberts (2020), for example, tested DQN on about fifty futures contracts net of costs. It fits discrete choices, but a market reward is far noisier than a game score.

Section 2

The Q-table's fatal flaw: it needs a room, not a page

The Q-learning lesson's worked example — three states, a handful of actions — fit entirely on a page. That was never the hard case.

▦

One cell per (state, action) pair

Tabular Q-learning stores a literal number for every combination it might ever need — and its convergence guarantee explicitly assumes every pair gets visited, stored, and updated individually, infinitely often.

3

Fine when the world is three labels wide

Flat, Long, Short, a few actions — every cell has a name you could point to. The Q-learning lesson built its whole example on exactly this scale.

∞

Breaks the moment the state is continuous

A state built from thirty-odd real-valued market features — recent returns, volatility, momentum, cross-asset signals — has, for practical purposes, infinitely many distinct values. No two trading days share an exact feature vector.

⊘

An unvisited row has no opinion at all

A table indexed by exact state would need to see the same row twice before it could say anything about it — and with continuous features, it almost never does. It doesn't guess badly; it simply has nothing to say.

This lesson exists to fix exactly one limitation — nothing about Q-learning's update rule changes. What changes is what "the thing being updated" is: not a table cell, but the weights of a network.
Section 3

Same update rule, a different container for the estimate

Q(s,a) stops being a table cell and becomes Q(s,a;θ) — a neural network parameterized by weights θ.

DQN architecture, in one picture
A table has no answer for a state it's never seen. This network gives every state some answer, on the strength of everything similar it has already trained on.

Nothing about the underlying idea changes: whichever action's box comes out highest is still the greedy choice, exactly as it was reading the highest cell in a table. What's new is that the same shared weights θ produce every one of those boxes — training on one state quietly reshapes the guess for every state that resembles it, which is the entire value a table could never offer.

The failure mode a table could never produce

A network that generalizes well helps in unfamiliar-but-similar states. A network that generalizes badly — confidently guessing a wrong number for a state that isn't actually similar to anything it trained on — is new. A table facing an unvisited state has no answer at all; a trained network always has one, and it isn't automatically the right one.

Section 5

Why a plain swap isn't enough

Train the naive way — sample transitions in the order they happen, target with the same network being updated — and it's badly unstable.

Problem 1

Correlated samples. Consecutive states in a trajectory are highly similar — a market state one tick later looks almost identical to the one before it. Training on them in strict sequence biases the network toward whatever narrow slice of the world it just happened to be passing through.

Problem 2

A moving target. If the same weights being updated also generate the target they're trained toward, every gradient step that moves the guess closer also moves the goalpost. The network ends up chasing a target that shifts under its own updates.

Each problem gets one specific, named fix — not a general "add more data" or "train longer." The next two sections are exactly those two fixes.

Section 6

Fix 1 — experience replay

Store every transition as it happens. Train on a random sample from the whole history, not the newest arrival.

Section 7

Fix 2 — the target network

Freeze a second copy of the network, θ⁻, used only to compute the target. Sync it from θ every N steps — not every step.

Illustrative training loss — without the trick, then with it
Same weights compute the guess and the target, and every batch is whatever the agent just experienced. The target the network is chasing shifts under its own updates — this is the honest, illustrative shape of "unstable," not a real training log.
Random mini-batches decorrelate the training data; a frozen θ⁻ holds the target still between syncs. Neither fix alone is the whole story — this is what the combination is supposed to buy, illustrated, not a claim about any specific run.

Section 8

How often should θ⁻ get updated?

A smaller N keeps the target fresher but closer to moving under its own updates. A larger N holds it stiller — up to a point, past which it's just stale.

Illustrative stability vs. sync frequency
Steps between target-network syncsN = 100
Illustrative shape, not a measured curve — but the qualitative trade is real: syncing every step reintroduces the moving-target problem; syncing so rarely that θ⁻ never catches up trades that away for a target that's stuck describing an online network several thousand gradient steps in the past.

Section 10

Still value-based: the max that doesn't go away

A network in place of a table changes how Q(s,a) is stored. It doesn't change what DQN computes at every target.

DQN — value-based
  • Every target needs maxa′ Q(s′,a′;θ⁻) — trivial when actions are a small, discrete menu (Buy / Hold / Sell)
  • Acts by taking whichever output box is largest — exactly like reading the best cell in a table
  • This lesson's whole apparatus — replay, target network — exists to train that max reliably
Policy gradients / actor-critic — policy-based
  • Parameterizes and optimizes the policy directly — never computes a max over actions at all
  • The fix for a continuous action space like position size, where "maximize over every possible action" is its own nested optimization problem, not a lookup
  • Covered in full in the Policy Gradients & Actor-Critic lesson
Value-based and policy-based aren't rival final answers — they're two tools suited to two different action-space shapes. Discrete-and-small favors DQN; continuous favors policy gradients. The choice between this lesson and the previous one is mostly that shape question.
Section 11

What a trained guesser doesn't tell you

The trade this makes, stated plainly

Swapping a Q-table for a neural function approximator adds real complexity — millions of weights instead of a handful of table entries — and removes interpretability: a table cell's stored number can be inspected directly; a trained network's generalization behavior on an unseen state usually can't be, short of extensive separate testing. That makes a poorly specified reward or an unrealistic simulated environment an easier way to "solve" a backtest and still fail live, not a harder one.

DQN and its descendants are genuinely impressive on well-defined games with a clear, dense reward — that's a fact about Atari, not a fact transferable to markets by default. Reinforcement learning is a general-purpose optimizer, not a trading strategy; it will faithfully optimize whatever reward and simulated environment it's handed.

Section 12

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

Why does a Q-table break down for a state built from thirty continuous market features?

Tabular Q-learning's guarantee requires every state-action pair to be visited repeatedly. With continuous features, essentially no two observed states are ever exactly the same, so a table indexed by exact state can't learn anything useful for most of them.
Question 2

What specific problem does experience replay fix?

Consecutive states in a trajectory are highly similar; training on them in strict order biases the network toward whatever narrow region it's currently passing through. Random sampling from a buffer mixes in experience from many different points in history.
Question 3

Why does the DQN target use θ⁻ (the target network) instead of θ (the network being trained right now)?

If the target used the same θ being updated, every gradient step that moved the guess closer would also move the target — a moving-target instability with no guarantee of settling anywhere. θ⁻ is synced from θ only every N steps, holding the target still in between.
Question 4

r = 0.1, γ = 0.9, max Q(s′,a′;θ⁻) = 2.0, Q(s,a;θ) = 1.6 — what's the squared loss?

target = 0.1 + 0.9(2.0) = 1.9. loss = (1.9 − 1.6)² = 0.3² = 0.09 — exactly the calculator's worked-example default.
Question 5

Why is DQN "value-based," and what does that mean for a continuous action space like position size?

DQN computes max Q(s′,a′;θ⁻) at every target, exactly like tabular Q-learning — that's what makes it value-based. That max is a simple lookup over a handful of discrete outputs, but becomes awkward for a continuous action space, which is exactly why the policy gradients / actor-critic lesson exists.
Your call
Scenario drill · an illustrative research meeting

"Sync the target network every step, it trains faster"

A colleague's DQN chooses between buy, hold and sell from a state of thirty market features. Training swings wildly: the loss falls, then jumps, then falls again. They propose two changes to speed things up: copy the online weights into the target network after every gradient step, and shrink the replay buffer to the last few hundred transitions so it only holds "fresh" data. What do you say?

  1. Do both. Fresher targets and fresher data should help.
    Syncing every step removes the target network's whole purpose: the target would move every time the weights do. A tiny buffer is dominated by recent, near-identical transitions, so replay no longer decorrelates anything. Both changes bring back the instability the fixes exist to stop.
  2. Keep a periodic sync and a large buffer sampled at random. If anything, sync less often, and check the reward and simulator before chasing speed.
    The staleness of the target is the mechanism, not overhead. Random draws from a large buffer are what break the correlation. And a stable training curve still proves only that the network optimized this reward in this simulator.
  3. Keep the buffer but switch to prioritized replay, sampling the most surprising transitions more often.
    A real refinement, but it changes the sampling distribution and needs importance weights to stay unbiased. It also leaves the every-step sync proposal unanswered, which is the bigger problem.
  4. Drop the target network and use a larger learning rate to converge before the target drifts.
    A bigger step makes the chase faster and wilder. With the target built from the same weights, each larger step moves the goalposts further, which tends to make the oscillation worse, not better.

What this shows. This is an illustrative situation, not a real episode. The answer is the lesson's own pitfall list: skipping the target network "because it trains faster" and a buffer too small to decorrelate are the two standard ways to undo DQN's fixes.

Section 13

What to carry forward

01

A Q-table needs one entry per state-action pair — infeasible once the state space is continuous or built from more than a handful of features, because near-identical states almost never repeat exactly.

02

A deep Q-network replaces the table with Q(s,a;θ), a neural network — the same TD update rule, now a gradient step, generalizing across states it's never exactly seen.

03

Experience replay stores transitions in a buffer and trains on a random mini-batch — breaking the correlation between consecutive samples that a naive live-stream training loop suffers from.

04

A target network freezes a second copy, θ⁻, for computing the TD target — syncing it from θ only every N steps stops the target from moving under its own updates.

05

DQN is still value-based — it still needs max over actions, which is exactly why policy gradients and actor-critic methods exist for continuous action spaces like position size.

06

A network adds complexity and removes interpretability relative to a table — that makes a poorly specified reward or an unrealistic backtest an easier trap to fall into, not a harder one.

07

How it reached trading: from the late 2010s deep Q-learning was applied to execution and futures trading (e.g. Zhang, Zohren & Roberts, 2020), but it was proven on clean game scores, not noisy market rewards.

What this now lets you do

Recognise, whenever a state space is too large or continuous to tabulate, that the fix is a function approximator on the exact same update rule — not a different algorithm. Read a DQN loss and immediately identify the online network, the target, and why θ⁻ is deliberately a separate, stale copy of θ. Know when to reach for value-based DQN (small discrete actions) versus policy-based methods (continuous actions) — and treat a high backtest score from either one with the same skepticism, since neither is evidence the underlying reward or simulator was realistic.
