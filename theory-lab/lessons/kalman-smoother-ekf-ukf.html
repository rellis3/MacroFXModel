The Kalman Smoother & Extended/Unscented Kalman Filters

Two separate upgrades to the plain Kalman filter: a backward pass that uses the whole dataset to sharpen every past estimate, and two ways of handling a genuinely nonlinear state-space model instead of a linear one.

CONCEPT — not built or tested anywhere in this repo ~19 min read Prereqs: Kalman Filter & Adaptive Relationships, The Particle Filter
TL;DR
  • The plain Kalman filter is forward-only — its estimate at time \(t\) uses only data through \(t\). The Rauch-Tung-Striebel (RTS) smoother adds a backward pass that revisits every past estimate using the entire dataset, including observations from after that point in time.
  • The Extended Kalman Filter (EKF) handles a nonlinear state-space model by re-linearizing it at every step via a first-order Taylor expansion — the Jacobian — evaluated at the current estimate, then running the ordinary linear Kalman equations on that local linear approximation.
  • The Unscented Kalman Filter (UKF) instead picks a small, deterministic set of representative points (sigma points), pushes each one through the true nonlinear function with no approximation, and reconstructs the mean and covariance from where those points land — generally more accurate than the EKF for strongly nonlinear systems, and it never requires computing a Jacobian.
  • The worked example smooths a two-day hedge-ratio track from the Kalman filter lesson, and separately runs EKF and UKF against the same nonlinear observation function — the two land within about 0.003 of each other here, because the nonlinearity is mild relative to the uncertainty band in play; the gap widens as nonlinearity or uncertainty grows.
  • Honest scope note: EKF and UKF matter for genuinely nonlinear systems. The plain linear Kalman filter already suffices for this curriculum's existing linear-Gaussian applications (e.g. tracking a hedge ratio) — reaching for either extension without a real nonlinearity in hand adds complexity for no benefit.
Section 01

Why this matters

The Kalman filter lesson built one recursion — predict, then update — and left two limitations explicitly flagged rather than solved. First, that filter only ever looks backward in time: the estimate \(\hat{x}_{t\mid t}\) at time \(t\) is the best guess using data through \(t\) only, even if the full dataset runs on for years afterward. That's exactly right for a live system (you genuinely don't have tomorrow's data yet), but it's needlessly conservative for historical analysis, where the whole series already sits on disk — day 40's true state is knowable with more precision once day 41 through day 200 are also available to check against. Second, that filter's whole closed form depends on the state and observation equations being linear. Real systems are routinely not: a nonlinear sensor reading, a state that saturates or mean-reverts nonlinearly, a relationship that's roughly linear only very close to the current estimate but curves away from it further out.

This lesson covers three named extensions built directly on the plain Kalman filter's own predict/update machinery — none of it is re-derived from scratch here, only extended in one of two directions. The RTS smoother answers the first limitation: given the entire dataset, go back and sharpen every historical estimate using the future observations the live filter didn't have yet. The Extended and Unscented Kalman filters answer the second: keep the same predict/update skeleton, but replace its linear-algebra core with something that tolerates a genuinely nonlinear \(f\) or \(h\) — the same nonlinear state-space setup introduced in the particle filter lesson, \(x_t = f(x_{t-1}, w_t)\), \(y_t = h(x_t, v_t)\), but handled here by a cheaper, deterministic approximation instead of a full particle swarm.

💡
Plain-English intuition

Hindsight is fair game once you're not live anymore

Recall the Kalman filter's boat-at-night analogy: a running position estimate, updated once per radar ping, using only pings received so far. Now imagine the voyage is already over, and every single radar ping from the whole night is sitting in a logbook in front of you. Where was the boat at 2am? The live answer — the one the crew actually had to navigate by, in real time, at 2am — could only use pings up through 2am. But your logbook answer, written the next morning, can also use the 3am, 4am, and 5am pings: if the boat's position implied by the 2am estimate looks inconsistent with where it clearly had to be by 4am, given how boats move, you can and should revise the 2am estimate in hindsight. That revised, better-informed answer is exactly what an RTS smoother computes — one backward pass through the log, using everything, sharpening every past estimate the live filter had to commit to early and provisionally.

The nonlinear extensions solve a completely different problem, best pictured geometrically. The Kalman filter's update step needs to know how a change in the hidden state translates into a change in what's observed — for a linear relationship, that translation is the same everywhere (a constant slope). For a nonlinear relationship, the translation itself changes depending on where you currently are on the curve. The Extended Kalman Filter's answer is to draw a straight tangent line touching the curve at the current best guess, and use that tangent's slope as a stand-in for the true curve nearby — accurate right at the touch point, worse the further you stray from it. The Unscented Kalman Filter's answer is different: instead of drawing one tangent line at one point, send out a small handful of scouts to a few carefully chosen nearby points, let each one walk the actual curve (no straight-line approximation at all), and then average where the scouts ended up to reconstruct the answer — trading one convenient approximation for a few honest, exact evaluations of the real function.

Section 02

The math, step by step

Part A — the RTS smoother: a backward pass over the whole dataset

Start from the forward Kalman filter exactly as derived in the Kalman filter lesson: run predict and update for every \(t = 1, \ldots, T\), storing at each step the filtered estimate and variance, \(\hat{x}_{t\mid t}\) and \(P_{t\mid t}\), and the predicted estimate and variance one step ahead of it, \(\hat{x}_{t+1\mid t}\) and \(P_{t+1\mid t}\) (the predict step's output, before that step's own update folds in \(y_{t+1}\)). The smoother then runs backward, from \(t=T-1\) down to \(t=1\), refining each filtered estimate using the already-smoothed value one step ahead of it:

\[ C_t = \frac{P_{t\mid t}}{P_{t+1\mid t}} \qquad \hat{x}_{t\mid T} = \hat{x}_{t\mid t} + C_t\left(\hat{x}_{t+1\mid T} - \hat{x}_{t+1\mid t}\right) \qquad P_{t\mid T} = P_{t\mid t} + C_t^2\left(P_{t+1\mid T} - P_{t+1\mid t}\right) \]
C_tthe smoother (backward) gain — how much this step's estimate should defer to what the future revealed
x̂_t|Tthe smoothed estimate at time t — using ALL T observations, not just the first t
P_t|Tthe smoothed variance at time t — always ≤ the filtered variance P_t|t, since more data can only sharpen the estimate

Read \(C_t\) as a direct cousin of the ordinary Kalman gain — it's a ratio of "how uncertain this step's filtered estimate was" to "how uncertain the very next step's predicted estimate was," and it controls how strongly this step's smoothed value gets pulled toward wherever the future's smoothed trajectory ended up. The recursion starts from the simple boundary condition \(\hat{x}_{T\mid T} = \hat{x}_{T\mid T}\) — the very last time step's smoothed estimate is identical to its filtered one, because there is no future data left to fold in — and works backward from there, one step at a time, each step using the already-computed smoothed value one step ahead of it.

Worked example

Smoothing the Kalman filter lesson's two-day hedge-ratio track

Reusing the Kalman filter lesson's own worked example exactly (not re-derived here): tracking a hedge ratio with \(\hat{x}_{0\mid 0}=1.20\), \(P_{0\mid 0}=0.0400\), \(Q=0.0009\), \(R=0.0100\), \(H_t=1\). That lesson's forward pass produced:

Day 1: \(\hat{x}_{1\mid 0}=1.20\), \(P_{1\mid 0}=0.0409\) (predicted); \(\hat{x}_{1\mid 1}\approx 1.321\), \(P_{1\mid 1}\approx 0.0080\) (filtered).
Day 2: \(\hat{x}_{2\mid 1}=1.321\), \(P_{2\mid 1}=0.0089\) (predicted); \(\hat{x}_{2\mid 2}\approx 1.311\), \(P_{2\mid 2}\approx 0.0047\) (filtered).

Day 2 is the last time step, so its smoothed estimate equals its filtered one: \(\hat{x}_{2\mid 2}=1.311\), \(P_{2\mid 2}=0.0047\). Now smooth Day 1 using that:

\[ C_1 = \frac{P_{1\mid 1}}{P_{2\mid 1}} = \frac{0.0080}{0.0089} \approx 0.899 \]
\[ \hat{x}_{1\mid 2} = 1.321 + 0.899 \times (1.311 - 1.321) = 1.321 - 0.00899 \approx 1.312 \]
\[ P_{1\mid 2} = 0.0080 + 0.899^2 \times (0.0047 - 0.0089) = 0.0080 - 0.00339 \approx 0.00461 \]

The filtered Day 1 estimate was 1.321 — the best guess a live trader would have had at the end of Day 1, using only Day 1's data. The smoothed Day 1 estimate is 1.312 — slightly lower, because Day 2's observation (1.30, below Day 1's estimate) retroactively pulls the Day 1 read down a little once it's known. Just as importantly, the smoothed uncertainty (\(P_{1\mid 2}\approx 0.0046\)) is noticeably lower than the filtered uncertainty (\(P_{1\mid 1}\approx 0.0080\)) — Day 1's estimate really is better known in hindsight, precisely because there's more data bearing on it. Neither of these numbers was available to a live trader at the end of Day 1; both require Day 2's observation, which is exactly why a smoothed estimate must never be treated as something a live system could have produced at the time.

If yesterday's guess was shaky (high uncertainty) and the days right after turned out to be very informative, you revise a lot. Part B — the Extended Kalman Filter: linearize, then run the linear equations

Now take the nonlinear state-space model from the particle filter lesson, \(x_t = f(x_{t-1}) + w_t\), \(y_t = h(x_t) + v_t\) (writing the noise as additive here, the standard EKF setup). The EKF's whole idea is: at every step, replace \(f\) and \(h\) with their first-order Taylor expansion — a straight line tangent to the true curve at the current best estimate — and then run the exact same predict/update equations from the Kalman filter lesson on that local linear stand-in:

\[ F_t = \left.\frac{\partial f}{\partial x}\right|_{\hat{x}_{t-1\mid t-1}} \qquad H_t = \left.\frac{\partial h}{\partial x}\right|_{\hat{x}_{t\mid t-1}} \]
F_tthe Jacobian of the transition function — the slope of the true curve f, evaluated at last step's estimate
H_tthe Jacobian of the observation function — the slope of the true curve h, evaluated at this step's predicted estimate

In one dimension, a Jacobian is just an ordinary derivative — the ordinary slope of \(f\) or \(h\) at a single point. (In the general multi-dimensional case it's a matrix of partial derivatives, one per input/output pair; that generalization is out of scope here, but the scalar case shown captures the entire idea.) With \(F_t\) and \(H_t\) in hand, the EKF's predict and update steps are literally the Kalman filter lesson's own equations, with the true nonlinear functions used to propagate the mean and the Jacobians used only to propagate the uncertainty:

\[ \hat{x}_{t\mid t-1} = f(\hat{x}_{t-1\mid t-1}) \qquad P_{t\mid t-1} = F_t^2\, P_{t-1\mid t-1} + Q \]
\[ e_t = y_t - h(\hat{x}_{t\mid t-1}) \qquad K_t = \frac{P_{t\mid t-1}\,H_t}{H_t^2 P_{t\mid t-1} + R} \qquad \hat{x}_{t\mid t} = \hat{x}_{t\mid t-1} + K_t e_t \qquad P_{t\mid t} = (1 - K_t H_t)\,P_{t\mid t-1} \]

Notice precisely what changed and what didn't, compared to the plain Kalman filter: the mean is still propagated through the true nonlinear \(f\) and \(h\) — no approximation there at all — but the uncertainty (\(P\)) is propagated as if the system were linear with slope \(F_t\) or \(H_t\), which is only as accurate as the tangent-line approximation is at that point. That mismatch — exact mean propagation, approximate covariance propagation — is the entire source of the EKF's known weakness: it can become overconfident (an understated \(P\)) whenever the true curve bends away from its tangent line faster than the current uncertainty band is narrow.

🧒 Explain like I'm 5

Imagine trying to predict a hilly hiking trail using only a ruler laid flat against the ground exactly where you're standing. Right at your feet, the ruler matches the trail perfectly. A few steps ahead, though, the trail curves away from that flat ruler — maybe it climbs a hill the ruler has no idea is coming. The EKF is exactly that ruler: it re-lays itself fresh at every single step (so it's never wildly wrong for long), but it can still misjudge how steep the trail gets between one step and the next, especially on a sharply curving stretch.

Part C — the Unscented Kalman Filter: sample the true curve instead of linearizing it

The UKF keeps the same predict/update skeleton but replaces the Taylor-expansion step entirely. Instead of linearizing \(f\) or \(h\), it picks a small, deterministic set of points — sigma points — that exactly capture the current estimate's mean and variance, pushes each one through the true, unaltered nonlinear function, and reconstructs the propagated mean and variance from where those points land. For a state of dimension \(L\) (here \(L=1\), the scalar case used throughout this curriculum), the standard construction uses \(2L+1\) sigma points:

\[ \chi_0 = \hat{x} \qquad \chi_1 = \hat{x} + \sqrt{(L+\lambda)P} \qquad \chi_2 = \hat{x} - \sqrt{(L+\lambda)P} \]
χ_ithe i-th sigma point — a specific, deterministically chosen candidate value near the current estimate
λa scaling parameter controlling how far the sigma points spread from the mean — a chosen constant, not derived

(The general multivariate case needs a matrix square root of \(P\), typically via Cholesky decomposition, spreading \(2L\) points symmetrically along every dimension — that machinery is out of scope here, but the scalar case above shows the whole idea with three sigma points: the mean itself, and one point pushed out to either side by an amount set by \(P\) and \(\lambda\).) Each sigma point is pushed through the true function, \(Y_i = h(\chi_i)\), and the mean/variance of the transformed observation are reconstructed as weighted sums:

\[ \hat{y} = \sum_i W_i^{(m)} Y_i \qquad P_{yy} = \sum_i W_i^{(c)} \left(Y_i - \hat{y}\right)^2 + R \qquad P_{xy} = \sum_i W_i^{(c)} \left(\chi_i - \hat{x}\right)\left(Y_i - \hat{y}\right) \]
W_i^(m), W_i^(c)mean and covariance weights for sigma point i — chosen constants, one per sigma point, that sum to 1
P_yythe reconstructed variance of the predicted observation — combines curvature captured by the sigma points plus observation noise R
P_xythe reconstructed cross-covariance between the state and the observation — the UKF's stand-in for the EKF's P·H term

From there, the update step mirrors the ordinary Kalman gain exactly, just built from these reconstructed quantities instead of a Jacobian: \(K = P_{xy}/P_{yy}\), \(\hat{x}_{t\mid t} = \hat{x} + K(y_t - \hat{y})\), \(P_{t\mid t} = P - K\,P_{xy}\). The crucial structural difference from the EKF: nothing here was linearized. Every sigma point walked the real, unaltered nonlinear function; the only approximation left is reconstructing a mean and variance from a handful of exact points, rather than linearizing the function that produced them — which is why the UKF is generally more accurate than the EKF whenever the nonlinearity is strong enough that a single tangent line stops being a good local stand-in.

🧒 Explain like I'm 5

Instead of trusting one ruler laid down at your feet, send out three actual scouts to walk the real trail — one right where you're standing, one a bit ahead, one a bit behind — and let each one report exactly what they found, hills and all, with no ruler involved. Then average their honest reports to build your overall picture. It costs a bit more legwork than reading one ruler, but nobody had to pretend the trail was flat anywhere.

\(L\)The dimension of the hidden state — \(L=1\) throughout this lesson's scalar examples; the UKF uses \(2L+1\) sigma points in general.

\(\lambda\)The UKF's sigma-point scaling parameter, controlling how far the sigma points spread from the mean — a chosen constant, analogous to the Kalman filter's \(Q\)/\(R\) in that it must be picked, not derived.

Worked example

EKF vs. UKF against the same nonlinear observation, x̂=1.30

Take a deliberately simple, textbook nonlinearity for clean hand computation: the observation function is \(h(x) = x^2\) (a toy nonlinearity, chosen for arithmetic clarity, not a specific trading relationship). Predicted state \(\hat{x}_{t\mid t-1} = 1.30\), predicted variance \(P_{t\mid t-1} = 0.01\) (std. dev. 0.10), observation noise \(R = 0.02\), and an actual observation \(y_t = 1.75\).

EKF: the Jacobian of \(h(x)=x^2\) is \(H = 2x\), evaluated at \(\hat{x}=1.30\): \(H = 2.60\). Predicted observation \(h(\hat{x}) = 1.30^2 = 1.69\).

\[ e = 1.75 - 1.69 = 0.06 \qquad S = 2.60^2\times 0.01 + 0.02 = 0.0876 \qquad K = \frac{0.01\times 2.60}{0.0876} \approx 0.297 \]
\[ \hat{x}_{t\mid t} = 1.30 + 0.297\times 0.06 \approx 1.3178 \qquad P_{t\mid t} = (1-0.297\times2.60)\times 0.01 \approx 0.00228 \]

UKF (scalar, \(L=1\), choosing \(\lambda=2\) as an illustrative scaling constant — itself a chosen input, exactly like the EKF needed no such choice but the plain KF needed \(Q,R\)): \(\sqrt{(L+\lambda)P} = \sqrt{3\times 0.01} = 0.1732\). Three sigma points: \(\chi_0=1.30\), \(\chi_1=1.4732\), \(\chi_2=1.1268\), with weights \(W_0=2/3\approx0.667\), \(W_1=W_2=1/6\approx0.167\).

Push each through the true \(h(x)=x^2\): \(Y_0=1.6900\), \(Y_1=2.1703\), \(Y_2=1.2697\).

\[ \hat{y} = 0.667(1.6900) + 0.167(2.1703) + 0.167(1.2697) \approx 1.700 \]

Already a small but telling difference from the EKF: the UKF's reconstructed predicted observation is 1.700, not the EKF's 1.690 — because \(E[x^2] \geq (E[x])^2\) whenever \(x\) has any variance at all (Jensen's inequality: the curve bends upward, so averaging the curve's outputs gives a slightly higher value than evaluating the curve at the averaged input). The EKF's tangent line cannot see this — it only knows the slope at one point, not the curvature around it.

\[ P_{yy} = \underbrace{0.0678}_{\text{curvature term}} + \underbrace{0.02}_{R} = 0.0878 \qquad P_{xy} \approx 0.02601 \qquad K = \frac{P_{xy}}{P_{yy}} = \frac{0.02601}{0.0878} \approx 0.296 \]
\[ \hat{x}_{t\mid t} = 1.30 + 0.296\times(1.75-1.700) \approx 1.3148 \qquad P_{t\mid t} \approx 0.00230 \]

EKF lands at \(\hat{x}_{t\mid t}\approx 1.3178\); UKF lands at \(\approx 1.3148\) — about 0.003 apart, with almost identical updated uncertainty (\(0.00228\) vs. \(0.00230\)). For this particular curvature (\(x^2\)) and this particular uncertainty band (\(\sigma\approx 0.10\)), the two methods nearly agree, because the tangent line is still a fairly good local stand-in over that narrow a band. That gap is exactly what widens as the true function's curvature grows relative to the uncertainty band — a stronger nonlinearity, or a wider \(P\), pushes the sigma points further from \(\hat{x}\) into territory the tangent line increasingly misrepresents, while the UKF keeps sampling the true curve regardless.

EKF — linearize, then apply the linear formula

Cheap: one derivative evaluation per step. Exact mean propagation through the true \(f\)/\(h\), but covariance propagation only as good as the tangent line locally. Can become overconfident (understated \(P\)) when curvature is strong relative to the uncertainty band.

UKF — sample the true curve, skip the derivative

Needs no Jacobian at all — useful when \(f\)/\(h\) isn't differentiable in closed form, or the derivative is awkward to derive. Generally more accurate for strongly nonlinear systems, at the cost of evaluating the true function \(2L{+}1\) times per step instead of once, and choosing the scaling constant \(\lambda\) (and its relatives \(\alpha,\beta,\kappa\) in the fuller formulation).

🎯
A named scenario

Writing a research note on a whole year's drifting relationship, versus running it live tomorrow

Suppose an analyst wants to write up how a hedge ratio actually behaved over the past calendar year, for a research note explaining what happened and why. That's exactly the RTS smoother's use case: run the ordinary forward filter across the whole year first, then run the backward pass using the entire year of data, and report the smoothed trajectory — the best-informed reconstruction of what the ratio was doing at every point, now that the whole year's outcomes are already known. But if that same analyst then wants to trade tomorrow off "what the model currently thinks the ratio is," the smoothed trajectory is the wrong number to use — tomorrow's true state is not yet known, so only the plain filtered estimate (or, if the relationship is genuinely nonlinear, an EKF/UKF filtered estimate) is valid to act on live. Mixing the two up — reporting a smoothed backtest as if it represented what a live system could have known in real time — is the single most common way this family of tools gets misused, and it is presented here purely to illustrate the distinction, not as a claim that either the smoother or either nonlinear filter has been built or validated for any live use in this repo.

Section 03

How practitioners actually use this

The RTS smoother takes its name from Herbert Rauch, Frank Tung, and Charlotte Striebel's 1965 paper (cited below), and is the standard tool whenever a state-space model is being fit to historical data for reporting or research rather than run live — smoothing a macro time series' unobserved trend component, reconstructing a full historical volatility path, or producing the cleanest possible historical reconstruction of any hidden state a Kalman-style model tracks, precisely because the smoother is strictly better-informed than the filter for anything already in the past.

The EKF has been the default nonlinear extension of the Kalman filter since the 1960s — it was, in fact, part of the Apollo program's guidance computer alongside the plain linear filter, since a spacecraft's actual dynamics are nonlinear. It remains the standard choice across robotics (nonlinear sensor models like bearing-only tracking), aerospace, and any estimation problem where the nonlinearity is mild enough, or the required update rate fast enough, that its lower computational cost outweighs its approximation error. The UKF, introduced by Julier and Uhlmann in 1997 (cited below), is reached for when the nonlinearity is strong enough that the EKF's linearization visibly degrades performance, or when the transition/observation function isn't conveniently differentiable in closed form (making the Jacobian itself awkward or expensive to derive) — at the cost of evaluating the true function several times per step instead of once, and choosing its own scaling constants.

In quantitative finance specifically, EKF/UKF-style extensions show up wherever a Kalman-style state-space model's relationship between the hidden state and the observation is not linear — for example, if a hidden factor enters an observed price through a nonlinear pricing formula rather than directly, or if a volatility-like quantity is modeled as a hidden state feeding into a squared or exponential observation relationship. This curriculum's own existing linear-Gaussian applications — tracking a hedge ratio, a beta, a factor loading — are, by design, exactly the case where the plain Kalman filter from that lesson already suffices; nothing about those specific use cases currently requires EKF or UKF machinery.

⚠️
Common pitfalls

Where these extensions get misused

Treating a smoothed estimate as something a live system could have known. This is the single most important pitfall in this lesson, and it's the exact same trap the Hidden Markov Model lesson flags for Viterbi-decoded regime labels: a smoothed state estimate uses observations from after the point being estimated. A backtest that quietly substitutes smoothed estimates for what a live filter would have produced is using information from the future without saying so.

EKF divergence when the nonlinearity is strong relative to the current uncertainty band. Because the EKF only linearizes locally, a sharp enough curve or a wide enough \(P\) can make the tangent-line approximation badly wrong — sometimes badly enough that the filter's estimate drifts away from the truth and its own reported uncertainty shrinks anyway (false confidence). There is no automatic warning built into the EKF's equations for this; it has to be checked externally, e.g. by monitoring whether the innovations behave as the model expects.

Assuming "unscented" means "exact." The UKF avoids linearizing the function, but reconstructing a mean and variance from a handful of sigma points is still only exact when the true relationship is itself linear (in which case both EKF and UKF reduce to the plain Kalman filter, exactly). For a genuinely nonlinear function it remains an approximation — a better one than a first-order Taylor expansion in most cases, not a perfect one.

The UKF's scaling constants are themselves a chosen input, not a derived quantity. \(\lambda\) (and its relatives in the fuller \(\alpha,\beta,\kappa\) formulation) controls how far the sigma points spread — exactly the same category of chosen, tunable input as the Kalman filter lesson's \(Q\) and \(R\), and subject to the identical warning against grid-searching it against backtest performance.

Reaching for EKF/UKF when the problem is actually linear. Both extensions reduce to the plain Kalman filter exactly when \(f\) and \(h\) truly are linear — in that case they add computational cost (a Jacobian, or several extra function evaluations per step) for zero accuracy benefit. Confirm the nonlinearity is real and material before reaching past the plain filter.

Worth remembering: the EKF's exact-mean/approximate-covariance mismatch is the single root cause of nearly every EKF failure mode — it never shows up as an error message, only as an estimate that's quietly wrong and a reported uncertainty that's quietly too small to notice.

Key Takeaways

✓The RTS smoother is one backward pass over the whole dataset, using the already-smoothed value one step ahead and the smoother gain \(C_t = P_{t\mid t}/P_{t+1\mid t}\) — strictly sharper than the forward-only filter, but only available after the fact.
✓The EKF linearizes via the Jacobian at every step, then runs the exact same predict/update equations from the plain Kalman filter — exact mean propagation, approximate covariance propagation.
✓The UKF samples the true curve at a few sigma points instead of linearizing it, needing no Jacobian and generally beating the EKF for strongly nonlinear systems.
✓The worked example's EKF and UKF landed within about 0.003 of each other — close, because a mild curvature over a narrow uncertainty band is still well approximated by a tangent line; the two diverge more as either grows.
⚠A smoothed estimate has lookahead baked in — never valid as a live signal. The same trap the Hidden Markov Model lesson flags for Viterbi labels applies here identically.
⚠Concept lesson only, and only needed for genuine nonlinearity. This repo's existing linear-Gaussian applications (hedge-ratio tracking) are already fully served by the plain Kalman filter — nothing here is built, tested, or validated, and explaining the extensions is not a claim either produces edge.
Section 05

Self-test

Q1. Why can a smoothed estimate \(\hat{x}_{t\mid T}\) never be produced by a live trading system operating at time \(t\)?
Because computing it requires observations from after time \(t\) — up through \(T\) — which a live system operating at time \(t\) does not yet have. The smoothed estimate is only computable after the fact, once the full dataset through \(T\) is available; it answers "what do we now know, in hindsight, about time \(t\)?" not "what could we have known, live, at time \(t\)?"
Q2. In the worked example, why is the smoothed Day 1 variance (≈0.0046) lower than the filtered Day 1 variance (≈0.0080)?
The filtered variance reflects everything known through Day 1 only. The smoothed variance additionally incorporates Day 2's observation, which is more information bearing on the true state at Day 1 — and more information can only ever sharpen (never worsen) an estimate, which is exactly why smoothed variance is always less than or equal to filtered variance at the same time step.
Q3. What exactly does the EKF linearize, and what does it leave un-approximated?
The EKF linearizes the covariance propagation — it uses the Jacobian (the local slope) of \(f\) and \(h\) to propagate \(P\) as if the system were linear at that point. It does not linearize the mean propagation: the predicted state \(\hat{x}_{t\mid t-1}=f(\hat{x}_{t-1\mid t-1})\) and predicted observation \(h(\hat{x}_{t\mid t-1})\) both use the true, unaltered nonlinear functions directly.
Q4. Why did the UKF's predicted observation (1.700) come out slightly higher than the EKF's (1.690) for h(x)=x², given the same starting estimate and uncertainty?
This is Jensen's inequality at work: for a convex function like \(x^2\), the average of the function's outputs across a spread of inputs is always at least as large as the function evaluated at the average input, whenever there's genuine spread (variance) in those inputs — \(E[x^2] \geq (E[x])^2\). The UKF's sigma points genuinely sample that spread and average the true curve's outputs, capturing this curvature effect. The EKF's tangent line only evaluates the function at the single mean point, \(h(\hat{x})=1.30^2=1.69\), and has no way to see the curvature around it.
Q5. If a nonlinear observation function turned out to actually be linear, what would the EKF's Jacobian and the UKF's sigma-point reconstruction reduce to?
Both would reduce exactly to the plain Kalman filter. If \(h(x) = Hx\) is truly linear, its Jacobian is simply the constant \(H\) everywhere (no approximation, since a straight line's tangent line is itself), and the UKF's sigma points, each pushed through that same linear function, would reconstruct precisely the same mean and variance the ordinary linear Kalman update produces — there would be no divergence between EKF, UKF, and the plain filter at all.
Q6. Name one situation where the UKF would be clearly preferred over the EKF, and one where the plain linear Kalman filter is clearly preferred over either.
Prefer the UKF over the EKF when the nonlinearity is strong relative to the current uncertainty band (the tangent line badly misrepresents the true curve nearby), or when the observation/transition function isn't conveniently differentiable in closed form, making a Jacobian awkward to obtain. Prefer the plain linear Kalman filter over either nonlinear extension whenever the true relationship genuinely is linear and Gaussian — in that case the plain filter is exact, cheaper, and simpler, and reaching for EKF/UKF machinery only adds computational cost with no accuracy benefit.

Further reading
  • H. E. Rauch, F. Tung & C. T. Striebel, "Maximum Likelihood Estimates of Linear Dynamic Systems," AIAA Journal, 1965 — the original paper behind the RTS smoother.
  • Simon J. Julier & Jeffrey K. Uhlmann, "A New Extension of the Kalman Filter to Nonlinear Systems," Proceedings of AeroSense: Signal Processing, Sensor Fusion, and Target Recognition VI, 1997 — the original Unscented Kalman Filter paper.
  • Eric A. Wan & Rudolph van der Merwe, "The Unscented Kalman Filter for Nonlinear Estimation," IEEE Adaptive Systems for Signal Processing, Communications, and Control Symposium, 2000 — a widely cited, more accessible tutorial derivation of the UKF.
  • Dan Simon, Optimal State Estimation: Kalman, H∞, and Nonlinear Approaches, Wiley, 2006 — a comprehensive, rigorous text covering the plain Kalman filter, the RTS smoother, and both the EKF and UKF in one consistent notation.
