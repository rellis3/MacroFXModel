Gradient Boosting, Correcting the Ensemble One Tree at a Time

The previous lesson in this category, Decision Trees & Random Forests, fixed one tree's overfitting by growing many independent trees in parallel and averaging their votes — bagging. Gradient boosting takes the opposite structural bet: build trees one at a time, in strict sequence, where every new tree's entire job is to correct whatever error the ensemble built so far is still making. This is the final lesson in Tree-Based & Ensemble Machine Learning, and it closes the category with the field's other big idea — plus the one caveat that has to travel with it into any real feature set.

Section 1

Parallel and independent, versus sequential and dependent

Same goal — a model that predicts well on data it hasn't seen — two structurally opposite strategies.

Random forest — bagging
  • Grows B trees independently, in parallel, each on its own bootstrap resample
  • No tree ever sees another tree's output
  • Combines them only at the end, by averaging
  • Reduces variance — many high-variance, low-bias guesses, averaged
Gradient boosting
  • Grows trees sequentially, one at a time, in strict order
  • Every new tree is fit specifically to the ensemble-so-far's leftover error
  • Combines them by adding, a shrunk correction at a time
  • Reduces bias — a crude first guess, corrected again and again
A forest's trees never depend on each other, which is exactly what lets averaging cancel their independent noise — and exactly why the previous lesson's variance floor, ρσ², exists: the trees still all come from the same data. Boosting's trees are deliberately dependent — tree 2 cannot even be trained until tree 1's leftover error exists, because that error is tree 2's entire training target.
Section 2

Four steps, repeated many times

This is the entire algorithm — everything else in this lesson is this loop, run on real numbers.

0

Start simple

Initialize the ensemble as a single constant — for a numeric target, just the training mean. A crude starting guess, wrong for almost everyone, but a reasonable baseline.

−

Find what's still wrong

Compute the residual for every training point: the true target minus the ensemble's current prediction. This is what's left over, not yet explained.

🌱

Fit a small tree to that leftover

Train a fresh, usually shallow tree — using the exact recursive splitting from the previous lesson — with the residual as its target, never the original y.

+

Shrink it, then add it in

Multiply the new tree's prediction by a small shrinkage rate ν (commonly 0.01–0.3), and add that shrunk correction to the running total. Then repeat from step 2.

Why shrink at all

Setting ν = 1 lets one tree fully "solve" the current residual in a single step — fast, but that tree ends up fitting that round's specific noise, not a pattern that generalizes. Small, repeated, shrunk corrections — more rounds, each more conservative — empirically generalize better than a few large, confident ones.

Section 7

Nobody trains the raw 2001 algorithm anymore

Three production libraries dominate real-world use — same sequential-correction core, different practical engineering.

🌲

XGBoost

Adds an explicit regularization term that penalizes tree complexity directly in the training objective, plus efficient built-in handling of missing values and histogram-based split-finding for speed.

🍃

LightGBM

Grows trees leaf-wise instead of level-wise, chasing whichever leaf reduces loss most — often noticeably faster to train on large or high-dimensional data, at some extra overfitting risk on small ones.

🐱

CatBoost

Built around statistically careful native handling of categorical features, avoiding the target leakage naive target-encoding can introduce, plus an ordering scheme to reduce reuse-of-data bias.

All three sit on top of the exact same two ideas from this lesson — a corrective step fit to the leftover error, and a shrinkage rate — without changing that core mechanism. The engineering is about training efficiently and handling messy real tabular data well, not a different underlying algorithm.
Section 8

Not just a concept in this repo — checked directly

Verified against this repo's actual code

The full lesson this deck condenses labels gradient boosting a "CONCEPT — explained here, not built or tested anywhere in this repo." Checking each file directly shows that framing is stale. Gradient-boosted trees genuinely run here, in three roles: bot/scripts/train_gold_model.py trains XGBoost and LightGBM classifiers on gold macro features; bot/modules/ml_confidence.py loads those two trained models and averages their win-probability to scale live position size; AnalogML/ml_walkforward.py walk-forward tests XGBoost and LightGBM classifiers (plus an XGBRegressor/LGBMRegressor blended into a Ridge meta-learner) against a triple-barrier trading label. Two more files use it in a narrower, secondary role: SessionResearch/forecast.py fits scikit-learn's HistGradientBoosting pair alongside its primary Ridge/Logistic models purely as a "does nonlinearity actually help" check, and volatilityExhaustion/daytype_classifier.py flags a shallow HistGradientBoosting model as a higher-flexibility comparison against its primary, harder-to-overfit logistic regression. Genuine production use in three files, a deliberate ablation/comparison role in two more — not a pure textbook concept.

Worth naming the boundary precisely: the previous lesson's forest and plain decision-tree classes still don't appear anywhere in this codebase — that finding stands. It's specifically gradient-boosted trees, this lesson's subject, that turn out to already be live.

Section 9

A great knife still needs the right recipe

Being told "this is the best-selling, most versatile kitchen knife in the world" tells you the knife is genuinely great — but nothing about whether it's the right tool for the specific recipe you're making tonight. Gradient boosting being the strongest general-purpose method for tabular data is the "great knife" claim. Whether it actually finds something real and tradeable in one specific set of FX or macro features is a completely separate question, answered only by testing that exact feature set on its own — every single time.
Two different claims, easy to blur together

Claim about the method: gradient-boosted trees are genuinely, consistently the strongest general-purpose technique on structured/tabular prediction problems — well-evidenced, across thousands of unrelated datasets. Claim about a feature set: whether this specific set of macro or FX features fed into it contains real, out-of-sample-validated predictive signal — a completely separate question, decided by that feature set alone.

A powerful algorithm applied to features with no real signal doesn't fail loudly — it overfits noise, and it can do so more convincingly than a weaker method would, because it's flexible enough to trace a shape through pure randomness. That is exactly why leakage-free, honest out-of-sample testing gets more important as the method gets stronger, never less.

Section 10

Check yourself

Nothing is scored beyond this device. The explanation is the useful part.

Question 1

What's the core structural difference between how a random forest and a gradient-boosted ensemble are trained?

A forest's B trees never see each other's output — combined only at the end by averaging. Boosting's trees form a strict chain: tree m can't be trained until tree m−1's residual exists.
Question 2

What is each new tree in gradient boosting actually trained to predict?

For squared-error loss, the residual is literally y minus the ensemble's current prediction. Every tree after the first is trained on that leftover error, never on y directly.
Question 3

What does the shrinkage rate ν control, and what tends to happen at ν = 1?

A small ν (commonly 0.01–0.3) needs more rounds to reach the same fit, but each step is more conservative — empirically generalizing better than a few large, confident corrections at ν = 1.
Question 4

Which of the three production libraries grows trees leaf-wise rather than level-wise, chasing whichever leaf reduces loss most?

LightGBM's leaf-wise growth is often noticeably faster on large or high-dimensional data than level-wise growth, at some extra overfitting risk on small datasets without careful depth control.
Question 5

Gradient boosting is the strongest general-purpose method on tabular data. Does that, by itself, tell you a specific FX/macro feature set has real trading edge?

A flexible, powerful method can fit noise very convincingly — possibly more convincingly than a weaker one. Its general strength across unrelated tabular problems says nothing about any one specific feature set's predictive power in one specific market.
Section 11

What to carry forward

01

A forest averages independent, parallel trees to cut variance; boosting chains dependent, sequential trees to cut bias — the structural opposite strategy for the same underlying goal.

02

The loop is four steps: start with a constant, compute the residual, fit a small tree to that residual, add it back in shrunk by ν — repeated for M rounds.

03

Each new tree only ever sees the leftover error, never the original target again after round 0 — nothing already fixed gets re-taught.

04

Shrinkage ν trades more rounds for a more conservative step each round; too many rounds with too little shrinkage overfits, the same way an unconstrained single tree does.

05

XGBoost, LightGBM, and CatBoost are the real production implementations — regularization, leaf-wise growth, and careful categorical handling on the same sequential-correction core.

06

Being the strongest general-purpose method on tabular data is a claim about the method, not about any one specific feature set — that gap is exactly where honest, leakage-free out-of-sample testing earns its keep.

What this now lets you do

Explain why a forest and a boosted ensemble solve the same overfitting problem from opposite directions — averaging away variance versus chasing down bias — and recognize which one a given tool (a forest, XGBoost, LightGBM, CatBoost) actually is. Read a falling training-loss curve for what it honestly is: not evidence of generalization on its own. And hold the method's strength and a specific feature set's signal as two separate claims, every time gradient boosting gets proposed for a real strategy.
