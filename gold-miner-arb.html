Gold vs Gold-Miners Stat-Arb · GDX / Gold cointegration backtester

Mechanises the owner-supplied spec: rolling hedge-ratio z-score, cointegration gate, scale-in/scale-out tranches, VIX macro filter, $ risk sizing, hard/time/macro stops. Runs the full policy against a naive single-tranche baseline on a true later-period OOS split, plus an independent cross-check via the platform's already-built, already-tested FX-pairs cointegration engine on the same GDX/Gold pair.
Known deviations from the original spec — surfaced, not hidden: (1) Daily bars, not 15-minute. Free Yahoo 15-min history only covers ~60 days — far short of the spec's own "2 years" calibration requirement and too short for a real OOS trade count. (2) Gold leg is OANDA XAU_USD spot, not CME GC futures — this avoids a worse problem (Yahoo's GC=F is an unadjusted continuous contract with real price jumps at roll dates that would corrupt the cointegration test), at the cost of ignoring the futures basis. (3) Time-of-day filter does not apply to daily bars — not silently applied. (4) The original spec has no cost section; this engine deducts a round-trip bps cost on every close (below) because free fills are not honest. (5) The "ADF p-value" gate is implemented as an OU λ t-stat vs a documented Engle-Granger 5% critical value (reusing hedgeSignalV2Engine.js, already live for FX pairs) rather than a hand-approximated p-value.

Reading this card — "Policy" is the full spec (VIX filter, cointegration gate, scale-in/out tranches, $ risk sizing). "Baseline" is a naive single-tranche version on the SAME price data (entry at |z|≥2, no VIX filter, no cointegration gate) — the honest thing to A/B against, per CLAUDE.md's working agreement ("built" ≠ "works" ≠ "has edge" — the machinery only means something if it beats the naive version OOS). A result only counts as a signal at ≥30 OOS trades.
R vs % Return — this spec risks a FIXED 1% of equity per position, so R-multiple and % Return are near-linear rescalings of each other in the exports below — flagged per house convention, not a bug.
MAE is close-to-close over the daily bars a leg was open, not a true intrabar spread path (no real intrabar path exists for a synthetic two-leg spread from two separately-sourced daily series).
