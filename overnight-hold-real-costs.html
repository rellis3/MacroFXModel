Toolkit exports exact format

C.OG's three columns: Date,Return %,MAE %. Date = the trade's entry date, Return % = net return of the trade as % of position notional, MAE % ≤ 0, two decimals, no symbols. On net files, the MAE also has that trade's costs taken off (counted as paid at the worst point, which is conservative). Combined = both instruments' rows at half size each (one portfolio at 1× notional), sorted by date.

Rounding to two decimals, as the spec asks, moves each NQ trade by up to ±0.005%. The mean net return is only +0.034% a trade, so a toolkit run on these files can differ slightly from the replica below, which used unrounded returns.

Journal import export colez-import-template-standard

One row per trade in the import template's 13 columns: Date,Time,Exit Date,Exit Time,Instrument,Direction,Model,Risk %,Return %,MAE %,MFE %,Tags,Notes. Uses the cost settings at the top of the page. Times are UK (20:00 entry, 14:30 exit next day). Return % is signed; MAE % and MFE % are positive sizes, as in the template.

% columns are % of the account at the chosen size: Return % = size × net return, MAE % = size × (worst M1 low + that trade's costs), MFE % = size × (best M1 high − costs, floored at 0). Costs are counted as already paid at both extremes, as in the toolkit CSVs. The overnight hold has no stop, so there is no true risk per trade. The Risk % column uses a fixed 1% of notional as the R unit (the old engine page's convention), which makes R = Return % ÷ size. Three decimals, because the edge is only about +0.03% a trade and two would round much of it away. For the combined book, export "Both" at 0.5×: that is the study's half-size-each portfolio.

How to read this

  • Is it real? Gross is positive on both markets. Net is still positive at your account's costs (NQ about +5.6% a year, gold +4.7% to +6.3%), but the per-trade mean isn't statistically confirmed (UNDERPOWERED).
