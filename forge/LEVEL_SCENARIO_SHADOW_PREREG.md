# S3 shadow: level scenarios, live reach / which-first / time (registered 2026-10-11, before any live session is logged)

**Part of:** `plans/LEVEL_ENGINE_ROADMAP.md`. Builds on the accepted Phase 2 results (`forge/LEVEL_P2_PREREG.md`):
- reach: accepted;
- time: accepted;
- race: b ÷ (a + b).

**What it is:** a read-only page (`level-scenarios.html`) that scores every level on the chart as price moves, plus a write-once forward log that tests the frozen model on sessions it has never seen.

**Safeguards:** no production calculation, parameter, bot or KV changes; nothing live reads the log; S1 untouched; the forward M1 block is not read.

## Frozen model
- **Source:** `js/levelReachParams.js`, version **4926bba63951b587**, generated by `scripts/levels/export_reach_params.py`.
- **Fit:** the Phase 2 M1 design, five logistic horizons (30/60/120/240 min, 22:00), fitted on sessions before 2022 only.
- **The export reproduces the registered skill vs B1:**

  | Horizon | E-conf | E-dev |
  |---|---|---|
  | 30 min | +5.35% | +3.97% |
  | 22:00 | +1.64% | +0.67% |

- **JS ↔ Python parity:** 400 rows, worst difference 7e-11 (`js/levelReach.test.mjs`).
- **Core:** `js/levelReach.js` is shared by the page and the logger.

## Live inputs
- **σ:** the production forecast's `ladder.sigma_daily_pct`, the `pit_sig_daily` basis.
- **Open:** the first M1 bar after London midnight.
- **Levels (the Phase 2 set):**
  - forecast ladder O-H / O-L p50/p75/p90;
  - today's open;
  - Asia high/low (from 07:00);
  - London high/low (from 12:00);
  - structural levels from KV `range_line_confluence`: the production `sessionConfluenceLevels`, refreshed 06:10 London.
- **Known difference from the registry:**
  - The live artifact uses London-boundary sessions and covers 19 instruments, so UK100 and some crosses get ladder plus session references only.
  - The registry used New York-close bars.
  - Phase 2 found level identity adds no reach information, so this changes which levels are scored, not how they are scored.
- **Domain:** levels outside today's range (intraday references exempt), 0.05–3σ from price, checkpoint hour ≥ 03:00.

## Forward log (`levelScenarioShadow` service)
- **Checkpoints:** at 03/07/10/13/16 London (weekdays, h:00–h:15), the log writes `R2 shadow/reach_v1/<date>/<HH>.json` once. Each record holds every eligible level's M1 and geometry probabilities for all five horizons, plus the nearest-above/below race.
- **Outcomes:** at 22:10 London, `outcomes.json` records each level's first-touch minute after the checkpoint and each race result (up / down / neither / ambiguous).
- **Data source:** OANDA M1 via the server, as for S1.
- **Writes:** only from Railway.

## Evaluation: ONE look, at 60 valid sessions
**A session is valid if:** at least 4 of the 5 checkpoints are logged with at least 15 instruments `ok`, and its outcomes are logged.

| Endpoint | Pass if |
|---|---|
| **Primary: reach by 22:00** | M1 Brier skill vs geometry (B1) > 0, 5-date block bootstrap 95% lower bound > 0, **and** max decile calibration gap ≤ 3pp (deciles ≥ 300 rows) |
| Time (secondary) | integrated Brier over the five horizons, M1 vs B1, lower bound > 0 |
| Which-first (secondary) | b ÷ (a + b) decile calibration ≤ 3pp on resolved races; "neither" and ambiguous rates reported |
| Reported | by class, checkpoint, level family, distance band |

**Decision:**
- **Pass:** the page's numbers are confirmed prospectively, and the reach model becomes the Q1/Q4 component of the scenario engine.
- **Fail on calibration only:** a separately registered recalibration; the page is labelled accordingly.
- **Skill ≤ 0:** the page falls back to geometry with an empirical calibration table, registered separately.

**No interim decisions.** The page and the API (`/api/level-scenario-shadow`) are interim views only.

## What the page must never claim
**Direction after a touch.** Rejection vs continuation shows as ≈50/50: every reaction test is null, and the line-touch fade fails net of cost, futures included (`forge/FUTURES_COST_RESCORE_PREREG.md`).
