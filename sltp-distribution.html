Mechanical H4 entries, both directions, on each asset's own M1 history — no bot signal, no costs. Signal-Conditioned SL/TP — Layer 2 (volatility_bot)

Layer 1 asks the question mechanically; Layer 2 asks it only at a bot's REAL entries. This replays volatility_bot/engine.py's actual, unmodified decide() tick-by-tick through years of real M1 — no mechanical sampling, single direction per entry (the bot's real call) — then feeds those real entries into the SAME shared barrier-race grid Layer 1 uses, plus real spread cost.

Two caveats, stated loudly

(1) "Today's policy, historical prices" ≠ "what the bot actually decided historically." The learned fade/follow policy is periodically relearned; this uses one live snapshot applied across all of history, not a day-by-day historical policy (which isn't stored anywhere).
(2) The daily σ used to size the bands is a local proxy (20-session causal rolling realized vol), not the platform's exact YZ-30/GARCH/HV20 — an approximation, not a bit-identical replay. See volatility_bot/layer2_sltp_replay.py and PYTHON_LEGO.md §8.

Per pair: how the bot's OWN actual exit (its real fade inner/outer levels, cost-adjusted) performed on its own real entries, vs. the best cell in a swept uniform SL/TP grid applied to those SAME entries. The swept grid is a genuinely different exit mechanism (fixed, not adaptive) — this asks whether a simpler fixed exit would have done better, not whether the entries themselves have edge.
