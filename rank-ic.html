Rank-IC Diagnostic · do my scores actually sort the outcome?

Every score the stack produces implicitly bets higher score → better forward outcome. This measures whether that's true, honestly. It takes each score — the day-type trend-day-ness T, its component estimators, and the regime / momentum direction call — computes it with no lookahead, and reports its Spearman rank information coefficient (rank-IC) against the realized forward window, on a true in-sample / out-of-sample split. Rank-IC is the quant first-pass because it's robust to FX fat tails (a ranking can't be hijacked by one crisis print) and to the curved shape signal→return takes. It is a falsification tool, not an edge finder: the benchmark to beat is IC = 0, and only out-of-sample.
Scope (honest). This grades only the scores reproducible from pure daily bars with no lookahead. The live star rating / signalScore depend on intraday level context (density, cross-session match, EMA-RSI, HMM) that can't be rebuilt from D1 — grading those needs the logged live-trade book (score + realized pnl), which the underlying rankIC brick can ingest once it's wired, but which this page deliberately does not fake from D1. Reading: |IC| ≈ 0 → the score is decoration; ~0.02–0.05 OOS with |t| ≳ 2 → a real-but-weak signal. Sign follows the target: for directional scores +IC = predicts direction; for magnitude scores +IC = predicts a more trending window.

rank-IC = Spearman ρ between a score and the realized forward outcome (ranks only, so fat tails and curvature don't distort it). t = t-stat of ρ vs the null ρ=0 (ρ·√((n−2)/(1−ρ²))); |t| ≳ 2 ≈ 5% two-sided. The column that matters is OOS IC — in-sample IC is not evidence. A row is highlighted when its OOS result clears |t|≥2. Targets: magnitude scores are graded against realized trend efficiency |close−open|/(high−low); directional scores against the signed forward return (close−open)/open. The ·-prefixed rows are the day-type composite's component estimators, disaggregated so you can see which brick (if any) carries the ranking. Multiple testing: the summary shows how many instruments are individually significant next to the cell count — a few survivors among many cells is what chance produces, so treat a lone significant pair as noise unless it's consistent IS and OOS.

Live entry scores · Asia-range, M1 gap-filled

Grades the actual live scores the bot fires — star rating, signalScore, day-type T, vol position, approach velocity — against realized trade pnl. It drives asiaRangeEngine over M1 history (frozen R2/parquet snapshot gap-filled to now from OANDA live) through the same entryGradeCore/rangeBiasCore/hmm.js bricks the live levels.js uses — so the score being graded is the one the bot actually computes, not a D1 reconstruction. Each row is rank-IC of a score vs pnl_pct on a true IS/OOS split; +IC ⇒ higher score ranked the winners above the losers.
Scope (honest). This grades signalScore as the Asia-range strategy fires it (that bot's entry candidates, the no-macro blend) — not every possible level touch. Sample size is the real limit: Asia-range candidates per pair can be thin, so OOS n may fall short of the ≥30 bar — the card shows n so a thin cell can't pass as a result. First run is slow (M1 load + gap-fill from OANDA per pair).
