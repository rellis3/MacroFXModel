## The idea we are testing

C.OG, Market Movers, 28 Sep 2026 (`education/cog_inbox/2026-09-28-market-movers-vol-forecaster-as-a-layer.md`):

- The vol forecaster is **one layer of about six**. "Every single position is different" because each position is the product of all the layers.
- The forecaster publishes a **shared vol state** with five fields:
  1. current conditional vol
  2. expected change in vol
  3. vol relative to its long-run level
  4. probability of each vol regime
  5. forecast error
- That state drives position sizing and regime states, and its errors work as a feedback loop.
- Other layers he names:
  - conditional views
  - meta-labelling
  - splitting correlation from variance
  - Black-Litterman
  - jump intensity and jump diffusion

Separate frame, also his (Discord, 19 Oct 2026), already in the repo as `cog-release-layers`. It reads a market event in
three layers:
1. What happened (NQ, 2y, 10y, USD).
2. Why (which shock).
3. How unusual, using **conditional** normalisation.

## The eight tabs on the page

| # | Layer | One-line question |
|---|---|---|
| 1 | Vol state | Can the forecaster publish the five fields point-in-time, each better than a naive benchmark? |
| 2 | Jumps | Does jump or news risk say when a σ stop gets blown through, beyond σ and the calendar? |
| 3 | Correlation ÷ variance | Does splitting own vol from correlation (the dollar factor) improve risk and signals? |
| 4 | Conditional views | Which directional views work, and does their accuracy change with the vol state? |
| 5 | Meta-labelling | Can a second model pick which trades hit target before stop? |
| 6 | Black-Litterman and sizing | How do views and confidence become sizes with steady book risk? |
| 7 | Stop orders | Where do entry, stop and target go, and which order type? |
| 8 | Feedback loop | How do the forecaster's own errors flow back into every layer? |

How each layer is researched:
1. A literature pass (no repo access).
2. A repo pass (code only, no verdicts).
3. A bias check (read past results only now).
4. A prereg.
5. The isolated test.

The combined test then adds the layers one at a time.

## Part A: done in this cloud session (2026-11-06 to 11-07)

### Built and merged (PR #1674)
- **The page:** `vol-layer-system.html`, with one tab per layer plus a combined System tab.
- **The plan data:** `js/volLayerResearch.js` holds C.OG's words, the question, the candidates, the repo starting points, the isolated test and the defects to fix for each layer.
- **Same-bar ties:** `pylego/barrier_race.py` `race_grid` and `race_trades_variable` gained `pessimistic_ties` (default False so old studies reproduce). Vol-layer tests pass True, so a bar that touches both the target and the stop counts as a stop. Two new tests.
- **`forge/rv.py`:** everything is built from M1 and is point-in-time.
  - `session_rv` gives one row per London 00:00–22:00 weekday session. It uses a 5-minute grid where empty slots are **dropped, never forward-filled**. Columns: RV, bipower, quarticity, up/down semivariance, and the overnight return as its own column.
  - `ny_close_daily` builds 17:00 New York bars, each stamped with when it closed. An unfinished bar is dropped.
  - `bars_before` and `last_bar_index_before` return only bars closed by the London open.
  - The lockbox cut at 2026-08-21 is the default.
- **`forge/rv_test.py`:** 9 tests covering holes, weekends, the clock changes, the overnight term, the lockbox, and **prefix invariance** (appending future M1 never changes a finished row). They caught a pandas-3 µs/ns bug in the join, which is fixed.
- **Docs:**
  - `plans/vol-layer/L1_LITERATURE_SPEC.md`: the layer-1 literature pass, with no repo access.
  - `plans/vol-layer/L1_REPO_PASS.md`: that spec mapped onto our code, plus the gaps and the causality risks.
- **Register:** row `vol-layer-l1-sigma` (CLAIMED).

### Found (research and code reading, not market tests)
- **The chosen σ on vol-forecast-v3** ("Forecast · chosen ★ persistence + IV", `js/forecastLadderPersist.js`).
  - **Base σ:** a daily-bar estimator, frozen per instrument: Yang-Zhang 10 days (×18), EWMA 0.94 (×15), YZ 20 (×2), EWMA 0.90 (×2). It is computed on NY-close bars as of yesterday, with the event multiplier on top.
  - **Morning nudge:** σ × exp(β·(x − mean)), where x is σ against its 250-session median, yesterday's range ÷ σ and its 5-day mean, and weekday, plus log(IV ÷ σ) where IV exists.
  - **No intraday returns:** it is not built from 1-minute realised vol.
- **Bar-shape mismatch:** each estimator was **picked on London 00:00–22:00 bars but runs live on NY-close bars**. The data rules say σ is only valid on the bar shape it was fitted on.
- **Older HAR helpers see future data:** several use whole-sample scales or smearing (`har_cj_forecast.py` run(), `volForecastBench._rvScale`, the first year of `forge/vol.py` har_rv_log, `jump_detect_lm.periodicity`). Don't reuse them as they are.
- **What the literature says (layer 1):**
  - GARCH(1,1) is a hard benchmark in FX (Hansen-Lunde 2005).
  - Gains from intraday data come mostly from better inputs (5-minute RV), not fancier models.
  - Compare models with QLIKE, Diebold-Mariano and a Model Confidence Set.
  - Δσ and σ-vs-long-run are mostly transforms of σ, so they are one dimension, not two.
- **Corrected claims:**
  - `hmm.js` live labels are already filtered and causal, so it isn't a live bug. In backtests, don't reuse the Viterbi path.
  - `jump_flags_seasonal.py` and `meta_proper` are pre-registered studies and were left unchanged. Their flaws became rules for new code: forward-filled zero returns inflate jump flags, and meta_proper uses a ret>0 label with no calibration.
- **Bias audit of this session:** some verdict text in code comments was seen by agents and ignored. Several "drop it" calls came from literature, not our data, so they are open questions.

## Where we are

- **Infrastructure:** the page, the M1 realised-variance builder and the tie fix are on main, and the per-layer stage tracker works.
- **What holds up so far:** the vol state is real as a **description** of vol. RV5 improves the forecast a little (validated). σ over-reacts. Forecast error carries information.
- **What doesn't yet:** nothing so far is a **tradeable entry net of costs**.
  - Tight geometry (K = 0.25σ) loses to spread.
  - No universal noise-threshold stop exists.
  - Jump-path trades are null.
- **Entry tests still open:** the review shows several entry questions were never tested in C.OG's own form. Those are the open doors for an entry.
